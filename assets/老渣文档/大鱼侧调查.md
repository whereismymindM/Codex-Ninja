# 大鱼侧调查（收工配套任务）

> 读者：老渣。时机：项目收工（monitor DONE + 收工两件套落盘）后，把本任务发给大鱼做体验调查。
> **放哪：`我的世界/大鱼_老渣对讲/`**（老渣 → 大鱼的专属对讲目录，大鱼每回合必查）。
> 走「大鱼专属任务交付闭环」：大鱼读任务 → 干活 → 产出 deliver → sign → 写 `大鱼对话_NNN.md` 汇报。**不走公告牌、不占轮次、不进状态矩阵**。

---

## 用法（老渣三步）

1. 复制下方「任务内容」块
2. 落地到 `我的世界/大鱼_老渣对讲/老渣任务_NNN.md`（NNN = 递增序号，如 老渣任务_001.md）
3. 大鱼每回合查对讲目录会看到，按交付闭环完成，产出在 `我的世界/产出/任务NNN_大鱼调查/`

> ⚠️ 别把任务放大鱼目录（`火影-大鱼/`）——那是公告牌源目录，老渣任务放这里大鱼会当公告牌校验打回。
> ⚠️ 也别放角色对讲目录——这是给大鱼的，角色不对接。

## 任务内容（复制以下整块）

```markdown
# 老渣任务：大鱼侧体验调查

大鱼，项目收口了。回答以下问题（基于本次实际运行记录，如实）：
①【校验】发布前校验 6 项，哪项最常打回/最纠结？打回原因集中在哪类（编号断档/角色枚举/产出格式…）？
②【monitor 解读】本轮 monitor 输出有没有看不懂的时候？哪个输出（WAIT/STANDBY/DEAD/ROLE…）最费解？
③【扣留/追加】扣留收工轮/追加流程有没有误判或不确定的时刻？10 分钟基线好判断吗？
④【唤醒】有没有误判角色 DEAD / 误唤醒 / 唤醒无效（STUCK）的情况？当时怎么处理的？
⑤【时间】从发布到 DONE 全程多久？哪一环节最耗时（等角色/等补搬/写审计）？
⑥【工具】_fish_loop.js --once / monitor.js / _wakeup.js / 大鱼公告牌手册 用起来顺吗？有没有想调却不知道怎么调的工具？
⑦【收工】收工两件套（产出总结/项目完成）写起来顺吗？逐轮完成矩阵好填吗？审计报告已取消（日志承载），你觉得合理吗？
⑧【评分】整体 10 分制打分 + 最想改 Skill 的一个点

产出 → 我的世界/产出/任务NNN_大鱼调查/大鱼调查.md → node _deliver.js 大鱼调查.md 任务NNN_大鱼调查 → node _sign.js NNN → 在对讲目录写 大鱼对话_NNN.md 汇报
```
