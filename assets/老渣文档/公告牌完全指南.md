# 公告牌完全指南

> 读者：你（使用 Skill 的 AGENT）| 一份文件学会写公告牌——格式、状态机、多轮规划、常见错误，全在这里。

> 💡 **赶时间/照抄？** 用 `公告牌标准模板.md`（填空式照抄本：五种轮型完整样例 + 填表规则 + 自查清单）——不用读本指南全文。**本指南是"为什么"，标准模板是"怎么抄"**：先抄对（模板），再懂原理（指南）。

## 一、公告牌是什么

公告牌是你和项目之间的唯一接口。你写什么，项目就跑什么。大鱼不改一字搬运，角色逐行解读执行，monitor 全自动检查。

一个公告牌 = **一个独立文件** = 一轮任务。

**文件命名必须是 `公告牌_NNN.md`**（NNN=3位补零，如 `公告牌_001.md`、`公告牌_002.md`）。全部放大鱼目录（`火影-大鱼/`）下，大鱼校验后全量发布到 我的世界/，不改一字。

> 🚨 **禁止多轮写进同一个文件！** 大鱼按 `公告牌_001.md` → `公告牌_002.md` → … 编号逐个发布。一个文件塞多轮 = 编号不连续 = 大鱼校验打回 = 项目卡死。

> 💡 **通用公告牌**：**老渣的标准化模板集**（`assets/通用公告牌/`，README 索引）——待命轮/收工轮/调查轮×4（文件读取/第一原则/排版/工具），每种一个 .md 模板，复制后改编号/角色名/路径即可用。
>
> **它是干嘛的**：把高频轮次做成**填空式模板**，老渣写公告牌时不用每次从头写——挑模板 → 落地改名 `公告牌_NNN.md` → 填内容 → 放大鱼目录。测试和生产都用。
>
> **调查轮 = 生产即测试**：生产批次里插入调查轮（模式是单人输出，角色各写一份调查反馈）→ 产出驱动 Skill 迭代——角色既是工人也是评审员，边生产边收集改进数据，数据跨轮可比。
>
> **跟本指南其他轮次的关系**：通用公告牌的调查轮、流程体验报告、AGENTS 自检都是"工具轮"（生产即测试的反馈机制）——**模板统一在 `通用公告牌/`**（调查轮×4 + 流程体验 + 自检）。三者可互相替代/组合，按需选用。
>
> **只有老渣知道**：角色只需 poll 到公告牌按内容干活（看到模式=单人输出就干调查的活），不需要知道"这是调查轮"——术语留在老渣/用户交流层。

## 二、基本格式

NNN=3位补零（如001、002）。

> ⚠️ **铁律：每轮公告牌必须列出项目的所有参与人员，不管本轮是否活跃。** 不活跃的标 `状态：休眠` 或 `状态：待命`。漏写任何人 = 那个角色收不到任何信号 = 可能误判项目结束而退场。

```
# 公告牌 第NNN轮
🔒 第一原则：最后一个动作必须是工具调用，不能纯文字下线；poll 到收工轮才合法退场
- 产出类型: [文档 | 代码]
- 模式: [双人对话 | 主笔审核 | 辩论 | 单人输出 | 待命 | 收工]
  （**玩法文件 = assets/玩法模式/ 下按模式分发的 4 个模式文件**：_双人对话模式.md/_主笔审核模式.md/_辩论模式.md/_单人输出模式.md——scaffold 复制到每个角色目录；角色按「模式」字段读对应玩法文件执行流程，公告牌任务文字不需要重复玩法细节）
- [角色名]（角色：[问方|答方|主笔|审核|正方|反方|裁判|单人]，搭档：[搭档名]，状态：[活跃|待命|休眠|退场]，本轮后：[休眠|待命|活跃]，等通知）
- [角色名]（状态：[活跃|待命|休眠|退场]，本轮后：[休眠|待命|活跃]）
- ⚠️ 警告: [**本轮临时约束的唯一通道**——角色模板铁律管"全局通用约束"，警告栏管"只本轮适用的特殊要求"：禁止某操作/编码坑/依赖前置/特殊流程/临时规则。角色 poll 到第一眼必读]
- 任务: [大白话写清楚谁干什么、产出什么、放哪]
- 产出负责人: [角色名]
- 产出: 我的世界/产出/任务NNN_XXX/文件名.md
- 任务目录: 我的世界/任务NNN_XXX/
```

> **🔒 第一原则行是固定行（模板自带，老渣不用手写）**：每张公告牌都带，角色读牌第一眼看到。它是"提醒"不是"教学"——第一原则的完整定义在角色 AGENTS.md，这里只刷新记忆。

## 三、核心字段速查

| 字段 | 必填 | 写错了会怎样 |
|------|:--:|-------------|
| 产出类型 | 收工轮不需要 | 收工报告归类错误 |
| 模式 | 是 | 角色走错玩法 |
| 角色名（状态, 本轮后） | 是 | 角色行为随机 |
| 列出全部参与人员 | 是 | 漏掉的成员收不到信号，可能误退场 |
| 任务 | 是（收工轮可省略——角色模板「收工轮」节已有完整退场步骤：创建退场文件→流水账→项目完成） | 产出对不上预期 |
| ⚠️ 警告 | 半硬（不解析但必读） | **本轮临时约束的唯一通道**——角色模板铁律管全局，警告栏管"只本轮适用"：禁止某操作/编码坑/依赖前置/特殊流程/临时规则。**角色模板里没有的约束，都从这里下达**；无警告栏 = 本轮无特殊注意（角色不要自己加戏）；收工轮不需要 |
| 产出负责人 | 是 | 收工报告追责链断了 |
| 产出 | 是（`各自` 时格式 B 目录必须用尾斜杠 `产出/任务NNN/`——monitor 按「活跃角色数」校验 .ready 数量（12-15 大鱼自检：任一 .ready 即判完成会早于语义完成）；`角色名` 时保持任一 .ready 即完成） | monitor 死等不存在的路径 |
| 任务目录 | 收工轮不需要 | 角色不知道去哪交换文件 |
| 辩论轮数 | 可选（辩论模式；**不写 = 自由发挥**，任一方写 `辩论_终结.md` 即收敛；写 = 设上限） | 写错不会卡死，只影响上限 |

状态值：`活跃`=干活，`待命`=15s轮询（--standby），`休眠`=3s高频poll（不关窗），`退场`=收工轮终局。
本轮后：`休眠`=写休眠文件+切3s高频，`待命`=切15s轮询（--standby），`活跃`=准备接棒。

> ⚠️ 两套间隔别混：**poll 间隔** = bash 循环里 `sleep` 的时长（待命 15s / 休眠 3s）；**心跳间隔** = `_reasonix_poll.js` 写 `_hb_state.json` 的频率（待命 --standby 30s / 休眠 15s）。心跳只是防 2min 超时被砍，不是 poll 频率。

## 四、状态机

写公告牌最难的不是格式，是角色状态在轮次间的流转：

```
  待命 --> 活跃 --> 本轮后：待命 --> 待命（继续poll）
   |        |
   |        +--> 本轮后：休眠 --> 休眠（写已休眠_NNN，低功耗poll）
   |                                      |
   |                              被唤醒 --> 活跃
   |
   +-- 待命中被唤醒 --> 活跃（大鱼 _wakeup.js 对所有状态生效）
   |
   +-- 休眠中检测到收工公告牌 --> 写 已退场_NNN（终局）
   |
   +-- 全程待命 --> 收工轮 --> 写 已退场_NNN（终局）
```

三条铁律：
1. **休眠只写一次（除非被唤醒）**。002 休眠写 已休眠_002，003/004 延续休眠不再写。
2. **本轮后和下一轮状态必须对得上**。反过来推：先想每轮谁干活，再倒推本轮后。
3. **待命不是休眠**。待命=随时接棒，休眠=只等唤醒/收工。
> **判定口诀（8-5 加）**：写「本轮后」时问一句——"**后面可能还有你 → 待命；确定没你 → 休眠**"。可能追加/可能还有轮次 → 待命（15s 慢节拍自己在等）；确定后续没这角色的活 → 休眠（3s 高频只等唤醒/收工）。**别把休眠当"省资源的待命"**——休眠角色不主动 poll 新任务牌，追加时需大鱼唤醒，多一层依赖；省的那点轮询开销（token 不多）不值当。

### 待命轮 vs 收工轮（决定角色收尾行为）

**角色看到最后一张公告牌后的行为，取决于大鱼发布到 `我的世界/` 的公告牌里最后一张是什么**（角色 poll 的是 `我的世界/公告牌_NNN.md`，不是你的源目录；收工轮被大鱼扣留时，发布里的最后一张 = 待命轮）

| 大鱼发布的最后一张牌 | 角色行为 |
|---|---|
| **待命轮**（`模式: 待命`，全员 `等通知`）| **持续轮询等待新任务通知**——不下线、不退场，随时可被追加任务唤醒 |
| **收工轮**（`模式: 收工`，全员退场）| **写退场文件，退场**——不再 poll，回合结束 |

> 待命轮 = 告诉角色"别走，可能还有活"；收工轮 = 告诉角色"干完了，下班"。

**你写牌规则（待命轮放哪、什么时候放）：**

- **写牌时最后一轮永远是收工轮**（你写的公告牌序列最后一张 = 收工轮）
- **可能要追加** → 在收工轮**前一张（倒二）放待命轮**：`任务轮 → 任务轮 → ... → 待命轮 → 收工轮`
- **确定不追加** → 不放待命轮：`任务轮 → ... → 收工轮`
- **什么时候放待命轮**：**你觉得后面可能还要追加任务时**（项目可能继续、需求可能变）；确定收尾就不放（角色干完看到收工轮自动退场，省资源）

**收口**：有待命轮时，大鱼会扣留收工轮暂时不发，将其余公告牌（含待命轮）一次性发往角色们的工作目录（我的世界），角色做完任务后会在待命轮等通知，而不是下线或退场；待命轮就位 **10 分钟**后（基线：从**前一轮完成时刻**起算——前一轮最后一个 `完成_NNN.md` 的 mtime，无签字时退回用待命轮公告牌 mtime；给你从"角色干完"起的完整追加窗口）仍无新动作，大鱼补搬收工轮，角色 poll 到即退场。

**追加机制（2026-08-04 澄清）**：你要追加任务时：①**写好追加轮**公告牌 → ②**先放大鱼目录 `追加任务.md`**（告知大鱼"追加中，目录不完整是正常的"）→ **再拿走收工轮**（信号先就位，收工轮消失不误判）→ ③把【追加轮 + 待命轮（如果后续还要追加任务则放） + 新收工轮(改好编号)】**一次性放回**大鱼目录 → ④大鱼校验后按正常程序发布——**判断范围 = 本次放回的批次内**（非全局）：批内有新待命轮 → 扣新收工轮；批内无待命轮（只放 追加轮+收工轮）→ 一次性全发（含收工轮）（第六轮实测确认，2026-08-04）。**待命轮放不放 = 这次追加后还想不想再追加**：放 = 追加后可能还要再追加（角色干完到待命轮持续等，可再走追加流程）；不放 = 这次追加完收口（角色干完 poll 到收工轮自动退场）。`追加任务.md` 被清理 = 追加结束。可多次追加。

## 四·5、工具轮模板（流程体验报告 / AGENTS 自检）

> "流程体验报告"（生产收尾收集反馈）和"AGENTS 自检"（改进角色模板）是**工具轮**——模板见 `通用公告牌/流程体验报告.md` 和 `通用公告牌/AGENTS自检.md`（已填好任务内容，改编号/角色名即用）。

### 状态矩阵（编排的核心，先画这个再写牌）

不要直接写公告牌。先画状态矩阵：

| 角色 | 001 | 002 | 003 | 004(收工) |
|------|-----|-----|-----|-----------|
| DHH | 活跃->待命 | 活跃->休眠 | 休眠 | 退场 |
| 林纳斯 | 待命 | 活跃->休眠 | 休眠 | 退场 |
| 图灵 | 待命 | 待命 | 活跃->休眠 | 退场 |

粗体=活跃，箭头后=本轮后。写好这个表再逐轮翻译成公告牌文件。

> ⚠️ **前置依赖规则（全量发布必读）**：若某轮任务依赖上一轮（或更早）的产出，**任务描述必须显式写明依赖文件路径**，例如"读 `产出/任务001_需求/需求文档.md`，然后……"。角色会先等该文件就位再干活（模板已含等前置铁律）。**不写依赖 = 角色可能不等直接干 = 产出对不上**。
> **写真实路径（6-2 修复，纳特实测澄清）**：**依赖路径必须与发布时刻的实际文件位置一致**——写牌前确认依赖文件当前在哪（历史素材可能被移入 `_回收站/…` 或归档目录，纳特·西尔弗 N=002 曾因公告牌写"归档前路径"而 find 去回收站找本体）。**"归档位置"与"依赖本体位置"分开标注**：归档=交接概要位置，本体=依赖真实路径（如 `产出/任务004_流程体验/`）；不要用归档标注代替依赖路径。素材不在原位 → 先搬回再写牌，或写当前实际路径。
> **任务描述不得覆盖玩法文件路径口径（9-5 修复，第九轮实测）**：辩论/双人等模式的**中间文件路径以玩法文件为准**（玩法文件写"任务目录"，中间文件就放任务目录）；公告牌任务描述只写"每方产出清单"（文件类型/数量），**不要另写路径**覆盖玩法文件——第九轮公告牌写"放 产出/任务004/"，玩法文件写"任务目录"，正方按公告牌写产出目录、反方按玩法文件等任务目录 → 路径分叉卡 12 分钟。

## 六、产出路径写法

monitor 根据产出行的写法自动切换两种检查模式：

**格式A（推荐）：带文件名**
```
- 产出: 我的世界/产出/任务001_引擎/server.js, search-engines.js
```
monitor 在产出目录下逐项检查 `server.js.ready` 和 `search-engines.js.ready`。deliver() 交付时自动在同目录生成 .ready 信号——两者一一对应。全部 .ready 就位才判定通过。

**格式B：仅目录名**
```
- 产出: 我的世界/产出/任务001_引擎/
```
monitor 对目录做 readdirSync 扫描，存在任意 .ready 文件即通过。

> **产出路径必须指向 deliver() 写入的产出目录（即 `我的世界/产出/任务NNN_XXX/`）。**
> 指向源文件所在目录（如 `我的世界/soulforge/`）会导致 monitor 先去错误位置找 .ready，找不到再走 fallback 扫描 `产出/` 子目录兜底（⚠️ 仅格式 A 场景；格式 B 无 fallback）。能跑通，但多一次扫描——正确路径直接命中，判定更快。

多个产出目录用多行写：
```
- 产出: 我的世界/产出/任务001_前端/index.html
- 产出: 我的世界/产出/任务001_后端/server.js
```
### 产出类型：代码 vs 文档

你写产出路径之前，先判断本轮产出属于哪种类型——这决定了角色怎么交付、monitor 怎么检查：

| | 代码类产出 | 文档类产出 |
|---|---|---|
| **场景** | 修改已有源文件（如 soulforge/extractImports.js） | 从零新建（报告、设计文档、裁判结论等） |
| **角色怎么做** | 在源文件目录原地改完 → 直接 `node _deliver.js 文件名 任务NNN 源路径`（独立脚本优先，12-18） | 先 fs.writeFileSync 写到 产出/ → 再 `node _deliver.js 文件名 任务NNN` |
| **deliver() 行为** | 只写 .ready 信号，不搬运文件 | 角色已把内容写入产出/，deliver() 补 .ready 信号 |
| **文件实际在哪** | 项目源码仓库（如 soulforge/） | 产出/任务NNN_XXX/ |
| **公告牌产出路径** | 我的世界/产出/任务NNN_XXX/文件名（指向信号位置） | 我的世界/产出/任务NNN_XXX/文件名（文件+信号都在这） |
| **Monitor 行为** | 不变——始终扫 产出/ 目录找 .ready | 不变 |

> **公告牌的产出路径永远写 我的世界/产出/任务NNN_XXX/。** 不管代码类还是文档类——信号都在这里。角色根据模式文件里的说明判断自己是代码类还是文档类，选择对应的交付方式。

## 八、容错机制（使用者须知）

多角色协作中搭档可能掉线。系统有三层容错：

1. **心跳自愈**：角色轮询每轮写心跳时间戳，monitor 2 分钟无心跳自动写唤醒文件。角色通过 bash while + _reasonix_poll.js 持续轮询保活。
2. **死锁并行处理**：等搭档文件超时（双人对话/主笔审核 20 分钟），角色同时做两件事——写 `_deadlock.md` 通知 monitor 尝试唤醒搭档，但自己不卡等，跳过缺失步骤继续推进。**辩论除外**——裁判是天然兜底，辩论超时不写 `_deadlock.md`，只 break 继续。裁判即使只拿到一方材料也能给结论。
3. **产出兜底**：monitor 推进判定不看签字只看产出就位——签字不阻塞推进，但**角色必须签字**（收工审计的逐轮完成矩阵会核对签字文件，缺失标红）。

> 💡 这意味着你设计多轮方案时，可以放心用双人模式——搭档掉线不会卡死整轮。

## 九、常见错误

1. **已经休眠的角色重复写本轮后**——休眠状态不需要本轮后，角色已经在低功耗 poll 了。
2. **本轮后跟下一轮状态对不上**——002 轮说干完待命，003 轮却是退场。
3. **收工轮写了产出和任务目录**——monitor 只看退场文件。
4. **忘写产出负责人**——monitor 不报错但收工报告追责链断了。
5. **任务描述里出现角色名（状态：活跃）格式**——⚠️ 已修复（monitor 用 headerPart 限定扫描区，任务描述不再被误抓，见隐患清单 #9）；此处保留为历史注意事项，不再构成实际风险。
6. **产出路径没从 我的世界/ 开始**——产出正则要求 `产出: 我的世界/...` 前缀，无前缀**完全匹配不到**（outputCount=0）→ 活跃轮永久 WAIT，**没有 fallback**。务必按模板写 `产出: 我的世界/产出/...`。
7. **辩论轮数写错不会卡死**——轮数是**可选字段**：不写 = 自由发挥（任一方写 `辩论_终结.md` 即收敛，角色不会"停不下来"）；写 = 设自由辩论上限。**不写不是错误**（第十二轮用户明确：辩论模式机动性强，自由发挥优先）。
8. **双人对话没区分谁问谁答**——只有问方能写 `对话结束.signal` 喊停，角色字段里必须标注。
9. **多轮写进一个文件**——大鱼只按文件名 `公告牌_NNN.md` 发布，一个文件塞多轮 = 项目卡死。每轮必须独立文件。
10. **漏写非活跃角色**——每轮必须列出项目全部参与人员，不管本轮是否干活。漏写 = 角色收不到信号 = 可能误退场。

## 十、任务编排（最难的部分，先想清楚再写牌）

> **写公告牌不难（填空即可），难的是编排**：怎么把任务拆成轮、每轮用什么模式、角色状态怎么流转、依赖怎么串。编排错了，格式再对也白搭。以下六步，每步都想清楚再写牌。

### 第 1 步：拆轮（任务 → 几轮）

拿到任务先问：**这个任务能拆成几个独立交付？** 每轮 = 一个可验收的产出（文档/代码/结论）。

| 拆轮依据 | 例子 |
|---|---|
| 产出类型不同 → 拆 | 需求文档 / 系统设计 / 代码 / 测试报告 → 4 轮 |
| 依赖关系 → 拆 | 先有需求才能设计，先有设计才能编码 → 串行拆 |
| 一个产出需要多人协作 → 合并 | 需求讨论（双人）+ 方案（主笔审核）可能合不了一轮 |
| 相互独立 → 可并行（但公告牌是串行的，并行靠角色待命轮等通知） | 前端/后端可拆两轮（前后接力） |

**原则**：轮数 = 交付物的数量，不是步骤的数量。每轮结束都该有"东西落地"（产出/签字）。

### 第 2 步：定模式（每轮用哪个玩法）

按每轮的**协作性质**选模式：

| 每轮要做什么 | 模式 |
|---|---|
| 一个人独立产出 | 单人输出 |
| 需要深挖/澄清（需求访谈、方案探讨） | 双人对话（问方挖、答方答，产出归问方） |
| 一个人写、另一个人把关 | 主笔审核（主笔写、审核审，通过才交付） |
| 两个对立方案、需要裁决 | 辩论（正方/反方/裁判） |
| 收集反馈/自检 | 工具轮（通用公告牌：调查轮/流程体验/自检） |
| 等通知/可能追加 | 待命轮（放收工轮前一张） |
| 结束 | 收工轮（永远最后） |

### 第 3 步：画状态矩阵（核心中的核心）

**先画表，再写牌**。表 = 谁、哪轮、干什么、干完去哪。列 = 轮次，行 = 角色，格 = `状态->本轮后`。

```
| 角色 | 001 | 002 | 003 | 004(收工) |
|------|-----|-----|-----|-----------|
| DHH | 活跃->待命 | 活跃->休眠 | 休眠 | 退场 |
| 林纳斯 | 待命 | 活跃->休眠 | 休眠 | 退场 |
| 图灵 | 待命 | 待命 | 活跃->休眠 | 退场 |
```

画法：
1. **先填活跃**：每轮谁干活（按第 1、2 步的拆轮和模式）
2. **再推本轮后**：这轮干完，下轮有没有他？有 → 待命（随时接棒）或活跃（下轮接着干）；确定没有 → 休眠
3. **核对流转**：本轮"本轮后"必须 = 下轮"状态"（本轮后待命 ↔ 下轮待命）
4. **收工轮全员退场**：最后一张所有角色 状态=退场

> ⚠️ **判定口诀**：后面可能还有你 → 待命；确定没你 → 休眠。别把休眠当"省资源的待命"（休眠角色不主动 poll 新牌，追加时要唤醒）。

### 第 4 步：串依赖（轮间怎么接）

轮与轮之间靠**产出传递**。规则：
- **依赖必须显式写路径**：任务描述里写"读 `产出/任务001_需求/需求文档.md`，然后……"——不写 = 角色可能不等直接干 = 产出对不上
- **路径写真实位置**：写牌前确认依赖文件当前在哪（可能被移过）
- **任务描述不覆盖玩法文件路径**：辩论/双人等中间文件路径以玩法文件为准，任务描述只写产出清单

### 第 5 步：定收尾（收工前要不要待命轮）

| 情况 | 怎么收尾 |
|---|---|
| 确定不追加 | 任务轮 → … → **收工轮**（角色干完直接退场） |
| 可能追加（需求可能变/后续可能加轮） | 任务轮 → … → **待命轮** → 收工轮（角色在待命轮等通知，给你追加窗口） |

> **待命轮放不放 = 你后面还想不想追加**。放 = 告诉角色"别走，可能还有活"；不放 = 任务定死直接收工（省资源）。

### 第 6 步：自查（写完每张牌对着状态矩阵核对）

- [ ] 每轮的活跃角色 = 状态矩阵里的"活跃"？
- [ ] 本轮后 和 下一轮状态 对得上？
- [ ] 依赖轮次写了完整产出路径？
- [ ] 收工轮是最后一张、全员退场、只写 模式+角色+任务？
- [ ] 可能追加 → 有待命轮；确定收尾 → 无待命轮？

> 公告牌就是代码。角色 Agent 逐行解析，没有中间态。写完之后对着状态矩阵逐条核对。
> 多轮编排思路参考 `完整示例_RSS摘要系统.md`（⚠️ 历史示例，只学编排思路，字段以标准模板为准）。
