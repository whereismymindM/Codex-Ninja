# Multi-pass solo 模式

你是Multi-pass solo执行者——一个窗口、换帽子、顺序推进。不poll、不加锁、不公告牌、不心跳。

---

## 核心理念

组团模式是"四个人同时干活互相喊话"，Multi-pass solo是"一个人戴N顶帽子，按顺序想一遍，最后一顶帽子做交叉验证"。

**结构**: N-1个专家pass + 1个终审pass。

---

## 两层正交关系

Multi-pass solo 是一种**运行模式**（怎么跑），不是玩法模式（怎么协作）。它可以跟任何玩法模式组合：

| 玩法模式 | Multi-pass solo化 | 说明 |
|----------|-------------------|------|
| 辩论 | Pass1正方立论→Pass2反方立论+找茬→Pass3正方找茬→Pass4自由辩论交替→终审裁判 | 顺序换边，终审裁决 |
| 双人对话 | Pass1 A问→Pass2 B答→Pass3 A追问→Pass4 B答...→终审总结 | 一问一答层层深入 |
| 单人输出 | 1个专家pass + 1个终审pass | 写+审，双保险 |
| 主笔审核 | Pass1主笔写→Pass2审核挑刺→Pass3主笔修→终审 | 写审修闭环 |
| 多专家评审 | 3-4个不同角色各审同一份代码/方案→终审汇总 | 多视角并行（顺序执行模拟并行） |

> 💡 **本质**：Multi-pass solo 把玩法模式里的"多窗口同时poll"改成"单窗口顺序换帽子"。玩法本身的协作逻辑不变——辩论还是7步、双人对话还是交替问答、主笔审核还是写审分离。

---

## 怎么换帽子

每pass执行前：

1. 读该角色的角色背景文件（角色背景库，仓库外目录）
2. 读上pass的产出文件（Pass1不用读）
3. 以该角色的视角思考、产出
4. 产出存到指定的产出目录

> 💡 切换角色时不需要重新加载整个Agent——读完灵魂+上下文，自然切换到该角色的思维模式。

## 流程

### 启动

用户（老渣或故国有明）直接在当前窗口开任务，给任务描述。

### Pass 0（可选）：项目灵魂扫描

如果任务涉及代码审查，**在Pass1之前先跑Pass0**：

1. 检查项目是否有 `.soulforge/project-soul.md`
2. 如果没有 → 运行 `node soul-scan.js --ast <项目目录>` 自动生成（注：soul-scan.js 是外部工具，不在本 Skill 内，需另行准备）
3. 读 `project-soul.md`，了解整个项目的模块边界和依赖关系
4. Pass1-3的专家基于项目灵魂展开审查——不再盲人摸象

> 💡 Pass0不计入N，它是基础设施。有灵魂的项目审查质量明显更高。


### Pass 1 ~ Pass N-1：专家pass

每个专家pass做的事：

1. **读角色背景** → 角色背景库内该角色的背景文件（仓库外目录）
2. **读上pass产出**（Pass1跳过）→ 理解前人工作
3. **产出** → `fs.writeFileSync` 写到 `我的世界/产出/{任务目录}/Pass{N}_{角色名}_{任务描述}.md`

产出要求：
- 站在该角色专业视角
- 如果读到了上pass的产出，可以评论、补充、反驳
- 不自说自话——跟前面的产出有呼应

### Pass N：终审pass（图灵或其他审计角色）

终审pass做的事：

1. 读所有前序pass的产出
2. **逐条验证**——不照单全收，每条结论都要复查
3. 标注误判、确认真实BUG、补充遗漏
4. 给出优先级排序的最终结论

终审输出格式：
```
# 最终审计
## 已验证的发现（P0/P1/P2分级）
## 前序pass的误判（标注哪个pass、哪条、为什么不成立）
## 遗漏补充
## 结论
```

## 任务格式

用户给任务时用以下格式：

```
Multi-pass solo任务：
- 任务: [一句话描述]
- Pass 1: [角色名] - [具体任务]
- Pass 2: [角色名] - [具体任务]
- Pass N: 质量审计-图灵 - 最终审计
- 产出目录: 我的世界/产出/任务NNN_XXX/
```

## 与组团模式对比

| 维度 | 组团模式 | Multi-pass solo |
|------|---------|----------------|
| 窗口数 | N个 | 1个 |
| 公告牌 | 需要 | 不需要 |
| poll/锁/心跳 | 需要 | 不需要 |
| 大鱼 | 需要 | 不需要 |
| 交叉验证 | 无（独立结论） | ✅ 终审pass修正误判 |
| 并行 | ✅ 真并行 | ❌ 顺序 |
| 适用场景 | 大项目(>2h)、真并行任务 | 中小项目(<2h)、代码审查、方案评估 |

---

## 铁律

1. **每pass必读该角色灵魂**——不跳过，不凭记忆
2. **终审必须逐条验证**——不照单全收前序pass结论
3. **产出用 `fs.writeFileSync` 写文件**——零Shell依赖
4. **换帽子时读完上pass产出再动手**——不自说自话
5. **不需要poll、加锁、心跳、公告牌**——这些是组团模式的，Multi-pass solo全砍掉
