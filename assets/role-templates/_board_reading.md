# 公告牌解读（怎么读牌）

> 本文件是角色 poll 到新公告牌（退出码 0）后的读牌指引。循环骨架见 `_startup_steps.md`；干活动作见 `_workflow.md`。

---

## 读牌四步（顺序执行）

### 第一步：第一眼必读警告栏

`- ⚠️ 警告:` 栏 = **本轮临时约束的唯一通道**——你的 AGENTS.md 铁律管"全局通用约束"，警告栏管"只本轮适用的特殊要求"（禁止某操作/编码坑/依赖前置/特殊流程/临时规则）。**模板里没有的约束，都从这里下达**，第一眼必读。
**无警告栏 = 本轮无特殊注意**，按正常流程执行，不要自己加戏。

### 第二步：先判定轮类型，再选动作

先读该轮的模式字段/你的角色行，**判完类型再选模板**——避免读到"不要 while"与"while 模板"时不知选哪个：

| 读到什么 | 轮类型 | 去哪 |
|---|---|---|
| `模式: 待命` 或 角色行 `状态：待命`（整轮待命） | 待命轮 | 待命轮询（bash while + --standby，骨架见 `_startup_steps.md`） |
| `模式: 试用` | 试用轮 | 等真人试用反馈（见 `_workflow.md`「试用轮」）——角色待命等反馈，收到后按反馈修 → deliver+sign |
| `模式: 收工` | 收工轮 | `_workflow.md`「收工轮」（创建退场文件） |
| 其余（任务轮） | 干活轮 | 读自己的角色行 → **先读对应玩法文件再动手**（模式→玩法文件映射见 `_workflow.md`「活跃」节） → 按玩法流程干活（顺序链：先读玩法 → 再读任务 → 动手） |

> 🚪 **判完就走**：按上表「去哪」列跳转执行，**本文件其余章节（状态机/状态明细/待命重要性/追加认知）是参考非必读**——需要时再回来看，不要为了"读完整"拖慢干活。全流程地图见 `_startup_steps.md` 顶部「全流程全景图」。

### 第三步：找自己的角色行，看状态

| 状态 | 这轮你干什么 |
|---|---|
| **活跃** | 干活：读公告牌任务 → 按玩法文件干活 → deliver → sign |
| **待命** | 这轮没你的事，但随时可能被叫——**持续 poll 等下一张公告牌，绝不私自下线** |
| **休眠** | 暂时退场，只等收工或唤醒——写休眠文件 + 继续 poll；**poll 到非活跃新牌 → lastN+1 写盘跳过**（见 `_workflow.md`） |
| **退场** | 收工轮——创建退场文件 → 追加流水账 → 输出最终回复 → 停止（唯一停止点） |

### 第四步：看「本轮后」字段

- 本轮后：待命 → 干完转待命轮询（--standby）
- 本轮后：休眠 → 写流水账 + 休眠文件 + 切高频轮询
- 本轮后：活跃 → poll 下一轮公告牌，正常走
- 🔒 **推进门**：**当轮次任务未完成，即使 poll 到下一张公告牌也不得推进**——只有完成当轮次任务（交付output/交review-result/职责已尽），才能推进到下一轮。收工轮同理：职责未竟不得退场（先补交/求助/说明）。"poll 到新牌"只是"有下一轮"的信号，**不是"当轮已完成"的许可**。
- **无「本轮后」字段** → 默认按活跃干活处理（字段缺失 ≠ 待命）

### 附：任务目录不存在时怎么办（干活轮常见第一道坎）

公告牌发布时任务目录（`我的世界/taskNNN_XXX/`）**未必同步创建**——问方/首写者还没开始建，或目录要由搭档创建。遇到 `ls taskNNN_XXX` 报"找不到目录"时：

1. **先别急着判路径写错**——任务目录缺失 ≠ 公告牌写错，大概率只是"还没建"
2. **查搭档心跳**（`../我的世界/{搭档}_talk/_heartbeat.txt`）判断：
   - 搭档活着 → 是"还没开始"，继续等（或问方自己是首写者则 `mkdir -p` 自己建）
   - 搭档心跳死 → 写求助给大鱼
3. **自己是首写者/产出负责人** → `mkdir -p` 建任务目录再干活
4. **自己只是等搭档** → 直接 `wait_file.js` 等搭档文件（**不要带 `--parent-check`**——带了会 WAIT_PARENT_MISSING 误报；等搭档写文件时目录自然被建）

## 公告牌字段 ↔ 动作对照表

| 公告牌写法 | 你的动作 | poll 间隔/模板 |
|---|---|---|
| `模式: 待命`（整轮） | 整轮待命——跳过干活+签字，**lastN+1 写盘**后持续 poll 等下一张牌 | **待命轮询（bash）while + `--standby`**（15s 节拍） |
| 角色行 `状态：待命` | 同上（两种写法等价）；标准写法为 `状态：待命，等通知`（"等通知"= 明确后面可能还有任务，写牌标准；monitor 按"待命"匹配，带不带均识别） | 同上 |
| 角色行 `状态：活跃，本轮后：待命` | 先干活+签字，干完转待命轮询（--standby） | 干活轮每轮 poll 一次；干完转待命 --standby |
| 角色行 **无「本轮后」字段** | 默认按活跃干活处理（字段缺失≠待命） | 干活轮每轮 poll 一次 |
| `模式: 试用` | 待命等真人试用反馈 → 收到后修 → deliver+sign（见 `_workflow.md`「试用轮」） | 普通 poll（收到反馈才有产出） |
| `模式: 收工` | 创建退场文件 → 追加流水账 → 输出项目完成 → 停止（见 `_workflow.md`「收工轮」） | 唯一合法停止点 |

### 状态明细表（图的分支 → 表里查细节）

| 状态 | 含义 | 你该干什么 | 判别要点 |
|------|------|-----------|---------|
| **活跃** | 这轮你干活 | 读公告牌任务 → 干活 → deliver → sign | 公告牌角色行标 `状态：活跃` |
| **待命** | 这轮没你的事，但随时可能被叫 | **跳过干活+签字（lastN+1 写盘），持续 poll 等下一张公告牌**，绝不私自下线 | `--standby` 15s 节拍；**不写休眠文件**；只等新牌/收工/唤醒 |
| **休眠** | 暂时退场，只等收工或唤醒 | 写休眠文件 + 继续 poll；**poll 到非活跃新牌 → lastN+1 写盘跳过**（见 `_workflow.md`） | 3s 高频节拍；**先写 `{角色}slept_NNN` 文件**（只写一次，除非被唤醒）；只等收工/唤醒 |
| **退场** | 收工轮 | 创建退场文件 → 追加流水账 → 输出最终回复 → 停止（唯一停止点） | 收工轮 `模式: 收工`；写 `{角色}retired_NNN` |

> **待命 vs 休眠，一眼区分**：都是"持续 poll 不下线"，但**待命 = 15s 慢节奏 + 不写文件**（随时接棒）；**休眠 = 3s 快节奏 + 写休眠文件**（低功耗等唤醒/收工）。看公告牌角色行是 `状态：待命` 还是 `状态：休眠`，以及本轮后字段。
> **判定口诀**："**后面可能还有你 → 待命；确定没你 → 休眠**"——你的「本轮后：待命」= 自己持续 poll 等新牌（可能追加）；「本轮后：休眠」= 只等唤醒/收工（确定后续没你）。**别把休眠当"省资源的待命"**——休眠时不主动 poll 新任务牌，追加需大鱼唤醒。

## 待命轮的重要性（最高铁律）

- 待命轮（`模式: 待命`——**标准写法：半角冒号+空格 `模式: 待命`**，按这个字面匹配；源码兼容全角/无空格（容错），但**按标准写法最稳**）说明**任务可能还要追加**——它之后可能有新公告牌（追加任务），也可能直接收工
- **待命轮之前/期间，绝对禁止私自下线**——你看到的最后一张牌是待命轮，不等于项目结束，后面可能还有活
- **待命轮之后**：持续 poll 等通知——新公告牌来了就干活，收工轮来了就退场。**只有收到收工轮（`模式: 收工`——半角冒号+空格）才允许停止**

## 追加轮次认知

项目可能追加任务。**可能追加**时，最后一张公告牌是待命轮（`模式: 待命`）——之后可能插入新轮次：

- 你会看到**新的公告牌**（编号在待命轮之后）→ 接着干
- 或看到**收工轮**（`模式: 收工`）→ 创建退场文件退场
- ⚠️ **待命轮后收工轮可能被大鱼扣留 10 分钟才补搬**（可能追加任务，属预期行为）——待命轮期间你持续 poll（--standby 15s）等下一张牌，**不是卡死，不许自行下线**

你不需要协调追加流程（那是老渣和大鱼的事）——**只需跟着公告牌走**：有新牌就干，收工轮就退场，待命轮就继续 poll 等。
