# 完整示例：RSS 摘要系统

真实生产场景，5 个角色、5 轮任务、3 种协作模式全覆盖。

---

## 角色

| 角色 | 职责 |
|------|------|
| 客户 | 提需求，说清楚想要什么 |
| 产品经理 | 聊需求、写方案、做审核 |
| 架构师 | 审方案、写系统设计 |
| 开发者 | 审设计、写代码 |
| 测试 | 验收代码、出测试报告 |

---

## 全局编排

```
第001轮 · 双人对话  客户(问)↔产品经理(答)  需求挖掘
第002轮 · 主笔审核  产品经理(主)↔架构师(审)  产品方案  客户退场
第003轮 · 主笔审核  架构师(主)↔开发者(审)    系统设计  产品经理退场
第004轮 · 单人输出  开发者                   写代码    架构师退场
第005轮 · 双人对话  测试(问)↔开发者(答)      测试验收  
第006轮 · 收工      🏁 全员退场                         开发者退场+测试退场
```

## 关键设计点

- **退场逐轮递减**：002 客户退 → 003 产品经理退 → 004 架构师退 → 005 干活轮（无人新退）→ 006 全员收工。每轮该退的人在下一轮公告牌标退场，干净利落。最后一轮专门发收工公告牌，所有角色同时看到退场、同时下线。
- **公告牌大白话**：每轮任务描述都写清楚了谁干什么、产出什么、放哪——角色读得懂。
- **模式覆盖**：双人对话(001/005) + 主笔审核(002/003) + 单人输出(004) + 收工(006)，四种模式全触发。
- **收工机制**：006轮角色读到全员退场 → 写退场文件 → 停止轮询 → 告知用户关窗。大鱼监控检测到活跃角色=0直接过关。
- **角色复用**：产品经理先做答方、再做主笔、最后做审核——同一个角色在不同轮次担任不同角色。
