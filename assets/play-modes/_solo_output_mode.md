# 单人输出模式

没有搭档，你一个人挑大梁。公告牌告诉你做什么、产出放哪。

---

## 怎么做

读公告牌 → 理解任务 → 动手干 → **用 `node _deliver.js <产出文件名> <任务目录>` 交付**（独立脚本优先；零Shell依赖，0.1秒）→ **用 `node _sign.js <轮次号>` 签字**（禁止手写签字文件——铁律 6）。
> **代码类产出**（修改已有源文件）：源文件原地改完 → 直接 `node _deliver.js 文件名.js taskNNN 源文件路径`，只发 .ready 信号，不搬运文件。
> **文档类产出**（新建报告、设计文档等）：先 fs.writeFileSync 写到 `../world/output/` 目录（别在角色目录下建 output/） → 再 `node _deliver.js 文件名 taskNNN` 发信号（**必须带任务目录参数**，与主笔审核一致——缺参会写成 `output/undefined/`）。
> **完整示例**：公告牌写 `产出: world/output/task001_survey/`、`任务目录: world/task001_survey/` 时——`node _deliver.js wakeup-confusion_Reviewer.md task001_survey`。
> **任务目录参数 = 纯目录名 `task001_survey`，不带 `world/output/` 前缀**（脚本自动拼 `output/`）——别把公告牌的 `产出:` 路径原样传进去（那是 monitor 按字面查的完整路径，不是 deliver 参数）。

### 🔑 终审 pass（产出后、deliver 前，必做）

**没人审你，你自己就是终审者。** 产出初稿后、deliver 前，强制过一遍终审（逐条验证 → 交叉核验 → 定稿，三关必过）：

1. **逐条验证**——不照单全收自己的初稿：每条结论/要点复查一遍（依据是否真实、逻辑是否闭环、有没有自相矛盾）
2. **标注误判/存疑**——发现写错的标注并修正；无法验证的标注「存疑」
3. **补充遗漏**——初稿漏掉的关键点补上
4. **优先级排序**——若产出含问题/建议清单，按 P0/P1/P2 排序

终审完再 deliver + sign。**产出质量第一道闸门在你这，不在审核（你没人审）。**


简单直接。别因为没人审就敷衍——自己是自己的第一道关卡。

---

## 签完字之后

读公告牌里你的「本轮后」字段——死循环 poll，永不主动下线：

### 本轮后：休眠
1. 写流水账 → 创建休眠文件
2. poll 短命令轮询（每3s，回合接力）——循环骨架见 `_workflow.md`「休眠」节（此处不重复）：

> 🚨 循环不退出！这个 while(true) 永不主动退出——只有公告牌出现或被大鱼唤醒才 break。

### 本轮后：待命
1. poll 短命令 + --standby 轮询（每15s，回合接力）——循环骨架见 `_startup_steps.md`「待命」节（此处不重复）：

> 🚨 待命不是下班！while(true) 循环到底，等下轮公告牌。

### 本轮后：活跃
继续 poll 下一轮公告牌，正常走。

## 语言规则

- 对话/报告文件内容**默认中文**——与搭档/公告牌语言一致（Node 直写中文零编码税）
- 公告牌、代码注释保持中文
- 你已精通中英双语，英文不影响人格

## 注意

- 没搭档不等于没标准——自己是自己的第一道关卡，产出质量与交付信号（.ready）都必须真实
- **终审 pass 是单人输出的默认配置**（见上方「🔑 终审 pass」节）：产出后、deliver 前必须自审一遍（逐条验证/标存疑/补遗漏）——多角色模式下没人交叉验证你的产出，所以单人输出默认自带终审自检
- 产出路径必须与公告牌一字不差（铁律 8）
- **交付三查（单人模式最高频踩坑）**——每次 deliver 前自查：
  ① **路径一字不差**：产出文件名/任务目录名与公告牌产出行完全一致（少一个字 = monitor 找不到 = 白干）
  ② **deliver 必带任务目录参数**：`node _deliver.js 文件名 taskNNN`（缺第 3 参会写成 `output/undefined/`，monitor 永不匹配）
  ③ **deliver 后自检 `.ready`**：确认 `../world/output/taskNNN/文件名.ready` 存在（deliver 只发信号，内容文件要先写入）
- **重启续接**：会话重启后按 `_startup_steps.md` 启动自检——签字存在→N++ 跳过已完成轮；签字不存在但有产出文件→从断点继续（**禁止重写已交付的产出**——覆盖 = 污染交付历史，.ready 已就位就别再动）；产出确实要改 → 先确认目标 `.ready` 不存在或改后重新 deliver。
