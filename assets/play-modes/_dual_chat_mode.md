# 双人对话模式

两个人深度碰撞一个话题：**问方**（挖掘者）连续追问，**答方**（思想引擎）逐答。公告牌告诉你谁问、谁答、搭档是谁、聊完要产出什么。

> ⚠️ 铁律：这不是"问答游戏"，不是"问够三轮就交差"——问方的使命是把答方脑子里所有相关的东西榨出来，**直到答方连续两轮说不出新东西为止**。

> 本文按**流程式**组织：先看你对应的「主干流程」，遇到分支（对话结束/失联超时/信号）再翻对应小节。

---

# 一、角色

- **问方（挖掘者）**：连续追问，把答方脑子里的东西挖干净；产出归问方（本模式固定）
- **答方（思想引擎）**：每轮回答 = 观点 + 为什么不是其他方案 + 一个不确定的地方 + 一个扎心的例证

---

# 二、问方 · 主干流程

**1. 出题**：写 `chat_{公告牌轮次}_T{第几问}_ask.md` 到任务目录（写完**立即**发同名 `.signal`）
- 第一问可以宽，但必须带"钩子"——答方没法用模板回答的角度
- **T 序号递增防旧信号秒返**：新问 T = 当前最大 T + 1——先 `ls <任务目录> | grep -oE "T[0-9]+" | sort -t T -k2 -n | tail -1` 取最大 T，**禁止凭记忆手写序号**

**2. 等答方回答**：wait_file 等 `chat_{轮次}_T{N}_answer.md.signal`（`--watch-hb` 监控答方心跳）→ 读到后读 answer 内容（wait_file 自动 ack）

**3. 判断"挖到新东西"**：
```
答方说了之前没提过的新观点/新例证/新角度 → 新东西 +1 → 回 1 继续追问
答方只是换说法重复前面的 → 没新东西 +1 → 连续两次 → 跳 4
不确定？问自己：这句删掉，前面的回答有损失吗？没损失 = 没新东西
```

**4. 结束对话 → 创建 `chat-end.signal`**（单独文件放任务目录，本身就是信号文件）
- 语义 = "不再有新问"：**只有确定不再发任何新问时才创建**；还有最后一问（预告收尾）→ 先发完问等答完再创建
- 创建前确认当前无未答之问；**创建后禁止再发新问**（确需追加 → 先把 chat-end.signal 改名 `chat-end_processed.signal` 再发）
- 细节见「分支·对话结束」

**5. 写产出（产出归问方，本模式固定）**：把对话精华提炼成产出（不是抄对话）→ 写前先检查目标 `.ready` 是否已存在（存在 = 已被交付/代交付 → 不覆盖，读已有补充）→ 写到 `../world/output/` → `node _deliver.js <产出文件名> <任务目录>` 发 .ready

**6. 签字**：`node _sign.js N`（独立脚本优先）

**7. 看「本轮后」**：休眠/待命/活跃（同主笔审核模式）

---

# 三、答方 · 主干流程（循环执行，直到问方喊停）

**1. 等"结束信号 或 下一问"**（wait_file `--any`，**必须带 `--any`** + `--watch-hb` 问方心跳）：
```
node temp-scripts/wait_file.js <任务目录>/chat-end.signal <任务目录>/chat_{轮次}_T{N}_ask.md.signal --any --watch-hb ../world/{问方角色名}_talk/_heartbeat.txt
```
- 返回后**先检查结束信号**（存在 → 收尾走第 4 步；不在 → 处理下一问走第 3 步）
- **🚫 答方永不自行判断对话完成**：每轮答完**必须回到本步**继续等"chat-end 或 下一问"——对话何时结束**只由问方决定**；禁止自行宣布"对话完成"只等结束信号（那会错过下一问，双方互锁）。你永远不知道还剩几轮，**每次答完都当"可能还有下一问"来等**

**2. 判断等到的是什么**（结束信号与新问并存：比较 mtime，晚者优先）
- `chat-end.signal` mtime 晚于（或等于）新问 .signal → 收尾，跳第 4 步
- 等到的是问题文件 → wait_file 已自动 ack；手写轮询先删 `ask.md.signal`（读完即删防秒返）→ 走第 3 步

**3. 写回答**：写 `chat_{轮次}_T{N}_answer.md` 到任务目录（写完**立即**发同名 `.signal`）
- 每个回答 = 观点 + 为什么不是其他方案 + 一个不确定的地方 + 一个扎心的例证（回答铁律见「十、铁律」）
- 答完回到第 1 步继续等

**4. 交付并签字**
- **产出归问方**（本模式固定）：问方正常 → 跳过交付，直接 `node _sign.js N` 签字
- **问方失联时**（检测到 PARTNER_DEAD）→ **你代写产出**：把对话精华整理成产出（标注"问方失联，答方代交付"）→ 写前先查 `.ready` 防覆盖 → 写到 output/ → `node _deliver.js` → 签字（单签）→ 流水账标注"对话终止于第 N 问"
- **设计对照**：主笔审核中主笔失联时审核**不代写**（审核只有审查意见、无产出素材）；此处答方握有完整对话内容，可代整理产出

**5. 看「本轮后」**：休眠/待命/活跃

---

# 四、分支 · 对话结束（chat-end）

- **结束信号语义 = "不再有新问"**：只有问方确定不再发任何新问时才创建 `chat-end.signal`；若还有最后一问（预告收尾）→ **先发完问、等答方答完，再创建**
- "说了收尾"不等于"现在结束"——说过预告 ≠ 同步创建（否则答方 wait_file --any 同时看到"问+结束信号"，比较 mtime 结束信号晚 → 误收尾丢掉最后一问答案）
- **创建前确认当前无未答之问**（T{N} 已答或明确放弃）；**创建后禁止再发新问**——确需追加 → 先把 `chat-end.signal` 改名 `chat-end_processed.signal`（铁律 2 允许改 .signal）再发新问
- **问方等答案超时**（20 分钟）→ **必须先创建 `chat-end.signal`**（解锁答方让它收尾）→ 再按超时规则推进 output/签字
- **问方侧监控答方失联**：等待答案时每 15 分钟查答方心跳（`--watch-hb`），失联 → 写求助 → 创建结束信号收尾（产出按已有材料整理）

---

# 五、分支 · 失联 / 超时

> **失联判据宽容（与 monitor 判 DEAD 同源）**：判对方失联前，先复查对方**对讲/output/任务目录最近阈值内（默认 15 分钟）有无新文件**：
> - **心跳 stale 但文件在动（在写/长思考）= 活着，继续等**——对讲目录静默但 output/任务目录有活同样不算
> - **只有"心跳 stale 且 output/任务/对讲均无新文件"才按失联处理**

**问方失联**（答方视角）：`PARTNER_DEAD`（wait_file exit 4）→ 写求助给大鱼 → **代写产出**（标注"问方失联，答方代交付"）→ deliver → 签字（单签）→ 流水账标注

**答方失联**（问方视角）：等待超时 → 复查路径 → 查答方心跳 + 近期文件（活着=继续等）→ 真失联 = 写求助大鱼 → **创建 chat-end.signal 收尾** → 产出按已有材料整理

**双人模式超时不再手写 _deadlock.md**（不手写，仅主笔审核模式写；双人/辩论由角色写求助大鱼）

---

# 六、等文件工具

**优先用 `wait_file.js`**（自动续心跳 + 自动 ack + 失联检测）。完整命令（复制即用，替换 NNN/轮次/T/角色名）：

```bash
# 问方等答方回答（--watch-hb 监控答方）
node temp-scripts/wait_file.js ../world/taskNNN_XXX/chat_001_T3_answer.md.signal --watch-hb ../world/{答方角色名}_talk/_heartbeat.txt --timeout 20
# 答方等"结束或下一问"（必须 --any，任一就位即返回）
node temp-scripts/wait_file.js ../world/taskNNN_XXX/chat-end.signal ../world/taskNNN_XXX/chat_001_T4_ask.md.signal --any --watch-hb ../world/{问方角色名}_talk/_heartbeat.txt --timeout 20
```

> **路径规则**：任务目录 = `../world/taskNNN_XXX/`（相对角色目录全路径，NNN=轮号、XXX=任务名，与公告牌一字不差）。`--hb` 可省略（自动推导续心跳）。
> **`--watch-hb` 传哪个文件**：传 `{搭档角色名}_talk/_heartbeat.txt`（monitor 判 DEAD 的**同源**文件）。对讲目录的 `_mtime.txt`（poll 时间戳）**别传它**——不参与判死，传错 = 失联检测与 monitor 不同源。
> ⚠️ 示例中的占位符**必须换成真实路径/文件名**，照抄字面量 = 永远等不到。

**内联 fallback**（仅当 wait_file 不满足需求时手写；CommonJS 同步版，**禁止顶层 await**）：

```js
// 等一个文件出现——CommonJS 同步版。替换 YOUR_FILE_PATH
const fs = require("fs");
const { execSync } = require("child_process");
var _deadline = Date.now() + 20 * 60 * 1000;
var _hbCtr = 0;
while (true) {
  if (fs.existsSync("YOUR_FILE_PATH")) break;
  if (++_hbCtr % 60 === 0) {
    var _hbPath = "../world/{{ROLE_NAME}}_talk/_heartbeat.txt";
    fs.mkdirSync(_hbPath.substring(0, _hbPath.lastIndexOf("/")), { recursive: true });
    fs.writeFileSync(_hbPath, String(Date.now()), "utf8");
  }
  if (Date.now() > _deadline) {
    // 双人模式口径：不手写 _deadlock.md（仅主笔审核写）——写求助给大鱼
    var _dlDir = "../world/{{ROLE_NAME}}_talk";
    fs.mkdirSync(_dlDir, { recursive: true });
    var _logName = _dlDir.split("/").pop().replace("_talk", "");
    fs.appendFileSync(_dlDir + "/" + _logName + "_poll-log.md", "[" + new Date().toISOString().substring(11,19) + "] 等文件超时（双人模式：写求助大鱼）\n", "utf8");
    break;
  }
  execSync("sleep 0.5", { stdio: "ignore" });
}
// 出了循环后：复查目标是否其实已就位 → 查搭档心跳（死了 → 写求助大鱼）→ 自己不停，缺失标注，最终签字
```

> ⚠️ **目标一律写 `.signal`，不要写 `.md`**——等 `.signal` 才自动 ack（改名 `.signal_acked` 防残留）；等 `.md` 不 ack，残留信号污染时序校验（role_lessons_archive 教训 #2/#3）。
> 🔴 **read_file 直读 .md = 违规**：读问/答 .md 必须用 wait_file.js（自动 ack）；若已用 read_file 直读，**读完下一条命令必须手动 ack**（`rename xxx.md.signal xxx.md.signal_acked`）——漏 ack = 残留 = 下轮秒返误判。
> ⚠️ **进入轮询前先 existsSync 检查文件是否已存在**：公告牌重写/搭档变更场景旧文件可能已在——已存在直接读判断可复用性，不要盲目进轮询等 mtime 变化。

# 七、信号规则（问/答通用）

- **写方**：写完 .md 的**下一条命令必须是发同名 `.signal`**（原子两步）——漏发 = 搭档空等；写方漏发时 wait_file.js 检测到（exit 5 报错）
- **读方**：读完对方 .md 必须处理同名 `.signal`（wait_file 自动 ack 改名 `.signal_acked`；手写路径 rename 后缀替换）——**禁止 bash mv 手动 ack**（留痕黑洞）
- **T 序号递增**：新问 T = 当前最大 T + 1（`ls | grep -oE "T[0-9]+" | sort -t T -k2 -n | tail -1`），禁止凭记忆手写——写错旧序号 → 命中残留旧 .signal 秒返 → 读旧内容重复回答

---

# 八、重启恢复

- 会话重启后：扫描任务目录 `chat_{轮次}_T*_问/答.md` 取最大 T 序号，推导当前该等的 `T{最大T+1}`
- 已答过的轮次**禁止重写**（覆盖 = 污染对话史）
- 若发现"问方写了 .md 但缺 .signal"（崩溃在两步之间）→ 问方补发缺失 .signal，答方按 .signal 为准

---

# 九、语言规则

- 对话/报告文件内容默认中文（与搭档/公告牌语言一致，Node 直写中文无编码问题）；公告牌、代码注释保持中文
- 文件写到任务目录下，不是对讲目录
- 别在问题末尾加 `---`（Markdown 分隔线，会被解析错）

# 十、铁律

**问方 · 追问铁律（违反一条就算失职）**：
1. 每次追问必须咬住上一答中最模糊的那个点（答方说"建议用微服务"→ 问"具体什么场景？单体能搞定为什么拆？团队人数？"）
2. 必须复述再追问——提问开头先用自己的话复述答方说了什么，确认听懂再挖
3. **连续两轮答方说不出新东西 = 才算深挖完成**——不是三轮自动结束；第 4 轮还在抖新料就继续挖
4. 追问维度自觉检查：数据/证据？边界/反例？代价/成本？替代方案？底层假设？
5. 问方看到答方连续两轮说不出新东西 → **立刻喊停**，别拖

**答方 · 回答铁律**：
1. **必须亮观点，不是列事实**——"这个场景适合是因为X"比"有以下特点A/B/C"有价值 100 倍
2. **必须自曝不确定**——每个回答至少一句"这方面我不太确定"或"这取决于X假设"
3. **必须有为什么不是其他方案**——说了一个方向后附带"之所以不选Y是因为……"
4. **用例证，不求多**——一个扎心的例子胜过十个不痛不痒的数据
5. 不要说"如上所述""如前文提到"——每一轮都当全新的思考来写
