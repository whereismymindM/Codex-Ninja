# 退场机制 v1 → v2 升级说明

> 读完本文 = 理解本轮 Skill 完善的全部理念和改动。
> 讨论参与者：质量审计-图灵、架构师-林纳斯、后端开发-DHH、技术VP-马斯克
> 老渣拍板：2026-07-23

---

## 一、v1 的问题（为什么改）

忍者效能优化项目暴露了三个痛点：

| 痛点 | 现象 | 根因 |
|------|------|------|
| 盲等焦虑 | DHH/马斯克待命时反复写求助「什么时候翻篇」，图灵干完活 poll 收工轮超时4分钟又写求助 | 角色不知道本轮结束后自己是什么命运 |
| 退了喊不回 | 角色退场=关窗。201轮退了，003轮需要他审核——断档 | 退场是不可逆操作，没有召回机制 |
| 签字命名Bug | 角色反复手写 `_签字_NNN.md` 而非 `_sign.js` 生成的 `完成_NNN.md`，monitor不认 | 工具未强制使用，角色习惯手写 |

核心矛盾：**角色需要确定性，但他们没有全局信息。** 中央调度不能动，角色自治不可行——唯一正确的方案是「中央调度信息透明化」。

## 二、v1 vs v2 核心对比

| 维度 | v1（原版） | v2（新版） |
|------|-----------|-----------|
| 退场后角色状态 | 关窗走人 | 切低功耗休眠，窗口不关 |
| 退场后轮询频率 | 不轮询（已关窗） | 每60秒轻量检查一次 |
| 大鱼能否召回 | 不能——角色已离线 | 能——写 `_wakeup.md`，角色下次轮询发现后切回活跃 |
| 角色知道本轮后命运？ | 不知道，只能盲等下一轮公告牌 | 知道——公告牌「本轮后」字段：退场/待命/活跃/待定 |
| 待命角色体验 | 反复 poll 公告牌，超时写求助 | 看到「本轮后：待命」就知道歇着等，看到进度提示知道在运转 |
| 退场文件 | `{角色名}已退场` | 不变——兼容 monitor |
| monitor 兼容性 | — | 不变——退场文件格式不变，monitor 无需改动 |

## 三、逐文件改动说明

### 3.1 `_poll.js` — 新增低功耗模式

**改动**：加两个 flag

```
--low-power          → 轮询间隔固定60秒（替代渐进式5/10/15/20/30秒）
--wakeup <对讲目录>   → 每次轮询时额外检查该目录下 _wakeup.md
```

**行为差异**：
- 正常模式：`node _poll.js ../我的世界/公告牌_NNN.md` → 每5-30秒查一次
- 低功耗：`node _poll.js --low-power --wakeup ../我的世界/林纳斯_大鱼对讲 ../我的世界/公告牌_NNN.md` → 每60秒查一次公告牌 + `_wakeup.md`
- 检测到 `_wakeup.md` → 删除信号文件，exit code 3（被唤醒）
- 检测到公告牌 → exit code 0（正常）
- 超时 → exit code 2

**设计理念**：低功耗不是关窗——是呼吸变慢。角色在线，大鱼随时能喊。

---

### 3.2 `_wakeup.js` — 全新文件

**定位**：大鱼的专属工具，放在 `火影-大鱼/` 目录下。

**用法**：`node _wakeup.js <角色名> <原因>`

**做的事**：在 `我的世界/{角色名}_大鱼对讲/` 下创建 `_wakeup.md`，写时间戳和召回原因。

**角色侧响应**：低功耗轮询时 `fs.existsSync(_wakeup.md)` → 读到内容 → 删除文件确认 → exit 3 → 切回活跃模式。

**设计理念**：最轻量的 IPC——文件系统就是消息队列。不需要 WebSocket，不需要长连接，一个文件搞定。

---

### 3.3 角色_AGENTS模板.md — 退场协议升级

**v1 原文**：
```
- 退场 → 分两步：
  1. 写流水账
  2. 创建退场文件，然后停止轮询，输出「窗口可以关了」
```

**v2 改为**：
```
- 退场 → 分三步：
  1. 写流水账
  2. 创建退场文件
  3. 切低功耗模式，不关窗
     node _poll.js --low-power --wakeup ../我的世界/{角色}_大鱼对讲 ../我的世界/公告牌_NNN.md
     输出「窗口可以不关——我在低功耗待命，大鱼随时可以唤醒我」
```

**设计理念**：退场不再是终点——是休眠。角色完成本轮使命后进入待机，既不给系统添乱（不 poll 公告牌干扰 monitor），又能被随时唤醒。

---

### 3.4 公告牌模板.md — 新增「本轮后」字段

**v1 格式**：
```
- 架构师-林纳斯（状态：活跃）
```

**v2 格式**：
```
- 架构师-林纳斯（状态：活跃，本轮后：退场）
```

**四个可选值**：
| 值 | 含义 | 角色行为 |
|:--:|------|------|
| 退场 | 本轮后走人 | 签字 → 流水账 → 退场文件 → 低功耗 |
| 待命 | 下轮歇着 | 签字 → poll 下轮公告牌，心里有底 |
| 活跃 | 下轮继续干 | 签字 → poll 下轮公告牌，保持注意力 |
| 待定 | 大鱼也不确定 | 签字 → 等大鱼在对讲里确认 |

**铁律追加**：
- 背景资料中禁止出现 `- 角色名（状态：活跃）` 格式样例——monitor 正则会误抓

**设计理念**：一行字消灭信息差。角色不需要知道全局——但需要知道自己接下来要干什么。成本为零，ROI 拉满。

---

### 3.5 四个模式文件 — 签字后看「本轮后」

`_单人输出模式.md` / `_双人对话模式.md` / `_主笔审核模式.md` / `_辩论模式.md`

**统一追加**：在每个模式最后一句话「签字」后面，加一段：
```
签字后，读公告牌里你的「本轮后」字段：
- 退场 → 直接写流水账+退场文件+切低功耗，不用poll下一轮
- 待命/活跃 → poll下一轮公告牌
```

**设计理念**：模式文件管「怎么干活」，退场协议管「干完活之后」。边界清晰。

---

### 3.6 大鱼_AGENTS模板.md — 新增唤醒协议

**新增章节**：「唤醒退场角色」——夹在「收工」和「跟老渣沟通」之间。

**三种唤醒场景**：产出有问题、收工后发现遗漏、老渣要追加任务。

**操作**：`node _wakeup.js 角色名 原因` → 角色60秒内切回活跃。

**设计理念**：大鱼不需要记住谁退了——需要谁就喊谁。退场不是消失，是待机。

---

### 3.7 scaffold.js — 配送 _wakeup.js

**fish 模式**：在复制 monitor.js 之后，加一行 `fs.copyFileSync` 把 `_wakeup.js` 送到 `火影-大鱼/` 目录。

**init/add 模式**：在复制工具文件列表里加 `_wakeup.js`，每个角色目录也放一份（方便测试和参考）。

**设计理念**：工具配送到位——大鱼用 `火影-大鱼/_wakeup.js`，角色可以用自己目录下的做本地测试。

## 六、四人共识摘要

## 背景

老渣提了两个方案让四人讨论：

> A方案：角色执行完任务即刻签字退场（干净利落，但不灵活）
> B方案：等下一轮公告牌写明退场才退（有仪式感，但盲等多一轮）

四人结论：A改良版——本轮公告牌直接标「本轮后：退场」。干完活立刻走，不等下一轮，也不靠猜。一行字消灭信息差，确定性不靠等待来换。

| 角色 | 核心立场 |
|------|------|
| DHH | 站中央调度不动，一行字能解决的信息差不需要拆架构 |
| 马斯克 | 「角色需要的是确定性，不是速度」——模糊比精确更诚实 |
| 图灵 | 单人输出+明确退场时可即刻切低功耗，但必须加召回窗口 |
| 林纳斯 | 「一行本轮后字段比三套安抚机制都管用」——提可召回状态+自动推导 |

**结论：四人全票通过 A 改良版。** 中央调度不动，信息透明化。退场不关窗，低功耗待命，大鱼可唤醒。

### 3.8 流水账追加模式（v2.1 补丁）

**问题**：多轮退场时，第二轮流水账会覆盖第一轮——因为 `fs.writeFileSync` 是覆写。

**修复**：退场第一步「写流水账」改为**追加模式**——如果文件已存在用 `fs.appendFileSync`，不存在才用 `fs.writeFileSync`。每次退场都在流水账里追加新段，保留完整历史。

改动位置：`角色_AGENTS模板.md` 退场协议第一步。
### 3.9 退场文件加轮次后缀（v2.2 补丁）

**Bug**：v1 退场文件名无轮次号（`角色已退场`）。v2 中002轮就写了退场文件，003收工轮 monitor 一查文件已存在直接判 RETIRE OK——不验证角色是否真正处理了收工轮。

**修复**：退场文件加轮次后缀——`角色已退场_NNN`。monitor 按当前轮次匹配。002的退场文件不会骗过003的检查。改动位置：`角色_AGENTS模板.md` 退场第二步 + `monitor.js` retireFile 路径拼接。

### 3.16 30s高频轮询 + 唤醒双保险

乔布斯测试揭露：回合制AI无法真正"持续低功耗轮询"——每次`node _poll.js`跑完回合就结束。60s低功耗窗口太大，公告牌到达时间错开就永远接不住。

**方案**：
- 轮询周期60s→30s（高频追公告牌，接住概率翻倍）
- 大鱼翻篇后立刻`_wakeup`唤醒所有退场角色（二重保险）
- 角色退场时不再说"低功耗待命"，改为"高频轮询+可唤醒"

### 3.17 大鱼常驻铁律

角色是回合制的，大鱼不是。新增铁律：项目期间大鱼永不主动下线——搬公告牌、跑monitor、翻篇、唤醒，全程在线盯到收工。

### 3.18 REPL版监控

Shell在多角色负载下10s超时截胡→监控失灵。改为Node REPL优先：在REPL定义`monitorFn()`，每次`await monitorFn()`——0.1~6s出结果，零超时。Shell版`node ../monitor.js`作为备用。


## 八、v2.4 多角色协作优化（部分已实施，部分设计稿）

> 乔布斯+尤雨溪双人对话暴露了 P2P 文件交换的固有问题：角色互 poll 任务目录等搭档，两个窗口抢资源，10分钟才跑完 6 轮。

### 4.1 交替单人模式（✅ 已实施）

核心：同一轮只活跃一人，其他待命或关窗。

```
001: A活跃提问，B待命
002: B活跃回答（去任务目录读A的001文件），A待命
003: A活跃追问，B待命
```

角色流程不变——看到活跃就去任务目录找搭档文件，看到待命就跳过。双人对话本质是两个单人输出交替进行。

**优势**：零互等、零传话、公告牌编排即可，代码零改动。乔布斯+图灵交替三轮实测通过。

**三种多人编排模式**（同一轮活跃不超过2人，其他待命）：

| 模式 | 示例 | 适用场景 |
|------|------|------|
| 串联 | 001:A活跃→002:B活跃→003:C活跃→循环 | 讨论、面试、逐人发言 |
| 并联+汇合 | 001:A+B同时活跃→002:C活跃审两份 | 主笔审核、多方案对比 |
| 辩论式 | 001:A+B同时活跃写立场→002:C活跃出结论 | 正反辩论、裁判裁决 |

核心不变：公告牌把并发拆成时序，大鱼不用改，角色不用改。


### 4.3 Shell自救规则（乔布斯实测）

交替单人模式下双窗口仍可能引发磁盘I/O过载→Shell全线挂死。乔布斯6分钟反复撞墙后切REPL瞬间恢复。规则：连续两次shell超时立刻切REPL，别等echo都跑不动。已写入角色AGENTS模板。
### 4.2 大鱼传话员（暂缓 · 以后讨论）

进一步优化方向：大鱼翻篇时读上一轮产出→提取摘要→写进下一轮公告牌的"搭档发言"字段。角色只读公告牌，不读任务目录。

### 公告牌新增字段

1. 读上一轮任务目录里的产出文件
2. 提取内容摘要写进下一轮公告牌搭档发言字段

### 优势：零等待、单窗口轮替不抢资源、预计6轮从10分钟降到3分钟

## 四、v2.3 v2.4 高频轮询修复

> 发现于 2026-07-24 四人提效讨论测试。林纳斯002轮退场后再也没醒过来。

### 4.1 致命Bug：低功耗轮询是伪命题

v2.3 号称退场不关窗，低功耗待命，但实际上：

角色退场 -> node _poll.js --low-power --max-wait 30 -> safeSleep(60s) <- Shell 10s 默认超时杀进程 -> 回合结束，角色实际下线

Shell 10s 超时 + _poll.js 60s sleep = 永远等不到第一次文件检查。agent 的回合制与低功耗轮询是根本矛盾的——除非 poll 全程在 Shell 超时内完成。

### 4.2 修复方案

_poll.js：低功耗间隔 60s -> 3s，默认 maxWait 30s -> 8s
角色_AGENTS模板：退场轮询从文字描述改为伪代码 while 循环
SKILL.md：追加 v2.4 说明

核心思路：每次 poll 控制在 9 秒内（3次检查x3s），安全落在 Shell 10s 超时线内。agent 看到 while 循环结构 -> 自然持续重跑 -> 真正的高频轮询而非一次性轮询。

### 4.3 为什么是 3s/8s

- 3s 间隔：够快——30s 内能检查 10 次，接住公告牌概率极高
- 8s maxWait：安全——3次检查 = 9s，在 Shell 10s 内
- 文件系统负载：3s 一次 fs.existsSync 可以忽略不计

## 七、v2.4.3 P2：抖动 + 自适应退避

**抖动**：`_poll.js` 低功耗模式启动时随机延迟 0-1.5s——多角色轮询相位错开，避免文件系统请求尖峰。
