# 主笔审核模式

一个人写，一个人审。公告牌会告诉你谁是主笔、谁是审核、搭档是谁、要产出什么。

---

## 主笔（每轮逐条执行）

**1. 写产出**
按公告牌指定的产出路径和文件名，把产出写出来。

**2. 发请审核**
在任务目录下写 `请审核.md`，告诉搭档可以审了。

**3. 等审核结果**
用 `REPL pollFile()` 等任务目录下的 `审核结果.md`。不管通过还是打回，审核方都写这同一个文件。

**4. 处理结果**
读 `审核结果.md` 第一行判断：
- 状态：通过 → 跳第 5 步（签字）
- 状态：不通过 → 读具体意见、改产出，把旧的 `审核结果.md` 重命名为 `审核结果_第N次.md`，重发 `请审核.md`，回到第 3 步

**5. 签字**
在对讲目录下写完成文件签字。

**6. 看「本轮后」**

读公告牌里你的「本轮后」字段——死循环 poll，永不主动下线：

- **本轮后：退场** → 写流水账 → 创建退场文件 → REPL 死循环低功耗 poll（每5s）：
`js
while(true) {
  let r = await pollFn();
  if (r === "FOUND" || r === "WOKEN") break;
  await new Promise(r => setTimeout(r, 5000));
}
`
- **本轮后：待命** → REPL 死循环间歇 poll（每60s）：
`js
while(true) {
  let r = await pollFn();
  if (r === "FOUND") break;
  await new Promise(r => setTimeout(r, 60000));
}
`
- **本轮后：活跃** → poll 下一轮公告牌，正常走

---

## 审核（每轮逐条执行）

**1. 等主笔发请审核**
用 `REPL pollFile()` 等任务目录下的 `请审核.md`。

**2. 审产出**
认真读，不是走过场。发现模糊、不完整、没数据支撑的地方必须打回。
读完立刻把 `请审核.md` 重命名为 `请审核_已处理.md`——清掉旧文件（不删除，保留审计线索），下次主笔重发新 `请审核.md` 时 poll 才能等到真正的新内容，不会被旧文件秒返骗过去。

**3. 给结果**
统一写 `审核结果.md`，第一行标注状态，后面写具体内容：
- 不通过 → 第一行写 `状态：不通过`，然后写清楚哪里不行、为什么不行，回到第 1 步
- 通过 → 第一行写 `状态：通过`，可附带简短评价，然后跳第 4 步

**4. 签字**
在对讲目录下写完成文件签字。

**5. 看「本轮后」**
读公告牌里你的「本轮后」字段——退场则写流水账+退场文件+切低功耗，否则 poll 下一轮。

---

## 注意

- 可以多轮打回，直到满意。


## ⚠️ P2-8: 审核结果同名覆盖风险

审核方多次审核写同一文件名。主笔在重发 `请审核.md` 前，**必须把旧 `审核结果.md` 改名归档**（如 `审核结果_第1次.md`），防止 poll 到旧内容误判。
