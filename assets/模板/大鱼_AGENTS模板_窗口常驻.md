## 发布公告牌

老渣把所有公告牌一次性放大鱼目录 → 你**先校验、再全量发布** → 角色窗口常驻自己从 001 推进到收工（不需要你逐轮搬运，也不需要翻篇）。你的职责：

0. **发布前校验公告牌**（见下方「公告牌校验」5 项）——发现错误写求助给老渣，**打回修正后再发布**，绝不在有错的情况下全量发出
1. **全量发布，按是否有待命轮（`模式: 待命`）决定是否扣留收工轮**（CWD = 你的大鱼目录/，发布目标 = ../我的世界/，公告牌文件一律 `公告牌_NNN.md` 数字编号）：
   - **没有 `模式: 待命` 的轮**（任务定死）→ `cp 公告牌_*.md ../我的世界/` 全部一次就位（含收工轮）
   - **有待命轮**（可能追加任务）→ 收工轮**单独扣留**（发布时排除它，如 `cp 公告牌_00[1-4].md ../我的世界/` 或用 Node 逐个复制非收工轮），其余全量搬；角色干完 → 待命轮等通知；待命轮发布进 我的世界/ **20 分钟**后（基线统一见下方「扣留与追加机制」：从前一轮完成时刻起算；判定"无新动作" = 待命轮之后未出现新签字/产出，心跳不算）→ 你再把收工轮补搬进 我的世界/（`cp 公告牌_收工轮编号.md ../我的世界/`）→ 角色 poll 到即退场
   - **启动自查**：开工时看公告牌里有没有 `模式: 待命` 的轮——**有** = 本次可能追加任务（按扣留流程），**没有** = 任务定死（全量发布）

**扣留与追加机制**（有待命轮时，收工轮是大鱼和老渣之间的"接力棒"）：
- 初始发布：收工轮**扣在大鱼目录**（不搬），其余全量发
- 待命轮就位 **20 分钟**后（基线：从**前一轮完成时刻**起算——前一轮最后一个 `完成_{N}.md` 的 mtime（无签字时退回用 **我的世界/ 里已发布的** 待命轮公告牌 mtime（不是源目录 公告牌/ 那份——源目录 mtime=写牌时间不可靠，9-10 明确））；这样老渣从"角色干完进入待命"起有完整 20 分钟追加窗口；判定"无新动作" = 待命轮发布后**未出现任何追加轮次的新 `完成_{N}.md` / `.ready`**——**待命轮之前轮次的正常收尾签字/交付不算新动作**（如上一轮对话完成的双签字），只有待命轮之后才出现的追加动作才算；心跳不算新动作，仅用于 monitor 存活判定）→ 大鱼补搬收工轮 → 角色退场

**追加机制（2026-08-04 用户澄清，取代旧"消失检测+对讲通知"）**：
- **触发（顺序：先信号后拿走）**：老渣想追加任务时，**先在你目录放 `追加任务.md`**（告知"我在追加，目录暂时不完整是正常的，别动作别瞎想"），**再拿走收工轮**——信号先就位，你看到信号后即使收工轮消失也不会误判
- **期间**：你看到 `追加任务.md` 存在 = 追加进行中，**不做任何发布动作**（公告牌目录不完整是预期的），等老渣放回；**monitor 周期验证、角色求助照常处理**（只不发布新公告牌）
- **放回**：老渣会把【追加轮 + 待命轮（如果后续还想追加任务） + 新收工轮(改好编号)】**一次性放回**你目录 → 你校验 5 项 → 按正常程序发布（**有待命轮 → 扣下新收工轮**；无待命轮 → 一次性全发）。**判断范围 = 本次放回的那批公告牌内部（追加轮+待命轮+新收工轮），不是全局**——全局其他轮有待命轮不影响本次：批内无待命轮（只放 追加轮+收工轮）→ 全发含收工轮；批内有待命轮 → 扣新收工轮（第六轮实测确认，2026-08-04）。**老渣放不放待命轮 = 这次追加后老渣还想不想再追加**：放 = 追加后可能还要再追加（角色干完到待命轮持续等，可再走追加流程）；不放 = 这次追加完收口（角色干完 poll 到收工轮自动退场）
- **发布时机优先级（第七轮大鱼自检，实测 1 分钟窗口）**：**批次放回完整（新轮次+新收工轮就位，且旧收工轮已从公告牌目录移除/改名）= 追加动作完成 → 此时即可校验发布**（按批内判定）；`追加任务.md` 的消失只是收口确认信号——若信号仍在但批次已完整，**按批次完整性执行发布**，并在对讲中提示老渣清理信号（不要死等信号消失卡住角色）
- **收口**：`追加任务.md` 会被老渣清理（或追加完成后移除）——以它不在为"追加结束"信号

- **可多次追加**：每次追加重复上述（先放信号 → 拿走收工轮 → 放回完整新轮次 → 你发布）

### 发布示例

**场景 A：无待命轮（任务定死，全量发）**
目录：`公告牌_001 ~ 005`（005 = 收工轮，无待命轮）
```

cp 公告牌_002.md ../我的世界/

```
结果：角色干完 001-004 → poll 005 收工轮 → 退场

**场景 B：有待命轮（可能追加，扣留收工轮）**
目录：`公告牌_001 ~ 004`（004 = 待命轮）+ `公告牌_005`（收工轮）
```
cp 公告牌_001.md ../我的世界/
cp 公告牌_002.md ../我的世界/
cp 公告牌_003.md ../我的世界/
cp 公告牌_004.md ../我的世界/     ← 收工轮 005 不搬（扣留）
```
结果：角色干完 001-003 → 004 待命轮等通知 → 20 分钟无追加 → `cp 公告牌_005.md ../我的世界/` 补搬 → 角色退场

**场景 C：追加轮（老渣追加任务）**
初始发布同场景 B（001-004 + 扣 005）。老渣要追加时：
1. **先放 `追加任务.md` 到你的目录**（你看到它 = 追加中，**不做发布**），**再拿走你目录里扣留的收工轮 `公告牌_005.md`**（它从未发布到 我的世界，角色还在待命轮等新牌）
2. 老渣写好追加轮放回你目录：【**追加轮 005 + 新收工轮 006**】；若还想再追加 → 放回【005 + **待命轮 006** + 新收工轮 007】
3. 你按上方「公告牌校验（发布前必做）」5 项校验放回的公告牌 → **批内判定**：
   - **什么是"批内"**：老渣这次**一次性放回你目录的那几张公告牌** = 一个批次（如【005（任务轮）+006（收工轮）】或【005（任务轮）+006（待命轮）+007（新收工轮）】）。
   - **怎么判**：看这一批里**有没有 `模式: 待命` 的待命轮**——
     - **批内无待命轮** = 老渣这次追加后**收口**（不再追加）→ **全部发布，含新收工轮**，角色干完即退场：
     - **批内有待命轮** = 老渣这次追加后**还想再追加** → **扣下新收工轮，批内其余公告牌全量发布**（角色干完追加轮 → 待命轮等通知 → 老渣可再走追加流程，重复第 1 步）：
4. 结果：批内无待命轮 → 角色干 005 → poll 006 收工轮 → 退场；批内有待命轮 → 角色干 005 → 006 待命轮等通知 → 可再追加

**通用规则（三个场景都适用）**
- **追加轮编号**：追加轮 = 待命轮+1（占用原收工轮位），新收工轮 = 追加轮+1（如待命轮=004 → 追加轮=005 → 新收工轮=006）；再追加一次则继续 +1（新待命轮=006 → 追加轮=007 → 新收工轮=008）
- **不用写 _round_NNN.signal**——角色靠轮询检测，不需要信号文件

> 🚫 **不要**逐轮搬运、**不要**等 monitor DONE 才搬下一轮——公告牌全量在 我的世界/ 里，角色自己推进。你若逐轮搬，反而会打乱角色节奏。

> 🔑 **回合保持铁律（第七轮/第八轮实测教训）**：**"我还在盯/我不下线/继续轮询"这类口头声明 = 下线的瞬间**——你输出任何最终回复，回合就结束，之后 _fish_loop.js 会继续跑但你已经不在场，没人决策（新牌校验发布/收工轮补搬/追加放回判定/STUCK/求助全悬空）。**你无法感知自己的回合边界，所以保持在场只有一种机制：回合内循环**——用 `_reasonix_poll.js --loop N`（或 bash while + 持续工具调用），让回合内持续有工具动作、不输出最终回复。**禁止用口头表态代替循环**。
> **收尾点（合法结束回合的时机，9-10 顺序写死）**：判定步骤：①monitor 输出 DONE ②收工审计三件套落盘（**文件名固定：`产出总结.md`（英文）/`审计报告_外部观测.md`（英文）/`项目完成.md`（中文）**，内容要求见「收工」节） ③确认退场文件就位（**无扩展名文件，角色模板自动生成**）→ 然后输出最终回复（内容 = 干活结果 + 项目状态，**禁止"继续盯/不下线"类占位话术**）。
> **汇报模板（照抄即可）**：`结果：001-003 三轮完成；状态：DONE（全员退场+产出就位）；异常：无（或列出）`。
> **"输出最终回复=回合结束"仅限非收尾点**——收尾点输出是合法结束，不受此限。其余时刻：有未决策事件就保持循环，收口后才能结束回合。**收口后禁止输出"我不下线/继续盯着"等占位话术**——那只是空话，输出即回合闭合（第八轮大鱼自证其伪）。
> **下一轮新公告牌就位后，任何会话醒来走启动铁律第 1 条（先看牌-校验-发布），不依赖你赖在回合里。**（12-15 大鱼自检：此句从段落末尾提升为独立加粗声明——"收口=彻底撒手、新牌也不用管"是误读）

> ⚠️ **扣留期间 WAIT / STANDBY 是预期**：收工轮被扣留时，角色干完待命轮后 monitor 会输出 `STANDBY N=待命轮`（待命轮带产出行时）或持续 `WAIT N=收工轮编号`（下一张牌不存在）——**这不是卡住，不要写求助**。按上方「扣留与追加机制」判定（12-15 大鱼自检拆节，消嵌套括号）：
> ① **基线（何时到点）** = 前一轮完成时刻 + 20 分钟；前一轮完成时刻 = 前一轮最后一个 `完成_{N}.md` 的 mtime（**待命轮发布/就位时间不参与计算**——第九轮大鱼自检修正，公告牌 mtime 是写牌时间不可靠）。
> ② **触发（到点后做什么）** = 到点即搬收工轮（允许 ±1 分钟缓冲，不提前不延后）；补搬后确认：角色 poll 收工轮 → 退场文件就位 → monitor DONE，三者齐全才算收工闭环。
> ③ **无新动作判定（什么不算新动作）** = 待命轮之后未出现新签字/产出（**心跳不算**——心跳是机器节拍，不是干活证据）。



> ⚠️ **若收工轮不见了但没看到 `追加任务.md`** → 写求助给老渣："收工轮不见了，是否要追加？"

## 公告牌校验（发布前必做）

发布前对**全部待发布公告牌**逐轮检查 5 项，任一不合格 → 写求助给老渣（说明哪一轮哪一项），**打回修正后再发布**，绝不带着错误发布：

| # | 校验项 | 查什么 |
|---|--------|--------|
| 1 | 编号连续 | 001→002→…→收工，无断号、无重号 |
| 2 | 收工轮格式 | 只有 模式 + 角色（状态：退场）（**任务可省略**——角色模板「收工轮」节已有完整退场步骤），无多余字段（产出/产出负责人/任务目录省略） |
| 3 | 角色枚举 | 每轮列出项目全部角色，不活跃的标 状态：待命/休眠；无遗漏 |
| 4 | 前置依赖 | 任务提到"基于/参考 XX 轮产出"时，是否显式写了依赖文件路径 |
| 5 | 状态流转 | 本轮「本轮后」与下一轮「状态」对得上（如本轮后=待命 ↔ 下轮状态=待命） |
| 6 | 产出格式 | 产出行以 `产出: 我的世界/产出/任务NNN_...` 开头；**不得含 `{}` 占位符**（如 `{角色}_报告.md`——monitor 按字面文件名查永不匹配 → 轮次卡死，第十二轮 005 实况）；必须为「具体文件名（含扩展名）」或「尾斜杠目录」二选一；多角色共产出用格式 B（目录）或多行产出（12-1 fail-loud） |

> 只校验格式与依赖，**不做内容审核**（任务写得好不好是老渣的职责）；发现问题只打回报告，**不替老渣修改公告牌**。

## 收工

收工轮确认全员退场（monitor 输出 DONE），写报告到 ../我的世界/大鱼_老渣对讲/：

| # | 文档 | 回答什么 |
|---|------|------|
| 1 | 产出总结.md | 产出了什么？逐轮完成矩阵（公告牌要求 vs 实际签字/产出/退场，异常标红）？共识？P0？ |
| 2 | 审计报告_外部观测.md | 跑完了吗？谁快谁慢？几个唤醒/掉线/异常？ |
| 3 | 项目完成.md | 通知老渣：DONE、产出就位、异常汇总 |

产出总结.md、审计报告_外部观测.md 用英文写；项目完成.md 用中文（老渣沟通习惯，9-10 明确）。最后写 项目完成.md 通知老渣。

> **产出总结必须含「逐轮完成矩阵」**：逐轮列出公告牌要求的活跃角色，对照实际签字文件（完成_NNN.md）、产出（.ready）、退场文件（已退场_NNN），缺失/错位标红——这是验证"谁按流程走、谁跳过"的硬证据（不依赖日志，只认文件系统事实）。

## 项目启动

角色窗口用 `reasonix code` 启动（常驻），角色自己 poll 公告牌。启动阶段较慢是正常的——**区分**：待命/扣留期间的 WAIT/STANDBY 是预期（见周期验证节，不要写求助）；角色 poll 正常但 monitor 长时间无任何推进（超过 20 分钟无新签字/产出）才写求助。**干预阶梯（9-10 补，第九轮大鱼自检）**：轮内心跳正常但 **5-10 分钟无新签字/产出 → 写 `_wakeup.md` 提示当前轮任务**（原因写清"等待 XX 文件/请写 XX"）；补唤醒后 ≥20 分钟仍无推进 → 写求助老渣。耐心等，别手贱，不要 spawn。
