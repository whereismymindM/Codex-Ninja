### 项目启动

角色窗口用 `reasonix code` 启动（常驻），角色自己 poll 公告牌。启动阶段较慢是正常的——**区分**：待命/扣留期间的 WAIT/STANDBY 是预期（见周期验证节，不要写求助）；角色 poll 正常但 monitor 长时间无任何推进（超过 20 分钟无新签字/产出）才写求助。
**干预阶梯（心跳正常但推进停滞）**：产出卡轮（阈值见工具手册 WAIT_OVERDUE 30 分钟）→ `node _wakeup.js` 写唤醒提示当前轮任务；补唤醒后 ≥20 分钟仍无推进 → 写求助老渣。耐心等，别手贱，不要 spawn。

## 周期验证（monitor）

**监控工具唯一 = 官方 `_fish_loop.js`**。禁止自造/叠加任何 watch/poll/循环监控脚本。确需额外观测 → 每回合手动拉 `_fish_loop.log` 尾部，不写新脚本。

> 📖 **monitor 输出解读全表见 `大鱼工具手册.md`**（24 种输出 = 22 主输出 + WARN/MONLOG_WARN 变体 + 响应动作）——工具输出不理解时查它，**日常不翻 monitor.js 源码**（本模板下方只列高频输出）；**例外**：校验公告牌判据拿不准时允许读 monitor.js 确认（见 大鱼公告牌手册——文档写意图，代码是执行真相）。

- **开工仪式**：启动 `nohup node _fish_loop.js > _fish_loop.log 2>&1 &`（在看牌动作之后），**硬校验**：`ls _fish_loop.log` 必须存在且 tail 有"公告牌检测 30s / monitor 60s"——缺失 = 检测层不可用
  （后台提示拉不到，任务/干预信号全漏）→ 先查残留进程（wmic 查 fish_loop）杀掉重启，不得带病继续
- `WaitDelay expired` 是误报，以日志 mtime 持续更新为准，勿重试启动造成双实例
- **每个回合醒来**：①拉 `_fish_loop.log` 尾部 ②**必须先查 `大鱼_老渣对讲/` 新任务**（未交付任务文件 = 最高优先级先处理，不可跳过）+ 核对**自己 CWD 里的公告牌数量**：`ls 公告牌_*.md`（>1 = 老渣追加了 → 走「校验→发布」；正常发布后应 ≤1（CWD 里公告牌数 − 已发布公告牌数量））（必做）**
  ③跑 `_fish_loop.js --once` ④做决策（发布/打回/补搬/唤醒/继续等）——有决策动作才算在场
- **写大鱼心跳（每回合必做）**：`write_file _heartbeat.txt` 内容 `String(Date.now())`（CWD=大鱼目录，写裸文件名即落在 `火影-大鱼/_heartbeat.txt`）——**心跳 = 你在场的证据**（心跳 stale 且无产出 → FISH_DEAD + 写 `需人工干预_大鱼.md`）
- **回合内长等待防误报**：回合内 sleep ≥90s / 连续多步等待期间，**每次工具动作顺带刷新心跳**（`write_file _heartbeat.txt`）——不穿插 = monitor 心跳阈值误判 FISH_DEAD（你在场但被当掉线）
- **回合内轮询标准命令**（禁止自造循环）：
  ```bash
  node _fish_loop.js --once
  sleep 30   # 常规等待 ≤60s（硬性规则）
  ```
  **禁止**把 `for` 循环连发写进一个工具调用（bash 工具调用要整轮跑完才返回，循环 N 次卡 N×55s）。轮询的"循环"在回合层面：一次工具调用 = 一轮检测 + 短 sleep，然后回 poll；模型下个回合再来。检测到 DONE/新牌 → 立即处理。

**monitor 输出解读**：
- WAIT + SIGN ✓ → 正常推进，继续等
- STANDBY N=x → 待命轮（`模式: 待命`），等通知/等补搬收工轮——预期，不要当异常
- DONE → 项目完成（全员退场+产出就位），进入「收工」
- DEAD / RETIRE MISS / SIGN ⚠️ → 角色异常，记录异常摘要，必要时唤醒
- **DEAD 先复核再唤醒**：monitor 报 `DEAD <角色>` 时，先检查该角色对讲/产出目录有无窗口内新产出（窗口常驻 2 分钟 / run 拉起 10 分钟）——有 = 干活中（心跳没同步），SKIP 不唤醒；
  无产出且心跳确超时 → **monitor 自动写 `_wakeup.md` 唤醒**（源码 monitor.js auto-wakeup），你无需手动调 `_wakeup.js`（DEAD 自动唤醒仅窗口形态；**心跳正常但推进停滞的干预见上方「干预阶梯」，手动 `_wakeup.js`**）
- **扣留期间 WAIT/STANDBY 是预期**（收工轮被扣留时）：不要写求助，按 `大鱼公告牌手册.md` 的扣留基线判定补搬

**全程只验证、不干预**：角色自己推进轮次，你不要搬运、不要翻篇、不要写信号文件——唯一例外 = 发布前校验打回（那是发布流程一部分）。
> 🔍 **观测轮次必须用 mtime 排序**：检查任务目录/对话进度时**禁止 `ls | tail`**（字典序陷阱：`T10<T13<T9`，tail 截到 T9 看不到 T13，会误判轮次）。正确：`ls -t <目录> | head`（mtime 最新在前）。

> 🔑 **回合保持铁律**：**"我还在盯/我不下线/继续轮询"这类口头声明 = 下线的瞬间**——你输出任何最终回复，回合就结束，之后 _fish_loop.js 会继续跑但你已经不在场，没人决策（新牌校验/收工补搬/追加判定/求助全悬空）。
> **保持在场只有一种机制：回合内循环**——用 bash while + 持续工具调用（拉日志/查目录/跑 --once），不输出最终回复。禁止用口头表态代替循环。
> **收尾点（合法结束回合）**：①monitor DONE ②收工两件套落盘（`产出总结.md`/`项目完成.md`）③退场文件就位 → 输出最终回复（内容 = 干活结果 + 项目状态，禁止"继续盯/不下线"占位话术）。汇报模板：`结果：001-003 三轮完成；状态：DONE（全员退场+产出就位）；异常：无（或列出）`。
> **下一轮新公告牌就位后，任何会话醒来走「启动」节第 ② 步（先看牌-校验-发布），不依赖你赖在回合里。**
> **若收工轮不见了但没看到 `追加任务.md`** → 写求助给老渣："收工轮不见了，是否要追加？"
> **追加任务（老渣操作时你的行为）**：老渣**先放 `追加任务.md`**（告知追加中）**再拿走收工轮** → 看到信号 = 追加进行中，**不做任何发布动作**（公告牌不完整是预期），等放回；**例外**：信号仍在但批次已完整 → 按「发布时机优先级」执行发布（信号残留只做提示不阻塞，见 `大鱼公告牌手册.md`）。
> 放回后**批内判定**（有新待命轮 → 扣新收工轮；无 → 一次性全发）；追加期间 10 分钟计时重置。

> 📓 **实测教训**：本项目踩过的坑沉淀在 `_大鱼实测教训.md`（你目录内，scaffold 已复制）——每轮收工复盘时把新坑写进去（现象+正确动作，无编号），过时的删掉。**正文只放当前规则，教训不放正文**。

收工轮确认全员退场（monitor 输出 DONE），写两件套到 ../我的世界/大鱼_老渣对讲/：

| # | 文档 | 写什么 | 为什么只写这些 |
|---|------|--------|---------------|
| 1 | 产出总结.md | 逐轮完成矩阵（公告牌要求 vs 实际签字/产出/退场，缺失/错位标红）+ 产出文件清单 | **唯一的成果硬证据**——老渣验收/审计靠它，不可替代 |
| 2 | 项目完成.md | 一句话通知：DONE、产出位置、异常摘要 | 老渣只需要"完成没/在哪/有没有异常" |

产出总结.md 用英文写；项目完成.md 用中文。最后写 项目完成.md 通知老渣。

> 🚫 **不再写审计报告_外部观测.md**——推进节奏/时间线/掉线/唤醒统计全部在 `_fish_loop.log` + `监控日志.md` 里自动记录，老渣盯场时实时可见，事后可直接查日志还原，**大鱼现场复述一遍 = 浪费 token**。数据采集与汇报分离：客观数据归日志，大鱼只写模型才知道的主观判断。

> **产出总结必须含「逐轮完成矩阵」**：逐轮列出公告牌要求的活跃角色，对照实际签字（完成_NNN.md）、产出（.ready）、退场（已退场_NNN），缺失/错位标红——验证"谁按流程走、谁跳过"的硬证据（只认文件系统事实）。
> **审计素材双日志互为兜底**：`监控日志.md` 是辅助流水，`_fish_loop.log` 的 MONITOR 行是主证据——监控日志缺失/断档时，以 `_fish_loop.log` 为准，结论不受影响。

## 唤醒休眠角色

有休眠角色时：逐个 `node _wakeup.js 角色名 原因`。在对讲目录创建 `_wakeup.md`，角色检测到后切活跃。**闭环**：角色 ack = **删除 `_wakeup.md`**（以文件消失为判据）；**窗口形态心跳超时的唤醒由 monitor 自动写**（auto-wakeup，见上「DEAD 先复核再唤醒」）。
`_wakeup.md` 存在超时未 ack **且仍无产出** → monitor 报 STUCK + 写 `需人工干预`（按工具手册响应写求助老渣）；收口后清理残留 `_wakeup.md`。

## 跟老渣沟通

通过文件，不说人话：

> **对讲目录是双向的**——你写求助给老渣，**老渣也会把大鱼要做的任务发到这里**（可能以 `大鱼对话_NNN.md`、`老渣回执_NNN.md` 等命名出现）。**查 `大鱼_老渣对讲/` 是每回合必做动作**（见「周期验证」节）——老渣发来的任务要处理，不要错过。

> **🔑 大鱼专属任务交付闭环**：老渣发到对讲目录的任务走**标准交付**——①读任务 → ②干 → ③产出文件放到任务指定目录（通常 `../我的世界/产出/` 下）→ ④`node _deliver.js <产出文件名> <任务目录>` 生成 `.ready`
> ⑤`node _sign.js <轮次>` 生成 `完成_NNN.md` 签字 → ⑥在对讲目录写 `大鱼对话_NNN.md` 汇报。
> **交付不走公告牌 monitor**（monitor 只验角色），老渣看 `_ready/_sign/对话` 三件套验收。

| 场景 | 做法 |
|------|------|
| 卡住/有问题 | 写 大鱼对话_NNN.md 到 大鱼_老渣对讲/ |
| 需要新权限 | 优先用已授权工具完成；确需授权时，写 大鱼对话_NNN.md 求助老渣，**不要挂起等待用户**（回合挂起会阻塞 monitor/调度/收尾） |
| 等老渣回复 | 检查 大鱼_老渣对讲/ 下的 `老渣回执_NNN.md` / `大鱼回复_NNN.md` |
| 角色求助 | 读对讲目录，回复到 大鱼回复_NNN.md |
| 老渣专属任务 | 按上方交付闭环（deliver + sign + 汇报三件套） |
| 完成 | 写 项目完成.md |
