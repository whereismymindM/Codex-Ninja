# 干活流程（怎么干活）

> 本文件是角色进入干活轮/待命/休眠/收工后的动作指引。循环骨架见 `_启动多步曲.md`；读牌解析见 `_公告牌解读.md`；工具用法见 `_工具分类.md`。

---

## ⚡ 速查：干活轮最小动作链（3 行，全流程精华）

```
读玩法文件 → 产出（write_file 写内容）→ 交付（node _deliver.js 发 .ready）→ 签字（node _sign.js N）→ 看「本轮后」→ 回 poll 循环
```

> 完整细节见下方各节。卡住时先回到这一行——80% 的活轮只需要这条链。

## 活跃（干活轮）

> 🕐 **什么时候读这一节**：poll 到新公告牌，判定你是**干活轮**（模式不是待命/收工，你的角色行是 `状态：活跃`）时。轮次驱动的循环骨架见 `_启动多步曲.md`，这里讲具体怎么干。

读公告牌的模式字段，去读对应的玩法文件：
- 双人对话 → `_双人对话模式.md`
- 主笔审核 → `_主笔审核模式.md`
- 辩论 → `_辩论模式.md`
- 单人输出 → `_单人输出模式.md`

**流程**：读玩法文件 → 产出 → deliver → sign → 看「本轮后」→ 回 poll 循环（lastN 更新为本轮编号并写盘 `临时脚本/lastN.txt`）。

### 产出路径铁律

产出路径必须与公告牌**一字不差**（少一个字 = monitor 找不到 = 白干）：
- **文档类产出**（新建报告/设计文档等）：先 `fs.writeFileSync` 写到 `../我的世界/产出/` 目录（别在角色目录下建 产出/） → 再 `node _deliver.js <文件名> <任务目录>` 发信号
- **代码类产出**（修改已有源文件）：源文件原地改完 → 直接 `node _deliver.js <文件名.js> <任务目录> <源文件路径>`，只发 .ready 信号，不搬运文件

### 审计轮默认流程（任务描述含"审计/自检/核查/复核"字样时）

1. **先写本次审计的通过标准**（如"对话纪要覆盖主题/逻辑无自相矛盾/灵魂无漂移"）——先定义"通过"再执行验证
2. **逐条核查对象证据链**（引用原文 → 判定 → 给证据）
3. **资源/复杂度核查**：方案/算法/设计类任务核查"是否可计算、复杂度是否可接受"；纯文档/事实审计可跳过并标注
4. **不可判定项明确标注**（"无法验证，缺 XX 证据"），不硬判
5. **输出审计结论**（通过 / 不通过 / 需补充证据）

> 🔑 **审核方/裁判同样适用此格式**：主笔审核的审核意见、辩论的裁判结论，都按"引用原文 → 判定 → 证据"逐条核验写——不笼统表态，逐条给依据。

## 待命（强制动作，不是话术）

> 🕐 **什么时候读这一节**：公告牌 `模式: 待命`（或你的角色行 `状态：待命`）——这轮没你的事，持续 poll 等下一张牌。循环骨架（bash while + --standby）见 `_启动多步曲.md`「待命轮询」，这里讲待命的五条铁律。

公告牌写 `模式: 待命` 的轮，你的状态为 **`状态：待命，等通知`**（待命轮的标准写法，**必须带"等通知"**——它明确告诉你后面可能还有任务，保持 poll 等下一张牌，不是这轮完事）。这轮没你的事，不用签字。不许说告退/再见/done，不许关窗口。

**待命 = 持续轮询，直到看到收工/退场信号。** 五条铁律：

1. **待命可能持续较久（10 分钟是常见扣留值，不是上限）**：待命轮之后收工轮可能被大鱼扣留（可能追加任务），通常 10 分钟后补搬，**但扣留期可能更长**（无追加信号就继续等）——期间你一直 poll 是**预期行为**，不是卡死，不许自己下线。
2. **必须真正发起 poll 循环**：bash 里跑 `node _reasonix_poll.js "{{ROLE_NAME}}" "$lastN" --standby`（**`$lastN` 必须加引号**——写成 `<N>` 会被 bash 当输入重定向），退出码 3（无事）就 `sleep 15` 后继续循环——待命就是循环本身（骨架见 `_启动多步曲.md`）。
3. **续心跳靠跑脚本**：`_reasonix_poll.js` **每次 poll 自动写心跳**（普通轮 15s / 待命 `--standby` 30s 间隔）——待命循环跑它 = 心跳持续在续，**不会断**。
   **离线期（会话间隙/进程不在）心跳必然断属正常**——monitor 会检测心跳超时写一次唤醒文件（`_wakeup.md`）；若唤醒未被确认且仍无新产出则升级为挂死（STUCK）提示人工干预，角色下次快路径 poll 才处理 WOKEN，不是异常。**唯一要防的是"该跑脚本却裸等"**（裸 `sleep 15` 循环不续心跳会真断）。
   **双杀认知**：**心跳停 ≠ 回合结束**——只要回合没结束、poll 还在跑，心跳断了也会被 monitor 唤醒；**真正该死的是"回合结束 + 心跳停"双杀**。保活的本质是保回合（下一动作=工具调用），不是保心跳。
   **写长文件边界**：`write_file` 等**单次工具调用是秒级完成，不触发心跳断**；只有**连续长干活**（bash 长脚本/多步串联，单次调用 >2 分钟）才需要按"连续干活期每 30s 写一次心跳"主动续。
4. **禁止把"继续待命轮询"当最终回复输出**：无工具调用的最终回复 = 回合结束 = 静默下线。**必须持续 poll 直到收工轮**，不许说"继续轮询"然后退出。
5. **唯一合法退出**：收工轮（`模式: 收工`，半角）——创建退场文件后才输出最终回复。
6. **poll 到非活跃轮（退出码 0 读牌确认 `模式: 待命`，或你角色行 `状态：待命/休眠`——包括任务轮里的待命角色）后推进 lastN 并写盘**：
   `lastN=$((lastN+1))` → `echo $lastN > 临时脚本/lastN.txt`（不推进 = poll 永远停在同一张非活跃牌；推进后 poll 才检测下一张=收工轮/追加轮，见 `_启动多步曲.md`「待命轮询」）

## 试用轮（等真人试用反馈）

> 🕐 **什么时候读这一节**：公告牌 `模式: 试用`——本批次交付物要过真人实际试用，你是待命方等反馈。

**试用轮流程**：
1. **待命等真人反馈**：poll 到 `模式: 试用` → 读公告牌（交付物是什么）→ **待命轮询**等真人试用（可能几十分钟到几小时——真人要实际点程序）
2. **收到反馈**：等 `任务NNN_试用/试用反馈.md` + .signal（wait_file.js 等）——反馈 = 真人试用发现的问题清单（如"收藏无标题""排除不能取消"）
3. **按反馈修**：逐个修（六态自测：正向/反向/边界/幂等/并发/恢复）→ 重新交付
4. **写试用报告 + deliver + sign → lastN+1 写盘 → 回 poll**：报告 = 反馈清单 → 修复对照（每条反馈怎么修的）；真人确认后 deliver + sign 收轮，`lastN=$((lastN+1))` → `echo $lastN > 临时脚本/lastN.txt` → 回 poll（与干活轮一致——不推进 = poll 永远重读同一张试用牌）

> 🔑 **试用轮的意义**：AI 自审审不出用户体验（排除取消/收藏错位全是真人用才暴露）——试用轮让"真人用"成为必经环节，不是靠碰运气。

## 休眠（低功耗，不是下班）

> 🕐 **什么时候读这一节**：公告牌角色行 `状态：休眠`（或本轮后字段是"休眠"）——你暂时退场，只等收工/唤醒。循环骨架见本节第 3 步（bash while，3s 节拍），这里讲休眠三步。

只有公告牌写`模式: 收工`（半角）才是真终点。休眠三步：

1. **写流水账**：fs.appendFileSync 追加到 `../我的世界/{{ROLE_NAME}}_大鱼对讲/{{ROLE_NAME}}_流水账.md`，**默认中文**（与语言规则一致），时间线格式
2. **写休眠文件**：创建 `{{ROLE_NAME}}已休眠_NNN`（不加 .md），只写一次（除非被唤醒）
3. **切高频轮询**：bash 里跑（骨架如下，每3s）：

```bash
lastN=$(cat 临时脚本/lastN.txt 2>/dev/null || echo 0)   # 初始化：读状态文件（第 1 步推导结果；0 仅兜底）
while true; do
  node _reasonix_poll.js "{{ROLE_NAME}}" "$lastN"   # 注意 "$lastN" 必须加引号——写成 <lastN>（无引号）会被 bash 当输入重定向（照抄必错）
  case $? in
    0|1|2) break ;;
    3) sleep 3 ;; # TIMEOUT 继续循环
  esac
done
# 退出码已在 case 判断时消费（bash break 会清空 $?，break 后不可再区分 0/1/2），统一重新 poll 判定：新牌就位→读牌（_公告牌解读.md）/ 被唤醒→回 poll 顶部重读 / 收工→按「收工轮」退场
# ⚠️ 读牌后若新牌**非我活跃**（我状态=休眠/待命，其他角色干活轮）→ 跳过干活+签字，**lastN+1 写盘**（`lastN=$((lastN+1))` → `echo $lastN > 临时脚本/lastN.txt`）→ 继续 poll——不推进 = 每 3 秒重复 BULLETIN 同一张牌，永远等不到收工轮
```

> 🚨 **休眠后唯一工作：反复跑 bash while 轮询，循环到底！** 不要只调一次就停——那等于假休眠。

## 收工轮

> 🕐 **什么时候读这一节**：公告牌出现 `模式: 收工`（poll 退出码 2）——无论你当前待命/休眠/活跃，全部按此退场。这是唯一的合法停止点。

### ⚡ 收工退场流程图（先看图，再读步骤）

```text
  收工触发（两条等价路径，任一到达即收工流程）：
    ├─ poll 退出码 2（RETIRED 收工检测）
    └─ poll 退出码 0 读牌发现「模式: 收工」（读到即按收工处理，无需再等退出码 2）
   ▼
  → ① 确认职责已尽：盘点本项目/前几轮公告牌分配给你的任务是否已交付
    │    ├─ 未尽 ──▶ 先补交/求助/说明，完成后再进 ②（职责未竟不得创建退场文件）
    │    └─ 已尽 ──▶ 进 ②
  → ② 检查退场文件：../我的世界/{角色}_大鱼对讲/{角色}已退场_NNN 存在？
    │    ├─ 存在 ──▶ 直接进 ④（跳过创建）
    │    └─ 不存在 ──▶ 进 ③
  → ③ 创建退场文件（无 .md 后缀，对讲目录下——monitor 只在这里验证）
  → ④ 追加流水账收工确认（回顾全程，每轮一行，≥2 行）
  → ⑤ 确认退场文件已创建 → 输出"项目完成"（回合结束）
  → ⑥ 停止循环 ──▶ ■ 终点（唯一合法停止点，退场后不再 poll）
  图例：──▶ 迁移/动作  ├─/└─ 分支  ■ 终点
```

公告牌出现 `模式: 收工`，无论你当前是待命、休眠还是活跃，即视为状态=退场（**状态=退场 是 `模式: 收工` 的推导结果，公告牌收工轮不写"退场"字样**）：

0. **收口 lastN（跨批续接）**：收工轮号 = 收工轮公告牌编号——BULLETIN 读牌发现收工轮 → `公告牌_(lastN+1)` → `lastN=$((lastN+1))`；
   **退出码 2（RETIRED）→ poll 输出 `RETIRED N=X`，X 即收工轮号（poll 检测 `公告牌_(lastN)`，未推进，不 +1）** → 统一 `echo $lastN > 临时脚本/lastN.txt`
   （运行后追加时新批首轮 = 收口值+1，与新批唤醒告知的起始编号对应）
1. **确认职责已尽（收工第一步，不可跳过）**：盘点本项目/前几轮公告牌分配给你的任务是否已交付——未尽则先补交/求助/说明，完成后再继续（**职责未竟不得创建退场文件**——这是收工前的最后一道责任闸）
2. 检查对讲目录下的退场文件：`../我的世界/{{ROLE_NAME}}_大鱼对讲/{{ROLE_NAME}}已退场_NNN` 是否存在（**不加 .md 后缀**）
3. 不存在就立刻创建——**必须创建在对讲目录下**，不要写到 我的世界/ 根或其他位置；monitor 只在这里验证退场
4. **追加流水账收工确认——必须回顾全程**：写入**独立文件** `../我的世界/{{ROLE_NAME}}_大鱼对讲/{{ROLE_NAME}}_流水账.md`（不是操作日志！）——从你参与的第一轮起，每轮一行（哪轮 / 干了什么 / 等了谁 / 结果），最后写退场动作。**禁止只写"退场"一行**（monitor 会校验行数，<2 行标 ⚠️）。
  **例外**：全程没参与的角色写一行"全程待命"即可——monitor 对"全程待命"单行豁免，不会标 ⚠️。
4a. **【仅项目终局轮 / 角色中途退场时】写角色记忆**：`../我的世界/{{ROLE_NAME}}_大鱼对讲/{{ROLE_NAME}}_角色记忆.md`——给**下一任的自己**的传承（本项目我干了什么 / 关键决策 / 踩过的坑 / 留下的判断与未尽事项）。
**与流水账区别**：流水账=记录（审计/老渣看），角色记忆=传承（下一任的自己读）。**批次收口轮不写**（项目没完，自己还在场，不需要传承给自己）——只终局轮/中途退场时写。**判据拿不准时写**（monitor 不校验角色记忆，多写无害、少写丢传承）。
5. **先确认退场文件已创建（第 3 步完成），才输出「项目完成」**——顺序不可颠倒；此时输出最终回复 = 回合结束（合法收尾点）。**退场后不要再 poll 等下一张牌**（收工轮=终止轮，之后无牌；追加由老渣主动发起，不需要你退场后继续等）
6. 停止循环——这是唯一可以停下来的时刻

## 等文件（等搭档 / 等依赖）

> 🕐 **什么时候读这一节**：任务描述提到"基于/参考 XX 轮产出"（要等依赖），或双人对话/主笔审核/辩论里要等搭档的下一份文件时。这是最高频的等待场景，含基线检查/续心跳/超时兜底。
>
> 🔑 **等文件一律优先 `wait_file.js`**（多目标 AND 等齐 / `--any` 任一 / `--watch-hb` 失联检测 / 自动续心跳 / 自动 ack 全内置）——**内联轮询仅当 wait_file 不满足需求时手写**。

### ⚡ 等文件流程图（先看图，再读规则）

```text
  任务提到"基于/参考 XX 产出"？
    ├─ 否 ──▶ 直接干活
    └─ 是 ──▶ 基线检查三项（任一为否 → 按右侧处理，不进入等文件）：
               │  ① 目标不存在？  否（已存在）──▶ 直接读文件干活
               │  ② 搭档心跳活？  否（心跳死）──▶ 写求助给大鱼
               │  ③ 真该等？      否（不该等）──▶ 读公告牌核对任务路径
               └─ 三项全"是" ──▶ 等文件（wait_file.js --any/--watch-hb/--parent-check）
                    │（等文件期间每 30s 续心跳——wait_file 自动，手写循环要自己加）
                    │（⚠️ --parent-check 仅"等依赖"场景用；等搭档写文件**不要带**——任务目录由搭档创建，带了会误报 WAIT_PARENT_MISSING，见 _公告牌解读.md「任务目录不存在时怎么办」）
                    ├─ 退出码 0（就位）──▶ 读文件干活
                    ├─ 退出码 2（超时）──▶ ①复查路径 → ②查搭档心跳 → ③写求助 → ④先干不依赖部分 → 回 poll（下一轮再试）
                    ├─ 退出码 3（父目录缺）──▶ 读公告牌核对任务目录路径（可能写错）
                    └─ 退出码 4（对方失联）──▶ 写求助给大鱼
  图例：──▶ 迁移/动作  ├─/└─ 分支
```

> **🔑 等文件禁止 bash 长等（heredoc 挂死教训）**：等搭档/依赖文件**禁止**用 `bash sleep 90` 盲等、**禁止**用 `bash heredoc <<'EOF' + node` 等（heredoc 引号/EOF 出错 → bash 永久挂起，bash_timeout=0 不砍 → 心跳断、被误判 DEAD、项目卡死）。
> **违反此条 = 你自己和整个项目一起卡死，且没人能自动救你。**

**一律用 `临时脚本/wait_file.js`**（已随 scaffold 分发）：
- 标准等文件脚本（`node 临时脚本/wait_file.js <目标> [目标2] [--hb <心跳文件>] [--timeout 分钟] [--parent-check] [--any] [--watch-hb <对方心跳文件>] [--watch-hb-dead <分钟>]`）
  - 退出码：0=就位 / 2=超时 / 3=父目录缺失 / 4=对方失联 / 5=写方漏发信号（目标 .md 新产出但缺 .signal）
- 比每次复制 40+ 行内联样板少出错面，且保留内联轮询+续心跳+超时兜底全部行为；不满足需求时才手写内联轮询（CommonJS 化，禁 require + 顶层 await 混用）
- **参数何时用**：等"结束信号 **或** 下一问"（任一就位）→ 必须 `--any`（缺了 = AND 语义两个都等会卡死）；等搭档文件有失联风险 → `--watch-hb <对方对讲目录/_heartbeat.txt>`（对方心跳超阈值 exit 4）
- `wait_file.js` **已用 `__dirname` 内部锚定**（与 CWD 无关）；**自写临时脚本**统一用 `process.cwd()`

**等文件前先基线检查**（防提前裁决/空等）：
1. 目标文件当前不存在（已存在直接读）
2. 搭档是否还活着（查其心跳，死了写求助）
3. 当前是否真的该等（读公告牌确认前置轮已完成）

**等待前目录存在性检查（fail-loud）**：开始等待前先确认目标文件的**父目录**（任务目录）存在——目录不存在 = 大概率公告牌任务目录字段写错 → 立即读公告牌核对任务目录路径，**不要静默等满 20 分钟**。

**任务提到"基于/参考/根据 XX 轮产出"时**：先按上方「基线检查」①-③ → 再等待该文件就位，**不要跳过依赖直接干**——依赖未就位 = 产出必然对不上。

**等依赖/等搭档期间必须续心跳**：等待循环内每 30s 写一次 `Date.now()`（数字毫秒）到 `../我的世界/{{ROLE_NAME}}_大鱼对讲/_heartbeat.txt`（wait_file.js 自动续，手写循环要自己加）。

**超时兜底**：等待超时后 ①复查目标路径是否其实已就位（路径写错常见）②查搭档心跳（死了写求助）③仍缺失 → 写求助给大鱼说明"依赖 X 超时未就位 + 已复查路径"→ 先做不依赖它的部分，不要空等死锁。**`_deadlock.md` 仅主笔审核模式手写**（通知 monitor 尝试唤醒搭档）；双人/辩论不手写（双人写求助、辩论裁判兜底），由 monitor 内部处理。

## 心跳契约

> 🕐 **什么时候读这一节**：任何**长等待/长干活**（等文件、等搭档、bash 长脚本、多步串联，单次 >2 分钟）前——确认心跳会不会断，要不要主动续。日常秒级 write_file/短命令不需要读这节。

- **`_heartbeat.txt`** = monitor 读的存活判定文件；`_hb_state.json` = poll 脚本节流状态（monitor 不读，陈旧正常）。续心跳写 `_heartbeat.txt`
- **干活间隙也要续心跳**：**单次 write_file/短命令（秒级完成）不需要续心跳**；**bash 长脚本 / 多步串联（单次调用 >2 分钟）才需要**——内部每 30s 写一次心跳，或用 `_reasonix_poll.js --loop N`。
  （**N = 进程内循环探测次数**，不是轮号！脚本循环探测 N 次，任一次命中新牌/收工/唤醒即退出，N 次全无事 exit 3；用于减少外层 bash spawn 开销，如待命 `--loop 60` = 1 次进程内循环 60 轮）
- **轮询方式选择判据**：普通干活轮 = 每轮 poll 一次；待命/休眠轮 = bash while + `--standby`（或 `--loop 60` 合并循环）；长连续干活（>2 分钟无 poll 动作）内部每 30s 写心跳即可，不需要 --loop——--loop 只是性能优化（减少 spawn），不是保持在场必需

## 向大鱼求助

> 🕐 **什么时候读这一节**：卡住了（依赖缺失/搭档失联/路径存疑/需要决策）需要找大鱼时。求助是"每轮 poll 顺带探测回复"的短轮询，不是长阻塞等待。

卡住了？写 `../我的世界/{{ROLE_NAME}}_大鱼对讲/大鱼对话_NNN.md` 求助。然后**每轮 poll 时顺带探测一次回复**（不要长阻塞等待——等回复用短轮询探测即可）：

**探测动作** = 每次 poll 循环里检查 `大鱼回复_NNN.md` 是否存在（**NNN = 当前轮号，3 位补零**；普通轮每轮查一次 / 待命轮 --standby 每 15s 查一次 / 长干活期每 30s 查一次）。

```bash
# 单次探测：检查一次立即交还控制，由外层 poll 循环反复发起（不要在此阻塞等待）
if [ -f "../我的世界/{{ROLE_NAME}}_大鱼对讲/大鱼回复_NNN.md" ]; then
  echo "大鱼回复已就位"
fi
sleep 2   # 未就位时的短暂间隔，然后回到外层 poll 循环
```

**升级路径**：求助后 3 轮 poll 无回复 → **重写求助**（重复内容 + 标注"求助未回复"）；仍无回复且影响推进 → 继续干活不阻塞（先做能做的），记录到流水账——**不要去改公告牌**（公告牌由大鱼维护，角色无写权限）。等到回复后把回复文件重命名为 `大鱼回复_NNN_已阅.md`。

## 路径与临时文件

> 🕐 **什么时候读这一节**：写任何文件前（防路径嵌套/防 CWD 漂移），或要写临时脚本/中间文件时。`../我的世界` 不存在 = CWD 错了，先 pwd 确认。

- **路径锚定铁律（防嵌套目录）**：写任何文件前确认目标路径的父目录层级正确——`我的世界/` 只能是项目根下的那一个。若 `../我的世界` 不存在（CWD 漂移）→ **报错停止，禁止 mkdirSync 静默创建嵌套**（如 我的世界/我的世界/）。用 `pwd` 确认 CWD。deliver/sign 内联已内置校验（WORLDDIR_MISSING）
- **临时脚本/中间文件写自己的 `临时脚本/` 目录**（角色目录下，scaffold 已建、沙箱 allow_write 已配）：**禁止**往 `我的世界/` 根/产出区/任务区写临时脚本（污染共享区，monitor 会误扫）；**禁止**用 bash heredoc/`cat >` 绕过沙箱写别的目录（越界）。
  临时脚本用完全后自己清理（移入自己的 临时脚本/_已用；**确需删除 → 写求助，等回复再删**——删除铁律，申请对象=大鱼）
- **禁 `/tmp`**：bash 的 `/tmp` 是 MSYS 虚拟路径，Node 原生解析成 `D:\tmp` 不存在 → ENOENT。**测试/临时文件一律写自己的 `临时脚本/`**。
  **含正则/反斜杠/引号的内容用 write_file 原生直写**（heredoc 二次转义破坏正则语义）；**纯简单文本（无转义风险）才可用 heredoc**——优先 write_file，heredoc 是兜底
