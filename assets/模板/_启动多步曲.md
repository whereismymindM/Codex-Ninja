# 启动多步曲（角色醒来 → 进入主循环）

> 本文件是角色会话启动时的第一份动作指引。收到「进入角色」后，按步骤走完即进入主循环。
> 读牌解析见 `_公告牌解读.md`；干活动作见 `_干活流程.md`；工具用法见 `_工具分类.md`。

---

## 第 0 步：确认现场

1. 确认当前目录下有 `_reasonix_poll.js`（启动动作，没有先停下排查）
2. **读项目根 `../团队须知.md`（团队须知）**——了解部门协作环境：大鱼怎么运作、目录结构、沟通协议、信息边界、语言规则。read_file 可读（不受沙箱限制）。如读不到（无团队须知）跳过，不阻塞
3. **读项目灵魂（摘要优先 + 向上查找）**——代码结构地图（模块清单/上帝文件/依赖/调用链），由 SoulForge 生成；进场自动带地图，不靠自觉：
   - ① 从角色目录 CWD 开始**向上逐级查找**最近的 `.soulforge/` 目录（独立代码项目自带；协作容器如舱室根/非代码目录通常没有 → 跳过）
   - ② 找到后优先读 `project-soul.summary.md`（**精简版，几 KB**——目录树/模块清单/上帝文件/统计，几十秒读完即带地图）；缺失才读 `project-soul.md`（全文，需要细读模块时再翻）
   - ③ 找不到 `.soulforge/` = 当前不在独立代码项目内 → 跳过不阻塞（想带地图可提醒老渣/大鱼生成）
4. 开工前先读 `_外部环境BUG清单.md`——Windows/环境坑，踩一个白干一轮
5. **确认 CWD 与路径推导（禁止凭印象拼绝对路径）**：
   - ① `pwd` 确认 CWD = 角色目录（如 `...\一号舱室-软件开发部\产品经理`）
   - ② **项目根 = CWD 的上一级**（`...\一号舱室-软件开发部`）
   - ③ **我的世界 = 项目根\我的世界**（`...\一号舱室-软件开发部\我的世界`）——只此一个，`../我的世界/` 相对路径（从 CWD 上级找）与 ②③ 推导**指向同一处**
   - ④ 访问共享区**优先用相对路径 `../我的世界/`**（铁律 1）；必须用绝对路径时按 ①→③ 逐步推导（每步 pwd/上一级，**禁止一次跳到"感觉是项目根"的目录**——典型错误：把部门父目录（大鱼号）当项目根，拼出 `大鱼号\我的世界` 不存在的路径）
   - ⑤ 现场确认：`ls ../我的世界/` 应能看到 公告牌/产出/任务/对讲 等目录（未发布时可能只有基础目录，属正常）

## 第 1 步：启动自检（lastN 从 0 重新开始）

> **重启禁令**：会话重启后 **lastN 从 0 或自检结果重新开始**（poll 传参 = 0 起步或自检推出的 lastN，禁止回传上次会话记忆的旧 poll 值——旧上下文直接回传会跳号；传 0 会重检已签牌，靠下方自检推进）。
> poll 只检测 `公告牌_(lastN+1)` 是否存在、不感知签字状态——传 0 会重复命中已签公告牌，**防重复只能靠你自己按下方自检推进 lastN**（自检得出的 lastN 是认知，不是传参；传参固定 0 或直接传自检推出的 lastN 都安全，前提是手动推进到位）。

**文件指涉定义**：
- **签字文件** = `../我的世界/{{ROLE_NAME}}_大鱼对讲/完成_NNN.md`（当前轮签字）
- **对话文件** = 任务目录（`../我的世界/任务NNN_XXX/`）下本轮产生的对话/交换文件（问/答.md、辩论文件等）

| 自检结果 | 认知 |
|---|---|
| 签字文件存在 | 这轮已完成，lastN = 该轮编号（认知），继续往下 |
| 签字不存在但任务目录有对话文件 | 中断重启，从最后对话文件继续 |
| 签字不存在且无对话文件 | 从头干 |

> 绝不覆盖已有文件。

## 第 2 步：进入主循环（bash while 骨架）

```bash
lastN=0                     # 初始化：0 = 会话重启从头；同会话转来/重启续接改为自检结果或当前已处理轮号（照抄必改）
while true; do
  node _reasonix_poll.js "{{ROLE_NAME}}" "$lastN"   # $lastN = 上一张已处理公告牌编号（初始 0；干完一轮后更新为该轮编号）
  case $? in
    0)  # BULLETIN N=X — 新公告牌就位 → 读牌干活（见 _公告牌解读.md）
        # 示意：读牌 → 判定轮类型 → 干活/待命/休眠/收工（按 _公告牌解读.md 执行）
        ;;  # 分支结束符必须放在命令之后（放在 # 注释里会被吞 → case 语法错误）
    1)  # WOKEN — 被大鱼唤醒 → 处理唤醒（见下方「退出码 1」）
        : ;;  # 占位空命令：按「退出码 1」处理
    2)  # RETIRED — 收工轮 → 退场（见 _干活流程.md「收工轮」）。收工前确认职责已尽（未尽则先补交/求助/说明，再退场）
        : ;;  # 占位空命令：按「退出码 2」退场
    3)  # TIMEOUT — 无事发生 → sleep 3 后再 poll
        sleep 3 ;;
  esac
done
```

> **lastN 传参**：`<lastN>` = **上一张已处理公告牌编号**（如刚签完 002，传 2；初始 0）。**不是"下一张"！** poll 内部自动检测 `公告牌_(lastN+1)`——传错会跳号（SIGN N=2 后传 3 → poll 检测 004 → 跳过 003）。
>
> **轮次推进自己完成**：不要等外部触发。非活跃轮（状态：待命/休眠）**跳过的是「干活+签字」，不是轮次推进**——跳过任务但继续 poll 下一张公告牌，直到收工轮创建退场文件。

### ⚡ 退出码流转图（先看图，再查表）

```text
⭐ 主循环入口（bash while 骨架）
   │
   ┌─▶ poll（node _reasonix_poll.js "<角色名>" <lastN>）
   │        │  ※ lastN = 上一张已处理公告牌编号（不是下一张！传错会跳号）
   │        │
   │        ├─ 退出码 0（BULLETIN 新牌）──▶ 读牌（_公告牌解读.md）→ 判轮类型 → 干活/待命/休眠/收工 → 更新 lastN ──▶ 回 poll（左上入口）
   │        ├─ 退出码 1（WOKEN 唤醒，普通轮） ──▶ 删 _wakeup.md → 查完成文件推进 lastN → 回 poll（间隔见速查表）
   │        ├─ 退出码 2（RETIRED 收工）──▶ 创建退场文件 → 流水账 → 输出"项目完成"──▶ ■ 终点（不再回 poll）
   │        └─ 退出码 3（TIMEOUT 无事）──▶ sleep（间隔见速查表）──▶ 回 poll
   │                                                                           ▲
   └───────────────────────────────────────────────────────────────────────────┘（所有"回 poll"都回到顶部 poll 节点，循环由 bash while 驱动）
   图例：──▶ 迁移/动作  ├─/└─ 分支  ⭐ 入口  ┌─▶ 回环  ■ 终点
```

### ⚡ 退出码速查表（普通轮 vs 待命轮）

> **两种 while 骨架的区别只在 `--standby` 参数和 sleep 间隔**——普通轮 `sleep 3`、待命轮 `--standby` + `sleep 15`。其余处理逻辑完全一样。

| 退出码 | 含义 | 普通轮（while 骨架） | 待命轮（--standby 骨架） |
|---|---|---|---|
| 0 | 新公告牌就位 BULLETIN | 读牌 → 判定轮类型 → 干活/待命/休眠/收工 | break 出循环 → 读牌 |
| 1 | 被唤醒 WOKEN | 删 `_wakeup.md` → 查完成文件推进 lastN → 继续循环（sleep 3） | 删 `_wakeup.md` → 继续循环（sleep 15）；待命轮无签字，lastN 不变 |
| 2 | 收工 RETIRED | 创建退场文件 → 流水账 → 输出最终回复（回合结束） | 同左（break 出循环 → 退场） |
| 3 | 无事 TIMEOUT | `sleep 3` 后再 poll | `sleep 15` 后再 poll |

## 退出码 0 → 读牌

见 `_公告牌解读.md` 完整流程（警告栏 → 轮类型判定 → 角色行 → 状态 → 本轮后）。

**干完这轮后 lastN 更新为这轮编号，回到主循环继续 poll。**

---

## 退出码 1 → 被唤醒

1. 若 `../我的世界/{{ROLE_NAME}}_大鱼对讲/_wakeup.md` 存在，**删除**（poll 路径=检测后删除；wait_file 等待路径=自动改名 `_wakeup_acked.md`——两条均有效，monitor 只认精确名 `_wakeup.md`，见下方注）。
   **注**：poll 检测到唤醒时已自动删除本文件（`_reasonix_poll.js` 内建），此步为兜底确认；wait_file 等待中检测到则改名为 `_wakeup_acked.md`——两种 ack 方式都能正确清除，monitor 只认精确名 `_wakeup.md`
2. 再检查当前轮是否已处理：**当前轮 = lastN+1（poll 即将检测的那张牌）**——`完成_{lastN+1}.md` 存在则 lastN 推进到 lastN+1（此处轮号 = lastN+1 的 3 位补零，如 lastN=1 → `完成_002.md`）
3. 继续循环（间隔同当轮节拍：普通轮 sleep 3 / 待命轮 sleep 15）

---

## 退出码 2 → 收工

创建退场文件 `{{ROLE_NAME}}已退场_NNN`（无 .md 后缀，创建到对讲目录）→ **追加流水账收工确认**（见 `_干活流程.md`「收工轮」完整流程）→ **此时才输出最终回复**。

> **收工判定以退出码 2 为准**；手动读公告牌发现「模式: 收工」时——poll 的收工检测与读牌结果一致，**直接按收工轮流程创建退场文件**，无需再等（读到即建）。

---

## 退出码 3 → 无事发生

`sleep 3` 后再次 poll。

---

## 追加轮次（可能遇到）

若最后一张公告牌是 `模式: 待命` 的待命轮，说明可能追加任务——你干完待命轮前面的活后，**不要下线，持续 poll 等下一张**（可能是新公告牌，也可能是收工轮；收工轮被大鱼扣留时可能等 10 分钟，属预期）。

poll 到新牌 → 按正常流程干活/退场。**10 分钟超时后的行为**：等待超过 10 分钟仍无新牌 = 正常（扣留期可能更长），**继续 poll 直到出现新牌**——不写求助、不自行退场、不结束回合；只有 poll 到收工轮（退出码 2）才退场。

## 待命轮询（bash while + --standby，15s 节拍）

> 本段与 `_干活流程.md`「待命」节配合：待命轮的具体动作（不签字/不干活/持续等）见干活流程，这里是循环骨架。

```bash
lastN=0                     # 初始化：0 = 仅用于会话重启进待命；同会话从干活轮转来时**把 0 改成当前已处理轮号**（0 会重新检测旧牌）
while true; do
  node _reasonix_poll.js "{{ROLE_NAME}}" "$lastN" --standby   # $lastN = 上一张已处理公告牌编号
  case $? in
    0) break ;;  # 新公告牌就位（读牌见 _公告牌解读.md；break 后按读牌结果：干活轮→切主循环骨架且 lastN 更新；仍待命→重进本 --standby 骨架）
    1) [ -f "../我的世界/{{ROLE_NAME}}_大鱼对讲/_wakeup.md" ] && rm "../我的世界/{{ROLE_NAME}}_大鱼对讲/_wakeup.md"; sleep 15 ;;  # 被唤醒：立即删唤醒文件（monitor 尽早看到 ack）再保持待命节拍，下一轮 poll 自然检查公告牌/收工轮；待命轮无签字，跳过完成文件检查，lastN 不变
    2) break ;;  # 收工
    3) sleep 15 ;; # TIMEOUT 继续循环
  esac
done
```

> **待命 = 持续轮询，直到看到收工/退场信号。** 四条铁律见 `_干活流程.md`「待命」——待命可能持续较久（10 分钟是常见扣留值，不是上限）；必须真正发起 poll 循环（跑脚本即自动续心跳，裸 sleep 会断心跳）；禁止把"继续待命轮询"当最终回复输出；唯一合法退出 = 收工轮。
