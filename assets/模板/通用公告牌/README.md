# 通用公告牌（测试/生产通用，老渣专用）

> **用途**：老渣写公告牌时的标准化模板集。测试和生产都用——生产每轮带调查轮 = 边生产边自我迭代（角色既是工人也是评审员，产出调查反馈驱动 Skill 迭代）。
>
> **读者**：仅老渣（人）。角色只需 poll 到公告牌按内容干活，不需要知道模板本身。
> **用法**：复制对应模板文件内容 → 按测试轮次编号（001/002/…）→ 保留需要的轮 + 必加待命轮/收工轮 → 产出路径按轮次改。
> **维护**：每次测试发现新的通用问题，加进对应调查轮文件；问题措辞调整后，跨轮对比时标注"问题变更于第 X 轮"。

---

## 模板清单（每个文件一种公告牌）

| 文件 | 用途 | 必加？ |
|---|---|---|
| `待命轮.md` | 可能追加任务时用（放在收工轮前一张），全员待命等通知 | 可选（可能追加时必加） |
| `收工轮.md` | 项目结束，全员退场 | **必加**（每批最后一张） |
| `文件读取调查.md` | 调查：读团队须知没/全程文件清单/必须vs非必须 | 生产每轮带 1 个调查轮 |
| `第一原则调查.md` | 调查：第一原则三问（情景/自省/评价） | 同上 |
| `排版评价调查.md` | 调查：启动认知/章节顺序/阅读路线/评分 | 同上 |
| `工具调用调查.md` | 调查：工具调用体验/参数/报错/评分 | 同上 |

---

## 典型批次（生产每轮）

```
功能轮（如 双人对话/单人输出）→ 调查轮（选 1-2 个）→ 待命轮（若可能追加）→ 收工轮
```

示例：`001 双人对话` → `002 文件读取调查` → `003 收工轮`
（待命轮只在老渣可能追加任务时插入收工轮前）

---

## 跨轮对比

同问题措辞保持稳定，改动时在对应模板文件标注"问题变更于第 X 轮"。产出收进 `重构交接/测试结果/场景N_*/`（老渣操作）。
