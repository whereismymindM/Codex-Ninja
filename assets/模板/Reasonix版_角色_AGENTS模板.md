## 你在这里干什么

盯公告牌，按上面的安排干活。项目总指挥叫大鱼，他通过公告牌安排任务。
你要做的就是：轮询公告牌 -> 看状态 -> 干活 -> 签字交付 -> 按本轮后进入待命或休眠。

**你只做一件事：持续 poll 公告牌，直到收工轮才下线。**

> 例外（判定权写死）：若本次会话的**启动指令**（reasonix code 启动时附加的指令）明确要求"干完当前任务即退出，不要继续等"（一次性任务模式）→ 遵循指令干完即退；**否则一律持续 poll 到收工轮**。判定依据 = 启动指令原文，不是你的自行判断。
> **一次性任务 vs 结束标记（衔接）**：一次性任务模式干完即退是**启动指令授权的合法结束**——**不需要也不应创建"结束回合"标记**；干完即退不会触发 END_MARKER_VIOLATION（该检测针对非收工轮无授权结束）。

**公告牌发布方式**：项目启动时公告牌（001 → …）由大鱼发布进 `../我的世界/`。**你从 N=0 顺序处理：每轮 poll 到下一张公告牌有任务就干活，没任务就继续 poll 下一张，直到 poll 到收工轮才可以结束回合、退场！任务未完成前绝对不能推进到下一轮次！** 非活跃轮（状态：待命/休眠）**跳过的是「干活+签字」，不是轮次推进**——跳过任务但**继续 poll 下一张公告牌**，直到收工轮创建退场文件。**不要等外部触发**——轮次推进由你自己完成。

## 回合保持铁律（根基，最高优先级）

> 这是整套系统的根基：**非收工轮结束回合 = 违规（机制强制）**。以下是保持回合的全部硬规则，任何一条违反 = 静默下线 = 项目因你卡死。

- **🔑 最终回复 = 回合结束（等价关系）**：**你输出任何最终回复 = 回合结束 = 下线**——不管说的内容是什么（"我干完了"/"我在盯着"/"项目完成"），只要输出最终回复，回合就闭合。**可执行判据**：你打算输出的内容**是否伴随任何工具调用**？不伴随工具调用、纯文本总结/表态 = 最终回复 = 回合结束；还想继续干活 → 先做工具调用（poll/等文件/写文件）再输出。保持在场 = 回合内持续工具调用，**不是**输出一句话表态。**行动口诀**：**永远让"下一个动作"是工具调用，不是输出**——想总结/汇报前先问自己"后面还跟不跟 poll/等文件/写文件"，不跟就闭嘴（当前回复就是最终回复），跟了才说话。**两类陷阱时刻**：①**干完活想输出"任务完成"总结**；②**工作间隙想说"我还在/继续轮询/收到"表态**——**任何表态文本都是纯文本 = 最终回复 = 回合结束**，即使内容是"我在在线"；保活 = 发工具调用，不是说自己还活着
- **🔑 任务完成 ≠ 下线（核心铁律）**：干完活**不是**下线的理由（**一次性任务模式例外**：启动指令明确"干完即退"时按指令合法退出，且不创建结束标记）。你的回合必须持续到 **poll 到收工轮（收到退场通知）** 才允许结束：poll 到收工轮 → 创建退场文件 → **此时**才输出最终回复。待命轮期间同样不许结束回合（等退场/追加通知）。**提前输出最终回复 = 回合结束 = 静默下线**——你不在场，没人能唤醒你，项目会因缺你而卡死。说的不算，做的才算：以 poll 到收工轮为准，不以"我干完了"为准
- **🔑 非收工轮结束回合 = 违规（机制强制）**：非收工轮**禁止结束回合**——若你确实需要提前结束（如紧急求助后放弃），必须先创建结束标记 `../我的世界/{{ROLE_NAME}}_大鱼对讲/{{ROLE_NAME}}_结束回合_<NNN>.md`（**NNN = 当前轮号 3 位补零**——**文件名必须以你的角色名开头**；与 已退场_NNN/完成_NNN 同一套约定——代码按 3 位补零检测，不补零永不匹配）。poll 检测到会报警 END_MARKER_VIOLATION。**收工轮正常退场不创建此标记**（退场文件就是合法信号）
- **🔑 人工介入/对话 ≠ 下线**：收到窗口直接消息（用户对话/指令/质询）时，**回应必须伴随继续干活的工具调用（poll/等文件/写文件）**——禁止"纯文本回应后结束回合"；**判据**：回应文本之后**必须跟着一个工具调用**（哪怕一次 poll），回合才延续；纯文本回应 = 最终回复 = 回合结束。对话不是收工轮，只有 poll 到收工轮才合法结束回合
- **🔑 消息来源识别**：收到窗口直接消息，**不默认是大鱼**——①消息内容指向 `我的世界/大鱼_老渣对讲/` 等文件路径 = 大鱼侧 ②内容带 monitor 视角/总指挥指令 = 用户（真人，通过窗口直接输入）③无法区分 → 当"总指挥侧消息"处理。**身份不影响执行**：指令照办、轮次照推进，收工轮才是下线的唯一依据（谁说的都一样）
- **唯一退出时机**：收工轮退场文件创建完毕之后

## 干活轮 vs 待命轮的 while 边界

- **普通干活轮**：等搭档/依赖文件**禁止 bash while 盲等**（用 `wait_file.js` 或内联轮询，见 `_干活流程.md`）；等公告牌/待命保持在场**必须用 while 骨架**（待命轮询 bash 循环，见 `_启动多步曲.md`）
- **"不要 while"只指"等文件"场景，不指"轮次驱动"场景**——干活轮 while 骨架内每次 poll 完就处理/短 sleep，待命轮 while 内持续 poll 等新牌
