# 大鱼模板 · 形态选择入口

> 本文件是**给老渣看的**：决定本次项目用哪种形态生成大鱼，然后按指引使用对应模板。
> **不要把这个文件本身作为大鱼 AGENTS.md 使用**——它没有大鱼的身份与职责。

## 两种形态，选一使用

| | 窗口常驻 | run 拉起 |
|---|---|---|
| 文件 | `大鱼_AGENTS模板_窗口常驻.md` | `大鱼_AGENTS模板_run拉起.md` |
| 角色怎么跑 | 角色窗口常驻（`reasonix code`），自己 poll 公告牌 | 角色由大鱼按需拉起（`reasonix run --continue`），干完即退 |
| 大鱼职责 | 发布 + 校验 + 周期验证 + 收工审计 | 发布 + 校验 + **调度唤醒** + 周期验证 + 收工审计 |
| 适用场景 | **协作复杂**（辩论/主笔审核/多角色接力）、角色数 ≤6、需要稳定推进 | **简单/串行**任务（单人输出/顺序轮次）、角色数多（内存压力大）、机器资源紧张 |
| 优点 | 协作顺畅不断链、实测最稳 | 省内存（角色干完即退 0 进程）、省窗口管理 |
| 代价 | 每个角色占一个常驻窗口/进程 | 多步协作会卡（干完即退下一步没人接）、每次拉起有冷启动 |

**选择依据一句话**：**协作复杂 → 窗口常驻；角色多/资源紧 → run 拉起；不确定 → 窗口常驻（默认）。**

## 怎么生成大鱼

1. 选形态（上面表格）
2. 用对应模板生成你的大鱼目录 `AGENTS.md`（如项目根下的大鱼文件夹）：
   - scaffold 支持：`node scaffold.js <项目根> fish window`（窗口常驻）或 `node scaffold.js <项目根> fish run`（run 拉起）
   - 或手动把对应模板内容复制为你的大鱼目录 `AGENTS.md`
3. 启动方式：
   - 窗口常驻：角色窗口 `reasonix code` 常驻；大鱼窗口也常驻（`reasonix code`）
   - run 拉起：只有大鱼常驻，角色按需被拉起

> 共享底座（公告牌格式、monitor、待命轮、扣留收工轮）两形态通用，见 `assets/老渣文档/公告牌完全指南.md`。
