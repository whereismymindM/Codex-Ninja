# 大鱼公告牌手册（校验 + 发布 + 扣留/追加）

> 读者：**大鱼**（发布/校验公告牌的执行者）。本手册是大鱼 AGENTS.md 的公告牌操作细节专章——发布前必读。
> 关联：AGENTS.md 管"流程骨架"（启动/周期验证/收工/沟通），本手册管"公告牌怎么校验、怎么发布、怎么扣留/追加"。

---

## 一、公告牌校验（发布前必做）

发布前对**全部待发布公告牌**逐轮检查 6 项，任一不合格 → 写求助给老渣（说明哪一轮哪一项），**打回修正后再发布**，绝不带着错误发布：

| # | 校验项 | 查什么 | 不合格后果（分级） |
|---|--------|--------|-------------------|
| 1 | 编号连续 | 001→002→…→收工，无断号、无重号 | 🔴 阻断——断号/重号 = 角色永远等不到某轮，必打回 |
| 2 | 收工轮格式 | 模式 + 角色（状态：退场）+ 任务（**可选**，"可省略"=允许有也允许无，带任务字段照常判合格）；其余字段（产出/产出负责人/任务目录）省略 | 🔴 阻断——收工轮多写产出字段 = monitor 找不存在的 .ready 卡死；必打回 |
| 3 | 角色枚举 | 每轮列出项目全部角色，不活跃的标 状态：待命/休眠；无遗漏。**集合确认**：项目角色集合以批次内公告牌互相印证为准；集合不一致时先写求助问老渣确认集合，不直接打回具体某轮 | 🔴 阻断——漏角色行 = 该角色收不到信号可能误退场；集合不一致先问老渣（不直接打回） |
| 4 | 前置依赖 | 任务提到"基于/参考 XX 轮产出"时，是否显式写了依赖文件路径（完整路径如 `产出/任务001_需求/需求文档.md`，不是仅"基于 001 产出"） | 🟡 容忍——缺路径角色可能不等依赖直接干 → 产出对不上；打回要求补路径 |
| 5 | 状态流转 | 本轮「本轮后」与下一轮「状态」对得上（如本轮后=待命 ↔ 下轮状态=待命） | 🟡 容忍——对不上角色行为随机；打回要求对齐 |
| 6 | 产出格式 | 产出行以 `产出: 我的世界/产出/任务NNN_...` 开头；**不得含 `{}` 占位符**（如 `{角色}_报告.md`——monitor 按字面文件名查永不匹配 → 轮次卡死）；必须为「具体文件名（含扩展名）」或「尾斜杠目录」二选一；多角色共产出用格式 B（目录）或多行产出。**格式 A/B 判定**：带文件名 = monitor 逐文件查 `.ready`；仅目录（尾斜杠）= 扫目录内任一 `.ready` 即过；`产出负责人: 各自` = 需 `.ready` ≥ 活跃角色数（严格语义） | 🔴 阻断——路径错/占位符 = monitor 永不匹配轮次卡死；必打回 |

> **分级语义**：🔴 阻断 = 发布后必然卡死/误行为，必打回修正再发；🟡 容忍 = 可发布但影响推进质量，打回要求补齐。**判据以 `../monitor.js` 实际解析逻辑为最终依据**——拿不准某项会怎么被解析时，读它确认（文档写的是意图，代码是执行真相）。

> 只校验格式与依赖，**不做内容审核**（任务写得好不好是老渣的职责）；发现问题只打回报告，**不替老渣修改公告牌**。

> **🔑 打回后的重新发布流程**：打回后**公告牌文件还在你的目录**（未发布），老渣修正时会**改写文件内容**（同文件名）——你**不靠"文件出现"检测新版本**（文件一直在），而是靠**文件 mtime 变化**（`_fish_loop.js` 的 NEW_BOARD 提示基于 mtime 检测，见其日志）。**发现公告牌文件 mtime 更新（NEW_BOARD 提示）→ 立即重新校验 6 项 → 通过则发布**；若你不确定是否已修正，`ls -l 公告牌_*.md` 看 mtime 并与打回时间对比，或直接重新校验一遍（校验是幂等的，不会重复发布）。

### 标准公告牌样例（校验时的"实物参照"）

**任务轮（单人输出）**：
```
# 公告牌 第001轮
- 产出类型: 文档
- 模式: 单人输出
- 角色A（角色：单人，状态：活跃，本轮后：待命）
- 角色B（状态：待命）
- 任务: 角色A 写需求文档
- 产出负责人: 角色A
- 产出: 我的世界/产出/任务001_需求/需求文档.md
- 任务目录: 我的世界/任务001_需求/
```

**待命轮**：
```
# 公告牌 第002轮
- 模式: 待命
- 角色A（状态：待命，等通知）
- 角色B（状态：待命，等通知）
- 任务: 全员待命。持续 poll 等下一张公告牌——可能追加任务（发新公告牌），也可能不再追加（大鱼到时补发收工轮）。
```

**收工轮**：
```
# 公告牌 第003轮
- 模式: 收工
- 角色A（状态：退场）
- 角色B（状态：退场）
- 任务: 全员退场。写流水账->创建退场文件->输出「项目完成」结束回合（窗口常驻不关，随时可继续对话）。
```

> 三样例对照校验表逐项过一遍即懂"判据长什么样"。偏离样例的写法不是必然错（如多角色共产出用格式 B），但**拿不准时对照样例 + 读 monitor.js 确认**。

## 二、发布公告牌

老渣把所有公告牌一次性放大鱼目录 → 你**先校验、再全量发布** → 角色自己从 001 推进到收工（不需要你逐轮搬运，也不需要翻篇）。你的职责：

0. **发布前校验公告牌**（见上方「公告牌校验」6 项）——发现错误写求助给老渣，**打回修正后再发布**，绝不在有错的情况下全量发出
1. **全量发布，按是否有待命轮（`模式: 待命`）决定是否扣留收工轮**（CWD = 你的大鱼目录/，发布目标 = ../我的世界/，公告牌文件一律 `公告牌_NNN.md` 数字编号）：
   - **没有 `模式: 待命` 的轮**（任务定死）→ `cp 公告牌_*.md ../我的世界/` 全部一次就位（含收工轮）
   - **有待命轮**（可能追加任务）→ 收工轮**单独扣留**（发布时排除它，如 `cp 公告牌_00[1-4].md ../我的世界/` 或用 Node 逐个复制非收工轮），其余全量搬；角色干完 → 待命轮等通知；待命轮发布进 我的世界/ **10 分钟**后（基线统一见下方「扣留与追加机制」：从前一轮完成时刻起算；判定"无新动作" = 待命轮之后未出现新签字/产出，心跳不算）→ 你再把收工轮补搬进 我的世界/（`cp 公告牌_收工轮编号.md ../我的世界/`）→ 角色 poll 到即退场
   - **启动自查**：开工时看公告牌里有没有 `模式: 待命` 的轮——**有** = 本次可能追加任务（按扣留流程），**没有** = 任务定死（全量发布）

## 三、扣留与追加机制

**扣留与追加机制**（有待命轮时，收工轮是大鱼和老渣之间的"接力棒"）：
- 初始发布：收工轮**扣在大鱼目录**（不搬），其余全量发
- 待命轮就位 **10 分钟**后（基线：从**前一轮完成时刻**起算——前一轮最后一个 `完成_{N}.md` 的 mtime（无签字时退回用 **我的世界/ 里已发布的** 待命轮公告牌 mtime（不是源目录 公告牌/ 那份——源目录 mtime=写牌时间不可靠）；这样老渣从"角色干完进入待命"起有完整 10 分钟追加窗口；判定"无新动作" = 待命轮发布后**未出现任何追加轮次的新 `完成_{N}.md` / `.ready`**——**待命轮之前轮次的正常收尾签字/交付不算新动作**（如上一轮对话完成的双签字），只有待命轮之后才出现的追加动作才算；心跳不算新动作，仅用于 monitor 存活判定）→ 大鱼补搬收工轮 → 角色退场

**追加机制（2026-08-04 用户澄清，取代旧"消失检测+对讲通知"）**：
- **触发（顺序：先信号后拿走）**：老渣想追加任务时，**先在你目录放 `追加任务.md`**（告知"我在追加，目录暂时不完整是正常的，别动作别瞎想"），**再拿走收工轮**——信号先就位，你看到信号后即使收工轮消失也不会误判
- **期间**：你看到 `追加任务.md` 存在 = 追加进行中，**不做任何发布动作**（公告牌目录不完整是预期的），等老渣放回；**例外**：若追加信号仍在但批次已完整 → 按「发布时机优先级」执行发布（信号残留只做提示不阻塞）；**monitor 周期验证、角色求助照常处理**（只不发布新公告牌）
- **放回**：老渣会把【追加轮 + 待命轮（如果后续还想追加任务） + 新收工轮(改好编号)】**一次性放回**你目录 → 你校验 6 项 → 按正常程序发布（**有待命轮 → 扣下新收工轮**；无待命轮 → 一次性全发）。**判断范围 = 本次放回的那批公告牌内部（追加轮+待命轮+新收工轮），不是全局**——全局其他轮有待命轮不影响本次：批内无待命轮（只放 追加轮+收工轮）→ 全发含收工轮；批内有待命轮 → 扣新收工轮（第六轮实测确认，2026-08-04）。**老渣放不放待命轮 = 这次追加后老渣还想不想再追加**：放 = 追加后可能还要再追加（角色干完到待命轮持续等，可再走追加流程）；不放 = 这次追加完收口（角色干完 poll 到收工轮自动退场）
- **发布时机优先级（第七轮大鱼自检，实测 1 分钟窗口）**：**批次放回完整（新轮次+新收工轮就位，且旧收工轮已从公告牌目录移除/改名）= 追加动作完成 → 此时即可校验发布**（按批内判定）；`追加任务.md` 的消失只是收口确认信号——若信号仍在但批次已完整，**按批次完整性执行发布**，并在对讲中提示老渣清理信号（不要死等信号消失卡住角色）
- **收口**：`追加任务.md` 会被老渣清理（或追加完成后移除）——以它不在为"追加结束"信号

- **可多次追加**：每次追加重复上述（先放信号 → 拿走收工轮 → 放回完整新轮次 → 你发布）

## 四、发布示例

**场景 A：无待命轮（任务定死，全量发）**
目录：`公告牌_001 ~ 005`（005 = 收工轮，无待命轮）
```
cp 公告牌_001.md ../我的世界/
cp 公告牌_002.md ../我的世界/
cp 公告牌_003.md ../我的世界/
cp 公告牌_004.md ../我的世界/
cp 公告牌_005.md ../我的世界/     ← 全部一次就位（含收工轮）
```
结果：角色干完 001-004 → poll 005 收工轮 → 退场

**场景 B：有待命轮（可能追加，扣留收工轮）**
目录：`公告牌_001 ~ 004`（004 = 待命轮）+ `公告牌_005`（收工轮）
```
cp 公告牌_001.md ../我的世界/
cp 公告牌_002.md ../我的世界/
cp 公告牌_003.md ../我的世界/
cp 公告牌_004.md ../我的世界/     ← 收工轮 005 不搬（扣留）
```
结果：角色干完 001-003 → 004 待命轮等通知 → 10 分钟无追加 → `cp 公告牌_005.md ../我的世界/` 补搬 → 角色退场

**场景 C：追加轮（老渣追加任务）**
初始发布同场景 B（001-004 + 扣 005）。老渣要追加时：
1. **先放 `追加任务.md` 到你的目录**（你看到它 = 追加中，**不做发布**），**再拿走你目录里扣留的收工轮 `公告牌_005.md`**（它从未发布到 我的世界，角色还在待命轮等新牌）
2. 老渣写好追加轮放回你目录：【**追加轮 005 + 新收工轮 006**】；若还想再追加 → 放回【005 + **待命轮 006** + 新收工轮 007】
3. 你按上方「公告牌校验（发布前必做）」6 项校验放回的公告牌 → **批内判定**：
   - **什么是"批内"**：老渣这次**一次性放回你目录的那几张公告牌** = 一个批次（如【005（任务轮）+006（收工轮）】或【005（任务轮）+006（待命轮）+007（新收工轮）】）。
   - **怎么判**：看这一批里**有没有 `模式: 待命` 的待命轮**——
     - **批内无待命轮** = 老渣这次追加后**收口**（不再追加）→ **全部发布，含新收工轮**，角色干完即退场：
     - **批内有待命轮** = 老渣这次追加后**还想再追加** → **扣下新收工轮，批内其余公告牌全量发布**（角色干完追加轮 → 待命轮等通知 → 老渣可再走追加流程，重复第 1 步）：
4. 结果：批内无待命轮 → 角色干 005 → poll 006 收工轮 → 退场；批内有待命轮 → 角色干 005 → 006 待命轮等通知 → 可再追加

**通用规则（三个场景都适用）**
- **追加轮编号**：追加轮 = 待命轮+1（占用原收工轮位），新收工轮 = 追加轮+1（如待命轮=004 → 追加轮=005 → 新收工轮=006）；再追加一次则继续 +1（新待命轮=006 → 追加轮=007 → 新收工轮=008）
- **不用写 _round_NNN.signal**——角色靠轮询检测，不需要信号文件

> 🚫 **不要**逐轮搬运、**不要**等 monitor DONE 才搬下一轮——公告牌全量在 我的世界/ 里，角色自己推进。你若逐轮搬，反而会打乱角色节奏。
