# 大鱼工具手册（工具使用说明，不用翻源码）

> 读者：大鱼。用途：你手上的所有工具怎么用、输出怎么解读、该怎么响应。
> **原则**：工具输出不理解时查本手册，**不要翻 monitor.js 源码**——本手册就是源码行为的完整说明。
> 关联：`大鱼公告牌手册.md` 管公告牌校验/发布/扣留/追加；本手册管工具本身。

---

## 一、monitor.js（周期验证监控）

### 运行

```bash
node ../monitor.js    # CWD=你的大鱼目录，我的世界/ 在 monitor.js 同级
```

实际每 60s 由 `_fish_loop.js` 自动跑；你想手动看最新一轮，跑 `node _fish_loop.js --once` 即可。

### 21 种输出完整解读（对照表）

| 输出 | 含义 | 你的响应 |
|---|---|---|
| `WAIT N=x` | 第 x 轮未完成，继续等 | 正常，继续等；看括号里的原因（产出缺谁/退场缺谁） |
| `WAIT_OVERDUE N=x` | 第 x 轮产出卡轮超 30 分钟 | 核查角色产出路径/deliver 参数，必要时 `_wakeup.js` 提示 |
| `DONE N=x` | 第 x 轮完成（产出就位/全员退场） | 推进到下一轮；若 x=收工轮 → 进入收工 |
| `STANDBY N=x` | 待命轮（`模式: 待命`），等通知 | **预期，不要当异常**；按扣留基线补搬 |
| `STANDBY_OVERDUE N=x` | 待命基线过 10 分钟仍无新动作且收工轮扣留 | 检查自己是否掉线；在场则立即补搬收工轮 |
| `SIGN 角色 ✓/⚠️` | 签字存在/缺失 | ⚠️ 记录审计，不阻塞（产出兜底） |
| `ROLE 角色 DONE/PENDING` | 该角色本轮完成/未完成 | run 形态调度依据：PENDING → 唤醒 |
| `RETIRE 角色 OK/MISS` | 退场文件存在/缺失 | MISS 记录审计 |
| `FLOW 角色 OK/⚠️` | 流水账完整/过简 | ⚠️ 记录审计 |
| `DEAD 角色` | 心跳超时+无产出=掉线 | 先复核（3 分钟内新产出→SKIP），确死→`_wakeup.md` |
| `SKIP 角色` | 心跳超时但有新产出=干活中 | 不干预 |
| `WAKE 角色` | 已写 `_wakeup.md` 唤醒 | 等角色 ack（删 `_wakeup.md`） |
| `STUCK 角色` | 唤醒未确认+无产出=挂死 | 写求助老渣（需人工干预） |
| `DEADLOCK` | 角色等文件超时写死锁信号 | 读公告牌找搭档→唤醒搭档 |
| `HELP 角色` | 角色写求助 | 回复到 `大鱼回复_NNN.md` |
| `FISH_DEAD` | 你（大鱼）心跳 stale+无产出 | **你掉线了！** 恢复后按启动流程重来 |
| `INTERVENE` | monitor 写了需人工干预文件 | 老渣查看处理 |
| `OUTPUT ✓/✗` | 产出就位/缺失 | ✗ 等角色交付 |
| `RETRY` | 产出目录近期有变化，快速复检 | 正常，等复检结果 |
| `READ_ERR` | 公告牌读取失败 | 重试/等文件写完 |
| `CRASH` | monitor 自身异常 | 记录，下次运行自动恢复 |

### 特殊行为

- **产出格式 A/B**：带文件名=逐文件查 `.ready`；仅目录（尾斜杠）=目录内任一 `.ready`
- **`产出负责人: 各自`** = 需 `.ready` ≥ 活跃角色数（严格语义）
- **心跳**：窗口常驻 2 分钟判 DEAD（自动唤醒）；run 形态 10 分钟且不自动唤醒（调度归你）
- **N 持久化**：`.monitor_state.json`，崩溃重启不跳轮
- **收工轮**：同时验退场文件和休眠文件；心跳超时角色强制视为已退场（RETIRE force）

## 二、_fish_loop.js（周期循环，检测+提示）

```bash
nohup node _fish_loop.js > _fish_loop.log 2>&1 &   # 启动（30s 查牌 + 60s monitor）
node _fish_loop.js --once                          # 单轮汇总（拉日志+monitor 一条命令）
```

- 输出：`NEW_BOARD`（新公告牌）/ `MONITOR`（monitor 结果）/ `MONITOR_ERR`
- **它只检测+打印，决策归你**——校验/发布/补搬/唤醒全是你的活（你 ≠ _fish_loop.js）

## 三、_wakeup.js（唤醒休眠角色）

```bash
node _wakeup.js <角色名> [原因]
# 例：node _wakeup.js 架构师-林纳斯 003轮修复方案需修改
```

- 在 `我的世界/{角色名}_大鱼对讲/` 创建 `_wakeup.md`
- 角色检测后**删除** = ack；10 分钟未见 ack 且无产出 → 补一次；收口后清理残留

---

## 四、_deliver.js / _sign.js（老渣专属任务交付）

```bash
node _deliver.js <产出文件名> <任务目录>   # 老渣任务产出 → .ready
node _sign.js <轮次>                      # 签字 → 完成_NNN.md
```

- 只用于老渣发到对讲目录的任务交付闭环（`大鱼_老渣对讲/`），不走公告牌 monitor
- 老渣看 `_ready/_sign/对话` 三件套验收

## 五、快速排障

| 现象 | 查什么 | 怎么做 |
|---|---|---|
| monitor 一直 WAIT | 看 WAIT 括号原因 | 产出路径/deliver 参数/依赖未就位 |
| 报 DEAD 但角色在干活 | 看同轮是否有 SKIP | 3 分钟内新产出=活着，SKIP 不唤醒 |
| 收工轮不见了 | 查 `追加任务.md` 是否存在 | 追加中（等）→ 否则求助老渣 |
| 报 FISH_DEAD | 你心跳断了 | 写心跳 `_heartbeat.txt` 恢复 |
| 报 STANDBY_OVERDUE | 扣留超时 | 立即补搬收工轮 |
| 角色求助 | 读对讲目录 | 回复 `大鱼回复_NNN.md` |
