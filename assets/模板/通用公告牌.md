# 通用公告牌（测试/生产通用，老渣专用）

> **用途**：老渣写公告牌时的标准化模板集。测试和生产都用——生产每轮带调查轮 = 边生产边自我迭代（角色既是工人也是评审员，产出调查反馈驱动 Skill 迭代）。
>
> **读者**：仅老渣（人）。角色只需 poll 到公告牌按内容干活，不需要知道模板本身。
> **用法**：复制对应轮模板 → 按测试轮次编号（001/002/…）→ 保留需要的轮 + 必加待命轮/收工轮 → 产出路径按轮次改。
> **维护**：每次测试发现新的通用问题，加进对应调查轮；问题措辞调整后，跨轮对比时标注"问题变更于第 X 轮"。

---

## 待命轮（可能追加任务时，放在收工轮前一张）

```
# 公告牌 第00N轮
- 模式: 待命
- {角色A}（状态：待命）
- {角色B}（状态：待命）
- {角色C}（状态：待命）
- 任务: 全员待命。持续 poll 等下一张公告牌——可能追加任务（发新公告牌），也可能不再追加（大鱼到时补发收工轮）。**待命轮期间绝对禁止私自下线**（第一原则）。
```

- 任务: 每个角色各自写一份 `{角色名}_文件读取调查.md` 到 产出/任务00N_文件调查/，内容包括：

  ③【必须 vs 非必须】你读的文件里，哪些是**必须读的**（不读就没法干活）？哪些是**非必须的**（读了更稳，但不读也能干）？有没有你觉得该读但文档没让读的？

- 任务目录: 我的世界/任务00N_文件调查/

## 使用建议

1. **生产每轮至少带 1 个调查轮 + 收工轮**（如：功能轮 → 文件读取调查 → 待命轮 → 收工轮）——边生产边自我迭代
2. **调查轮之间可合并**（如 文件读取 + 排版评价 放一轮，各写一部分）——避免测试过长
3. **跨轮对比**：同问题措辞保持稳定，改动时标注"问题变更于第 X 轮"
4. **产出收进** `重构交接/测试结果/场景N_*/`（老渣操作）
