# 工具速查

> 按使用者分类，每个工具一行用法 + 关键注意事项。脚手架负责把工具复制到对应目录。
> 最后更新：2026-08-02

---

## 🔧 老渣用

### scaffold.js（项目初始化）

```bash
node scaffold.js <项目目录> <roles.json>          # init：新建项目
node scaffold.js <项目目录> <roles.json> add      # add：追加角色
node scaffold.js <项目目录> fish [window|run]      # fish：只重建大鱼+monitor（window=窗口常驻/run=run拉起，默认window）
```

- projectDir 不能以 `/我的世界` 结尾（有防呆检查）
- `add` 不碰大鱼和 monitor，不重建 `我的世界/`
- `fish` 不注入灵魂——大鱼是纯执行器
- 跑完删 roles.json

## 🐟 大鱼用

### monitor.js（翻篇监控）

```bash
node ../monitor.js    # 大鱼在火影-大鱼/下执行，我的世界/ 在 monitor.js 同级
```

- 每次运行检查一轮，输出 WAIT（继续等）或 DONE（翻篇）
- 活跃轮 10-15s 跑一次，待命/收工轮 60s
- N 值持久化到 `.monitor_state.json`，崩溃重启不跳轮
- v2.16：自动检测角色心跳，超时写 `_wakeup.md` 唤醒
- 收工轮同时验退场文件和休眠文件
- 产出检查：优先 `.ready` 文件，其次目录非空

### _wakeup.js（唤醒休眠角色）

```bash
node _wakeup.js <角色名> [原因]
# 示例：node _wakeup.js 架构师-林纳斯 003轮修复方案需修改
```

- 在 `我的世界/{角色名}_大鱼对讲/` 下创建 `_wakeup.md`
- 角色低功耗轮询检测到后删除唤醒文件 → 切回活跃
- 翻篇后有休眠角色时逐个调用

## 👤 角色用

> 优先用 Node 内联函数 `sign()` / `deliver()` / `lock()`（0.1秒，零Shell排队）。Shell 版以下脚本为备用。

### _poll.js（等文件出现）

```bash
node _poll.js <文件路径> <描述>                                    # 基础：等一个文件
node _poll.js --signal <文件路径> <描述>                          # 同时等文件和"对话结束.signal"
node _poll.js --ready <文件路径> <描述>                           # 等 .ready 就绪信号
node _poll.js --max-wait 600 <文件路径> <描述>                    # 自定义超时（秒），默认600
node _poll.js --low-power --wakeup <对讲目录> <文件> <描述>       # 低功耗模式，等唤醒
node _poll.js --phase 1500 <文件路径> <描述>                      # 相位偏移（ms），错开轮询
```

- 退出码：0=等到，2=超时，3=被唤醒
- 低功耗模式默认 8s 超时，正常模式 600s
- 内置目录 mtime 优化：目录无变化时跳过文件扫描
- 低功耗模式有 0-1.5s 随机抖动，多角色错开相位

### _sign.js（签字）

```bash
node _sign.js <轮次号> [消息]
# 示例：node _sign.js 3
```

- 角色名由 scaffold 生成时焊死在代码里，不会签错人
- 签字文件：`我的世界/{角色名}_大鱼对讲/完成_NNN.md`
- 已有有效签字 → 快速跳过，不重写
- 重试 1 次 + 自检验证（原子写入本身可靠，重试多了给 shell 超时送人头）

### _deliver.js（原子交付）

```bash
node _deliver.js <产出文件名> [任务目录名] [源文件路径]
# 示例：node _deliver.js 需求文档.md 任务001_需求设计 ../soulforge/需求文档.md
```

- 传第 3 参（任务目录名）→ 快速路径，跳过公告牌扫描
- 不传 → 自动扫描公告牌推导任务目录（兼容旧调用）
- 原子写入：`.tmp` → `rename` → `.ready`
- 产出路径对标公告牌，一字不差

### _lock.js（文件锁）

```bash
node _lock.js acquire [锁名] [超时秒数]     # 抢锁，默认超时180s
node _lock.js release [锁名]               # 释放
# 示例：node _lock.js acquire 任务001 120
```

- `wx` 标志原子抢锁——不存在才创建，操作系统级原子
- 锁文件：`我的世界/写锁_{锁名}.lock`，默认锁名"写锁"
- 过期锁自动回收（>10分钟未更新）
- 等待间隔 5s

## ⚡ Node 内联版（角色优先用这个）

```javascript
await sign(N)              // 签字，自动读 AGENTS.md 获取角色名
await deliver(fname, dir)  // 交付，自动写 .ready 信号
await lock("acquire")      // 抢锁
await lock("release")      // 释放
```

- 定义在角色 AGENTS.md 的「工具函数」区
- 直接 `await` 调用，0.1 秒完成
- 禁止手写 sign/deliver/lock 逻辑——用函数
