# 隐患清单

> 记录已知的协作隐患、触发条件、消除方法。新老渣和老渣的助理都应该读。
> 最后更新：2026-08-03（M14：REPL 相关已标注，心跳参数同步 reasonix-f）

---

## ✅ 已修复

### 1. 角色跳轮——公告牌全量发布导致收工误判
- **触发**：老渣一次性全发公告牌，所有牌都在我的世界
- **根因**：角色轮询用 `_maxN`，全局最大=收工轮 → 直接跳退场
- **案例**：辛顿 Q1→跳002/003→004退场，全靠手动叫醒救回
- **修复**：大鱼模板加逐轮搬运铁律，我的世界同时只有一张牌
- **落地**：`assets/模板/大鱼_AGENTS模板.md`（历史修复——逐轮搬运已被全量发布+扣留收工轮取代，见 模板/大鱼_AGENTS模板_窗口常驻.md）

### 2. 搭档变更后旧文件 mtime 不更新，轮询卡死
- **触发**：公告牌重写搭档变更（乔布斯→辛顿），旧文件不重写
- **根因**：答方等 mtime 变化，文件未重写→永远等不到
- **案例**：深泽直人等了几百秒，经提醒直接读文件才开干
- **修复**：双人对话、主笔审核模式加「轮询前先 existsSync」
- **落地**：`assets/玩法模式/_双人对话模式.md`、`assets/玩法模式/_主笔审核模式.md`

### 3. poll 唤醒 `_max+1` 迟到一轮就死等
（⚠️ 机制已改版：当前为 `<当前N>` + N+1 推进，`_max`/`_startMax` 仅 Codex 版历史）
- **触发**：角色重启后错过一轮，等 `_max+1` 永远等不到
- **修复**：改为 `_max > _startMax`（进入 poll 时记初始值）（历史修复，见上）
- **落地**：4 个模式模板

### 4. poll 无容错——一行抛异常角色静默挂
- **触发**：轮询循环中任意一行抛异常（如 `readdirSync` 目录被删）
- **修复**：循环体包 `try-catch`
- **落地**：4 个模式模板

### 5. 角色掉线无人知——自以为在轮询实则已断
- **触发**：角色进程崩溃/回合中断（Reasonix 版无 REPL——Codex 版 REPL 超时场景已废弃），角色窗口还在但轮询已停
- **修复**：`_reasonix_poll.js` 按 `_hb_state.json` 批量写心跳（待命 --standby 30s / 休眠 15s）
- **落地**：`_reasonix_poll.js` + 4 个模式模板

### 6. monitor 只报告不行动——看到掉线不会自动捞
- **触发**：monitor 检测到角色心跳超时但不作为
- **修复**：心跳超 2 分钟 → 自动写 `_wakeup.md` 唤醒角色
- **落地**：`monitor.js`

### 7. scaffold 把角色生成到我的世界里面
- **触发**：老渣传 `我的世界/` 作为 projectDir
- **修复**：scaffold.js 加防呆，拒绝以 `/我的世界` 结尾的路径
- **落地**：`scaffold.js`

### 8. 内联 lock() 无原子保护——角色崩溃导致全员死锁
- **触发**：角色抢锁后崩溃，锁文件残留 → 全员卡死
- **根因**：早期 `lock()` 先 `existsSync` 再 `writeFileSync`，两步不原子（Codex REPL 版，已废弃）
- **修复**：升级为 wx 原子抢锁 + 过期回收(10min) + 超时(180s) + 持有进程存活校验（2026-08-03）
- **落地**：`Reasonix版_角色_AGENTS模板.md` + `_lock.js`（需 re-scaffold 角色才生效）

### 9. monitor 正则扫全文——任务描述中的相似文本被误匹配
- **触发**：公告牌任务描述中碰巧出现类似 `状态：活跃` 的文本
- **修复**：角色解析正则限定到 `headerPart`（`任务:` 行之前）
- **落地**：`monitor.js`

### 10. monitor 心跳唤醒与角色恢复的竞争条件
- **触发**：monitor 判定掉线准备唤醒时，角色刚好恢复
- **修复**：写 `_wakeup.md` 前重读心跳，<30s 内恢复则跳过
- **落地**：`monitor.js`

### 11. 搭档掉线导致对话/辩论/审核永久死锁
- **触发**：辩论/双人对话/主笔审核中搭档掉线，`while(true)` 无超时
- **修复**：内联轮询加 20 分钟超时 + `_deadlock.md`（辩论除外——裁判兜底不写）+ monitor 死锁唤醒搭档
- **落地**：`assets/玩法模式/_辩论模式.md` `assets/玩法模式/_双人对话模式.md` `assets/玩法模式/_主笔审核模式.md` `monitor.js`

### 12. 幽灵公告牌干扰 `_max`
（⚠️ 机制已改版：`_max` 为 Codex 版历史，当前轮次推进为 `<当前N>` + N+1，非法文件名的过滤仍保留）
- **触发**：我的世界残留旧公告牌（如 `公告牌_旧版_005.md`）
- **修复**：`parseInt` 后加 `isNaN` 过滤，非法文件名不计入 `_max`
- **落地**：4 个模式模板 + `monitor.js`

### 13. .ready 遗漏导致 monitor 永久 WAIT
- **触发**：deliver 流程中断导致 `.ready` 未写入
- **现状**：`_deliver.js` 只负责写 `.ready` 信号（内容由角色先写入产出目录），单文件原子写入（`.tmp → rename`），无内容搬运步骤；角色交付后应自检 `.ready` 存在
- **落地**：`_deliver.js`

### 14. monitor 自身崩溃盲飞
- **触发**：`readdirSync` 权限异常等未处理错误
- **修复**：主逻辑包顶层 `try-catch`
- **落地**：`monitor.js`

### 15. 收工轮角色掉线永不完成
- **触发**：收工轮有角色掉线，退场文件永不出现
- **修复**：心跳超时角色强制退场，输出 `RETIRE XX (force)`
- **落地**：`monitor.js`

## ⚠️ 待修复

### 16. 大鱼 AGENTS 路径变量未替换
（⚠️ **已过时**：现行模板与 scaffold 已无 `{{项目根目录}}` 占位符——路径全部用 `../我的世界/` 相对路径，此隐患触发条件已不存在，可移除）
- **触发**：scaffold 异常中断，`{{项目根目录}}` 原样留在 AGENTS.md 里
- **现状**：大鱼读到 `{{项目根目录}}/我的世界/` → 死路径 → 搬运失败
- **严重度**：🟡 中

### 17. 写方漏发 .signal——搭档空等（2026-08-08 实测暴露）
- **触发**：角色写完 .md 后**忘了写同名 .signal**（"写完文件"误当成"已通知对方"）——辩论/双人/主笔的信号协议只做了一半
- **案例**：评审轮正方 T1/T2 连续两轮漏发（T1 被大鱼唤醒兜底掩盖，T2 当场卡住反方 11 分半，老渣 touch 补发救场）
- **根因**：写 .md 与写 .signal 不是原子动作，角色执行习惯"写完就等"；T1 漏发被兜底反而强化错误习惯
- **修复建议**：①玩法文件把「写 .md → 立即写 .signal」标注为**原子两步**（同一条 bash 命令）②写完四查（内容非空/信号存在/信号为时间戳/才可 wait_file）③**wait_file.js 等待前检查"我方最近产出是否缺 .signal"并告警**（机制化，靠脚本不靠自觉）④马斯克已写承诺落盘（技术VP-马斯克_流程审计说明.md）
- **严重度**：🟡 中（不卡死但有兜底时间成本；wait_file 告警可根治）

### 18. 多审核方"请审核"单信号共享缺陷（2026-08-09 舰队项目三方审核实测）
- **触发**：≥2 个审核方时，`请审核.md.signal` 是单信号——**第一个审核方 wait_file --ack 改名后，其余审核方永远等不到**（德鲁克实测：靠"重建+重发"多次才让三方收到）
- **根因**：多审核方共享一个请审核信号，无"各审核方独立确认"机制；审核结果文件带角色名是角色涌现对齐（13-5 已固化），但请审核信号未设计
- **修复建议**：①多审核方场景，请审核信号按审核方区分（或主笔等三方各自确认的机制）②或修 wait_file --ack 改为"非破坏性确认"（不改名，记录已处理集合）③德鲁克建议：等文件默认续心跳（内联轮询模板必写 30s 心跳）——修 wait_file 命名匹配让角色统一用 wait_file（内置心跳）
- **严重度**：🟡 中（三方审核才触发；已靠涌现兜底，但协议应固化）
