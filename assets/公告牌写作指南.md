# 公告牌写作指南

> 读者：老渣 | 前提：已读过公告牌模板.md | 目标：写好每一轮公告牌，让大鱼不卡、角色不乱、monitor 不误判

---

## 一、公告牌是什么

公告牌是老渣和整个项目之间的**唯一接口**。你写什么，项目就跑什么。大鱼不改一字搬运，角色逐行解读执行，monitor 全自动检查。

**一个公告牌 = 一轮任务。** 你一次性写完全部轮次，放大鱼目录下，然后大鱼逐轮搬运。

---

## 二、核心字段速查

| 字段 | 必填？ | 作用 | 写错了会怎样 |
|------|:--:|------|-------------|
| `# 公告牌 第NNN轮` | ✅ | 轮次号，monitor 用这个找文件 | 轮次跳跃 → monitor 跳过中间的公告牌 |
| `产出类型` | ✅ | `文档` 或 `代码`，影响收工报告③的侧重 | 报告归类错误，老渣看了误导 |
| `模式` | ✅ | `双人对话/主笔审核/单人输出/辩论/收工` | 角色走错玩法 |
| `角色名（状态：活跃/待命/休眠/退场, 本轮后：休眠/待命/活跃/待定）` | ✅ | 告诉每个角色这轮干什么、下一轮什么状态 | 角色行为随机 |
| `任务` | ✅ | 大白话描述谁干什么、产出放哪 | 产出对不上预期 |
| `产出负责人` | ✅ | 谁对最终产出负责（不等于谁参与） | 收工报告追责链断了 |
| `产出` | ✅ | 产出文件的完整路径（从我的世界/开始） | monitor 死等不存在的路径 → 永不翻篇 |
| `任务目录` | 收工轮不需要 | 搭档之间交换草稿的目录 | 没有的话角色不知道去哪交换文件 |

## 三、状态机——公告牌的真正核心

写公告牌最难的不是格式，是**角色状态在轮次间的流转**。先看图：

```
             ┌──────────────────────────────────────────┐
             │            收工轮：所有人 → 退场            │
             │            写 已退场_NNN → 真下线           │
             └──────────────────────────────────────────┘
                              ▲
                              │
  待命 ──▶ 活跃 ──▶ 本轮后：待命 ──▶ 待命（继续poll）
   │        │
   │        └──▶ 本轮后：休眠 ──▶ 休眠（写已休眠_NNN，低功耗poll）
   │                                      │
   │                                      │ 被唤醒
   │                                      ▼
   │                              活跃 ──▶ 本轮后：休眠 ──▶ 再写 已休眠_NNN
   │
   └── 全程待命 ──▶ 直到收工轮 → 写 已退场_NNN（终局）
```

### 三条铁律

1. **休眠只写一次休眠文件（除非被唤醒）。** 002 休眠了写 已休眠_002，003/004 延续休眠状态不再写——直到收工轮终局确认。

2. **`本轮后` 和下一轮 `状态` 必须对得上。** 反过来推：先想好每轮谁干活，再倒推每轮的 `本轮后`。

3. **待命不是休眠。** 待命 = 60s 间歇 poll，随时接棒。休眠 = 5s 低功耗 poll，只等唤醒/收工。别把该待命的标成休眠。

## 四、多轮规划——先列状态表，再写公告牌

不要直接写公告牌。先画状态矩阵：

| 角色 | 001 | 002 | 003 | 004(收工) |
|------|-----|-----|-----|-----------|
| DHH | **活跃**→待命 | **活跃**→休眠 | 休眠 | 退场 |
| 林纳斯 | 待命 | **活跃**→休眠 | 休眠 | 退场 |
| 图灵 | 待命 | 待命 | **活跃**→休眠 | 退场 |

**粗体 = 活跃**，箭头后 = `本轮后`。写好这个表再逐轮翻译成公告牌，保证不会漏状态。

### 实例：从状态表翻译成公告牌

状态表第 002 行：DHH 活跃→休眠，林纳斯 活跃→休眠，图灵 待命。翻译结果：

```
# 公告牌 第002轮
- 产出类型: 代码
- 模式: 主笔审核
- 后端开发-DHH（角色：主笔，搭档：架构师-林纳斯，状态：活跃，本轮后：休眠）
- 架构师-林纳斯（角色：审核，搭档：后端开发-DHH，状态：活跃，本轮后：休眠）
- 质量审计-图灵（状态：待命，本轮后：活跃）
- 任务: ...
- 产出负责人: 架构师-林纳斯
- 产出: 我的世界/产出/任务002_架构审核/审核报告.md
- 任务目录: 我的世界/任务002_架构审核/
```

注意图灵写了 `本轮后：活跃`——因为下一轮（003）图灵是活跃，这样角色 poll 到 003 公告牌时能无缝接棒。

## 五、`本轮后` 精确指南

| 本轮后 | 角色行为 | 什么时候用 |
|--------|---------|-----------|
| `待命` | 干完活 → 签字 → 60s 间歇 poll 等下一轮 | 下一轮这个角色还要干活 |
| `休眠` | 干完活 → 签字 → 写流水账 → 写 `已休眠_NNN` → 5s 低功耗 poll | 此轮之后不再需要这个角色（直到收工或唤醒） |
| `活跃` | 继续 poll，下轮直接接棒 | 连续两轮干活的场景（极少发生） |
| 待定 | 按待命处理（60s间歇poll）——老渣还没想好下轮安排 | 规划阶段不确定时先占位，想好了再改 |
| 不写 | 角色行为不确定！**别偷懒** | N/A |

> ⚠️ **收工轮不需要 `本轮后`**——全员退场是终局，没有"后"了。

## 六、产出路径写法（影响 monitor 翻篇）

monitor v2.14 支持两种产出格式：

### 格式 A：列出具体文件名（推荐）

```
- 产出: 我的世界/产出/任务001_compare引擎重构/server.js, search-engines.js
```

monitor 会**逐个 fs.existsSync** 检查每个文件。少一个就不给 ✓ → 不翻篇。

**优点**：精确到文件级别，不会被目录里的草稿/tmp 文件骗过去。

### 格式 B：仅目录名

```
- 产出: 我的世界/产出/任务001_compare引擎重构/
```

monitor 回退到**目录非空即通过**。适合产出文件数量不确定的场景。

### 多个产出时

```
- 产出: 我的世界/产出/任务001_后端/server.js
- 产出: 我的世界/产出/任务001_前端/index.html, style.css
```

monitor 会汇总所有产出行，全满足才翻篇。

## 七、常见错误（你一定会犯的）

### ❌ 错误 1：休眠角色每轮重复写"本轮后：休眠"

```
# 公告牌 第003轮
- 后端开发-DHH（状态：休眠，本轮后：休眠）  ← 多余！已经在休眠了
```

**正确**：休眠状态不需要 `本轮后`。角色已经在低功耗 poll 了。

```
- 后端开发-DHH（状态：休眠）
```

### ❌ 错误 2：`本轮后` 跟下一轮 `状态` 对不上

```
002 轮: DHH（状态：活跃，本轮后：待命）   ← 说干完待命
003 轮: DHH（状态：休眠）                 ← 但实际是休眠！
```

角色 002 干完进入待命模式（60s poll），然后 003 公告牌出来发现状态不对——要么切休眠（但已错过了休眠三步），要么继续待命（但公告牌说休眠）。**状态不一致是最大坑。**

### ❌ 错误 3：忘记写 `产出负责人`

monitor 不报错，但收工报告里不知道谁该为这份产出负责。

### ❌ 错误 4：收工轮写了 `产出` 和 `任务目录`

收工轮 monitor 只看退场文件，不查产出。写了反而可能误导。

**正确**：收工轮只写角色状态+任务描述。

```
# 公告牌 第004轮
- 模式: 收工
- 后端开发-DHH（状态：退场）
- 架构师-林纳斯（状态：退场）
- 质量审计-图灵（状态：退场）
- 任务: 全员退场。写流水账→创建退场文件→低功耗poll等收工。
```

### ❌ 错误 5：公告牌正文里出现角色+状态格式样例

任务描述里写 `林纳斯（状态：活跃）` 会被 monitor 正则误抓为活跃角色！monitor 的正则是：
```js
/- .+?[（(].*状态[:：]活跃/g
```
任何地方出现这个模式都会被 monitor 当活跃角色检查签字。任务描述里避免它。

## 八、写公告牌的推荐流程

1. **画状态矩阵**——谁哪轮干活、干完什么状态
2. **定产出和路径**——每轮出什么、放哪、谁负责
3. **逐轮翻译**——按模板把状态表转成公告牌
4. **自查**：
   - `本轮后` 和下一轮 `状态` 是否一致？（收工轮除外——收工轮状态为退场而非休眠）
   - 收工轮有没有多写 `产出`？
   - 任务描述里有没有 `角色名（状态：活跃）` 字样？
   - 产出路径有没有写完整（从 `我的世界/` 开始）？
5. **放大鱼目录下**，编号连续（001, 002, 003...），不乱序

---

## 九、收工轮特殊规则

收工轮是整个项目的终局信号。跟普通轮的区别：

| | 普通轮 | 收工轮 |
|---|---|---|
| 模式 | 双人对话/主笔审核/单人输出/辩论 | `收工` |
| 角色状态 | 至少一个活跃 | 全部退场 |
| `本轮后` | 必须写（可选`待定`当暂未决定） | 不写 |
| `产出` | 必须写 | 不写 |
| `任务目录` | 必须写 | 不写 |
| monitor 检查 | 产出文件 | 退场文件 |
| `产出负责人` | 必须写 | 不写 |

---

> **最后一条：公告牌就是代码。** 角色 Agent 逐行解析你的公告牌，没有"大概懂了"的空间。每个字段要么写对，要么写错——没有中间态。写完之后自己对着状态矩阵逐条核对，比事后救火划算一万倍。
