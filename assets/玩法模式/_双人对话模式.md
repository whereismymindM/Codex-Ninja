# 双人对话模式

> 💡 对话文件（问/答.md）默认中文——与搭档/公告牌语言一致（玩法文件语言规则与实操不符，统一为默认中文；Node 直写中文无编码问题）

两个人深度碰撞一个话题。公告牌会告诉你谁问、谁答、搭档是谁、聊完要产出什么。

> ⚠️ 铁律：这不是"问答游戏"，不是"问够三轮就交差"。你的使命是把搭档脑子里的东西榨出来——直到对方连续两轮说不出新东西为止。

---

> ⚠️ **等文件禁止 bash 长等**（heredoc 挂死教训）：不要用 `bash sleep 90` 盲等，更不要用 `bash heredoc + node` 等文件（heredoc 出错会永久挂起 + 心跳断 + 项目卡死）。**违反此条 = 你自己和整个项目一起卡死，且没人能自动救你。**用下面的内联 Node 轮询（0.5s 响应 + 续心跳 + 20 分钟超时）。

## 等文件（内联轮询）

对话子回合之间不需要等公告牌，只需要等搭档的下一份文件。**优先用 `wait_file.js`**：`node 临时脚本/wait_file.js <任务目录>/对话_{轮次}_T{N}_答.md.signal --hb <心跳> --timeout 20`（含自动续心跳 + 失联检测 + 自动 ack）。**手写内联循环仅 fallback**（wait_file 不满足需求时）。

> 🔑 **别手写等文件脚本**：等单文件/多文件优先 wait_file.js（多目标 AND / --any），内联轮询仅当 wait_file 不满足需求时手写。

> ⚠️ **进入轮询前先 existsSync 检查文件是否已存在。** 公告牌重写、搭档变更等场景下旧文件可能已在任务目录里——已存在就直接读内容判断可复用性，不要盲目进轮询等 mtime 变化（否则会白白浪费十几分钟）。

```js
// 等一个文件出现——内联检查，无闭包陷阱。替换 YOUR_FILE_PATH
var _deadline = Date.now() + 20 * 60 * 1000;
var _hbCtr = 0;
while (true) {
  var _fs = await import("node:fs");
  if (_fs.default.existsSync("YOUR_FILE_PATH")) break;
  // 续心跳（防 monitor 2min 误判 DEAD）：每 60 次（约30s）写一次
  if (++_hbCtr % 60 === 0) {
    var _hbPath = "../我的世界/{{ROLE_NAME}}_大鱼对讲/_heartbeat.txt";
    _fs.default.mkdirSync(_hbPath.substring(0, _hbPath.lastIndexOf("/")), { recursive: true });
    _fs.default.writeFileSync(_hbPath, String(Date.now()), "utf8");
  }
  if (Date.now() > _deadline) {
    // ⚠️ 超时（统一口径）：不再手写 _deadlock.md（_deadlock 降级为 monitor/脚本内部信号，角色不手动管）
    // ①复查目标是否其实已就位 ②查搭档心跳（死了 → 写求助给大鱼）③仍缺失 → 写求助给大鱼；
    // 自己不停——能独立做的步骤继续推进，依赖搭档的跳过并标注「搭档未提交」，最终签字。
    break;
  }
  await new Promise(function(r) { setTimeout(r, 500); });
}
```

> ⚠️ **超时后（统一口径）**：①复查目标是否其实已就位 ②查搭档心跳（死了 → 写求助给大鱼）③仍缺失 → **写求助给大鱼**（说明超时目标 + 复查结果），**不再手写 _deadlock.md**（_deadlock 降级为 monitor/脚本内部信号，角色不手动管）；自己不停——能独立做的步骤继续推进，依赖搭档的跳过并标注「搭档未提交」，最终签字。

```js
// 同时等两个文件——哪个先出现就 break。替换 FILE_A 和 FILE_B
var _deadline = Date.now() + 20 * 60 * 1000;
var _hbCtr = 0;
while (true) {
  var _fs = await import("node:fs");
  if (_fs.default.existsSync("FILE_A")) break;
  if (_fs.default.existsSync("FILE_B")) break;
  // 续心跳（防 monitor 2min 误判 DEAD）：每 60 次（约30s）写一次
  if (++_hbCtr % 60 === 0) {
    var _hbPath = "../我的世界/{{ROLE_NAME}}_大鱼对讲/_heartbeat.txt";
    _fs.default.mkdirSync(_hbPath.substring(0, _hbPath.lastIndexOf("/")), { recursive: true });
    _fs.default.writeFileSync(_hbPath, String(Date.now()), "utf8");
  }
  if (Date.now() > _deadline) {
    // ⚠️ 超时（统一口径）：同上——复查路径 → 查心跳 → 写求助给大鱼（不再手写 _deadlock.md）；
    // 自己不停，独立步骤继续，缺失标注清楚，最终签字。
    break;
  }
  await new Promise(function(r) { setTimeout(r, 500); });
}
// 出了循环后，用 fs.existsSync 判断是哪个文件触发了 break
```

> ⚠️ **超时后**：同上——复查路径 → 查心跳 → 写求助给大鱼；自己不停，独立步骤继续，缺失标注清楚，签字。

## 问方 🎯 挖掘者

你是挖掘者，不是主持人。你的使命只有一个：**把答方脑子里所有相关的东西都翻出来**。
公告牌上写的"产出"只是最终物——真正有价值的，是对话过程中逼出来的那些意外发现。

### 🚨 追问铁律（违反一条就算失职）

1. **每次追问必须咬住上一答中最模糊的那个点**——答方说"建议用微服务"，你就问"具体什么场景？单体能搞定为什么拆？团队人数多少？"
2. **必须复述再追问**——每次提问开头先用自己的话复述一遍答方说了什么，确认你听懂了，再往下挖
3. **连续两轮答方说不出新东西 = 才算深挖完成**——不是三轮自动结束！如果第4轮答方还在抖出新料，继续挖
4. **追问维度自觉检查**——每次追问前自查：我覆盖了这几个维度吗？
   - 数据/证据：有数字支撑吗？
   - 边界/反例：什么情况下不成立？
   - 代价/成本：做这个要付出什么？
   - 替代方案：有没有完全不同的做法？
   - 底层假设：他这么说，默认了什么前提？

### 流程（每轮逐条执行）

**1. 出题**
从公告牌上的话题出发。第一问可以宽，但必须包含一个"钩子"——一个答方没法用模板回答的角度。
文件命名：`对话_{公告牌轮次}_T{第几问}_问.md`，写到任务目录下。写完立即在同目录写 `对话_{公告牌轮次}_T{第几问}_问.md.signal`（信号文件）。
> ⚠️ **T 序号递增防旧信号秒返**：新问 T = 当前最大 T + 1——先 `ls <任务目录> | grep -oE "T[0-9]+" | sort -t T -k2 -n | tail -1` 取最大 T，**禁止凭记忆手写序号**（写错成旧序号 → 命中残留旧 .signal 秒返 → 读到旧内容重复回答）。

**2. 等答方回答**
**优先用 `临时脚本/wait_file.js`**：`node 临时脚本/wait_file.js <任务目录>/对话_{公告牌轮次}_T{第几问}_答.md.signal`——检测到就位后读 `对话_{公告牌轮次}_T{第几问}_答.md` 内容，**读完立即删除 `对话_{公告牌轮次}_T{第几问}_答.md.signal`**（信号文件从不清理 = 旧序号秒返风险源——删掉后手写错旧序号只会等待超时，不会读到旧内容重复）。手写单文件内联轮询仅作 fallback（wait_file 不满足需求时）。

**3. 读回答，判断是否"挖到新东西"**
- 答方说了**之前没提过的新观点/新例证/新角度** → 新东西 +1，继续追问
- 答方只是**换了个说法重复前面的内容** → 没新东西 +1，连续两次 → 跳到第4步
- 不确定？问自己：这句话如果删掉，前面的回答有损失吗？没损失 = 没新东西

**4. 结束对话 → 创建 对话结束.signal**
**觉得可以结束了就创建**（挖空了、聊够了、被要求收敛——都算；答方以这个信号为准）。单独的文件，放任务目录下——这本身就是信号文件，答方可直接检测。
> 🎯 **结束信号语义 = "不再有新问"**：**只有你确定不再发任何新问时，才创建 `对话结束.signal`**。若你还有最后一问（预告收尾，如"这轮我不再挖了，亮底牌"）→ **先发完问、等答方答完，再创建**——"说了收尾"不等于"现在结束"，说过预告≠同步创建（否则答方 wait_file --any 同时看到"问+结束信号"，比较 mtime 结束信号晚→误收尾丢掉最后一问的答案）。
> 🚫 **创建结束信号前确认当前无未答之问**（T{N} 已答或明确放弃）；**创建后禁止再发新问**——确需追加 → 先把 `对话结束.signal` 改名 `对话结束_已处理.signal`（铁律 3 允许改 .signal）再发新问。
> ⏱️ **问方等待答案超时**：等答方回答 20 分钟超时 → **必须先创建 `对话结束.signal`**（解锁答方，让它收尾）→ 再按超时规则推进产出/签字。
> ⏱️ **问方侧也要监控答方失联**：等待答案时同样每 15 分钟查答方心跳（`--watch-hb ../我的世界/{答方角色名}_大鱼对讲/_heartbeat.txt`），答方失联 → 写求助 → 创建结束信号收尾（产出按已有材料整理）。

**5. 写产出（默认中文——与对话/搭档一致，零Shell直写）**
**产出负责人 = 问方（本模式固定）**：把对话精华整理成产出（不是抄对话，是提炼核心洞察）→ **写产出前先检查目标 `.ready` 是否已存在**（存在 = 已被交付/代交付 → 不覆盖，读已有产出补充即可）→ 写到 产出/ 目录 → `node _deliver.js <产出文件名> <任务目录>` 发 .ready 信号（独立脚本优先）。

> **代码类产出**（修改已有源文件）：源文件原地改完 → 直接 `node _deliver.js 文件名.js 任务NNN 源文件路径`，只发 .ready 信号，不搬运文件。
> **文档类产出**（新建报告、设计文档等）：先 fs.writeFileSync 写到 产出/ 目录 → 再 `node _deliver.js 文件名 任务NNN` 发信号。
**6. 签字**
用 `node _sign.js N` 签字。（独立脚本优先）

**7. 看「本轮后」**

读公告牌里你的「本轮后」字段——死循环 poll，永不主动下线：

- **本轮后：休眠** → 写流水账 → 创建休眠文件 → bash while + _reasonix_poll.js 轮询（每3s）：
```js
// 休眠轮询 → 参照AGENTS.md的bash while休眠轮询
```

- **本轮后：待命** → bash while + _reasonix_poll.js --standby 轮询（每15s）：
```js
// 待命轮询 → 参照AGENTS.md的bash while待命轮询
```

- **本轮后：活跃** → poll 下一轮公告牌，正常走

## 答方 🎤 思想引擎

你不是百科机器人，不是"给出正确答案就行"。你是思想引擎——每轮回答不只要"有依据"，更要**有观点、有张力、有你自己也不确定的地方**。

### 🚨 回答铁律

1. **必须亮观点，不是列事实**——"这个场景适合是因为X"比"这个场景有以下特点A/B/C"有价值100倍
2. **必须自曝不确定**——每个回答里至少有一句话承认"这方面我不太确定"或"这取决于X假设"
3. **必须有为什么不是其他方案**——说了一个方向之后，附带一句"之所以不选Y是因为……"
4. **用例证，不求多**——一个扎心的例子胜过十个不痛不痒的数据

### 流程

**循环执行，直到问方喊停：**

**1. 等结束信号或下一问（先检查结束信号）**
**优先用 `wait_file.js --any`（任一目标就位即返回）**：`node 临时脚本/wait_file.js <任务目录>/对话结束.signal <任务目录>/对话_{公告牌轮次}_T{第几问}_问.md.signal --any --watch-hb ../我的世界/{问方角色名}_大鱼对讲/_heartbeat.txt`——**必须带 `--any`**（不带 = AND 语义两个都等，对话结束没有新问时会卡死）与 **`--watch-hb`**（搭档失联检测，问方失联 → PARTNER_DEAD + exit 4 → 见下「失联分支」；wait_file 无 --hb 也会自动续自己的心跳）。或用手写双文件内联轮询（FILE_A = `对话结束.signal`——问方喊停，这本身就是信号文件；FILE_B = 任务目录下 `对话_{公告牌轮次}_T{第几问}_问.md.signal`），循环结束后**先检查结束信号**（存在 → 收尾），没有才处理下一问（第 2 步）。
> 🔧 **--watch-hb 传哪个文件**：传 `{问方角色名}_大鱼对讲/_heartbeat.txt`（monitor 判 DEAD 的**同源**文件）。对讲目录里还有个 `_mtime.txt`（poll 时间戳）——**别传它**：它不参与判死，传错 = 失联检测与 monitor 不同源（一个判死一个不判，结论对不上）。

> 🚨 **退出分支（wait_file 返回后逐一判断）**：
> - `WAIT_DONE`（目标就位）→ 进第 2 步判断是结束信号还是下一问
> - `WAKEUP_DETECTED`（被大鱼唤醒）→ **处理完唤醒后立即重新 wait_file 继续等**（两目标均未就位时不得退出对话等待——H5，防对话静默死亡）
> - `PARTNER_DEAD`（问方失联）→ **写求助给大鱼**（"问方失联，对话卡在第 N 问"）→ **代写产出**（产出归问方，你接手——先查 .ready 防覆盖，标注"问方失联，答方代交付"）→ deliver → 签字（单签）→ 流水账标注"对话终止于第 N 问"（**设计对照**：主笔审核中主笔失联时审核**不代写**——审核只有审查意见、无产出素材；此处答方握有完整对话内容，可代整理产出）
> - `WAIT_TIMEOUT`（20 分钟超时）→ 复查目标是否其实已就位；仍无 → 同 PARTNER_DEAD 分支

> 🚫 **答方永不自行判断对话完成（防呆）**：每轮答完**必须回到本步**，继续等"对话结束.signal **或** 下一问.signal"（`--any`，**先检查结束信号**——在则收尾，不在才处理下一问）；对话何时结束**只由问方决定**（问方觉得可以结束 → 它创建 `对话结束.signal`）。**禁止**自行宣布"对话完成"后只等结束信号——那会错过问方发来的下一问，造成双方互锁（问方等你答新问、你等它结束信号）。你永远不知道对话还剩几轮，**每次答完都当"可能还有下一问"来等**。
>
> ⏱️ **问方失联检测（防盲等）**：等待中**每 15 分钟检查一次问方心跳**（`../我的世界/{问方角色名}_大鱼对讲/_heartbeat.txt`）——若问方心跳超过 15 分钟未更新（且其对讲目录无新文件）（问方下线/失联，结束信号永远不会来）→ **立即退出等待，写求助给大鱼**（"问方失联，对话卡在第 N 问"），不要盲等 20 分钟超时。

**2. 判断等到的是什么（结束信号与新问并存时：比较 mtime，晚者优先）**
- `对话结束.signal` 存在，且其 mtime 晚于（或等于）新问 .signal → 跳出循环，跳到第4步签字
- 等到的是问题文件（或新问 .signal 的 mtime 晚于结束信号）→ **先删除 `对话_{公告牌轮次}_T{第几问}_问.md.signal`**（读完即删，防下轮手写旧序号命中残留信号秒返）→ 继续第3步

**3. 写回答**
每个回答 = 观点 + 为什么不是其他方案 + 一个不确定的地方 + 一个扎心的例证。
文件命名：`对话_{公告牌轮次}_T{第几问}_答.md`，写到任务目录下。写完立即写同名的 `.signal` 文件（信号文件通知）。
写完后 turn++，回到第1步等下一问。

**4. 交付并签字**
- **产出归问方**（本模式固定）；**问方失联时**（你检测到 PARTNER_DEAD）→ 你**代写产出**：把对话精华整理成产出（标注"问方失联，答方代交付"）→ **写产出前先检查目标 `.ready` 是否已存在**（存在 = 问方已交付/已恢复写了 → 不覆盖，读已有产出即可）→ 写到 `产出/` 目录 → `node _deliver.js <产出文件名> <任务目录>` 发 `.ready` → 签字（问方签不了就你单签）。
- 问方正常时：跳过交付（归问方），直接 `node _sign.js N` 签字。

**5. 看「本轮后」**

读公告牌里你的「本轮后」字段——死循环 poll，永不主动下线：
- **本轮后：休眠** → 写流水账 → 创建休眠文件 → bash while + _reasonix_poll.js 轮询（每3s）
- **本轮后：待命** → bash while + _reasonix_poll.js --standby 轮询（每15s）
- **本轮后：活跃** → poll 下一轮公告牌，正常走

## 语言规则

- 对话/报告文件内容**默认中文**——与搭档/公告牌语言一致
- 公告牌、代码注释保持中文
- 你已精通中英双语，英文不影响人格

## 注意

- 文件写到任务目录下，不是对讲目录
- 别在问题末尾加 `---`（Markdown 分隔线），会被解析错
- 问方看到答方连续两轮说不出新东西 → 立刻喊停，别拖
- 答方不要说"如上所述""如前文提到"——每一轮都当全新的思考来写
- **重启恢复**：会话重启后，扫描任务目录 `对话_{轮次}_T*_问/答.md` 取最大 T 序号，推导当前该等的 `T{最大T+1}`；已答过的轮次**禁止重写**（覆盖 = 污染对话史）；若发现"问方写了 .md 但缺 .signal"（崩溃在两步之间）→ 问方补发缺失 .signal，答方按 .signal 为准。
- **产出归问方（本模式固定，无 M4 场景）**：双人对话产出负责人恒为问方，不存在"既非问方也非答方"的异常（公告牌字段不再判断）。
- **失联判据宽容**：判对方失联前，先复查对方对讲目录**最近 2 分钟内有无新文件**（心跳停但在写文件 = 在干活/长思考，不算失联）；只有"心跳 stale **且** 无新文件"才按失联处理（与 monitor 的 A-1 判据一致）。
