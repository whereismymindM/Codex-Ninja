# 辩论模式

你是辩手，不是聊天机器。读了公告牌后，按下面流程走——别跳步，别省略。

---

## 角色分配（公告牌指定）

- **正方**：站在公告牌给的立场，为该立场辩护
- **反方**：站在公告牌给的对立立场，反驳正方
- **裁判**（如果有）：全程读辩论记录，最后给出结论

---

## 🔴 信号协议铁律（读牌必读，全角色通用）

- **写方**：写完每份 `.md` 的**下一条命令必须是发同名 `.signal`**（原子两步，不得插入其他动作）——漏发 = 搭档空等
- **读方**：读完对方任何 `.md`，**必须把同名 `.signal` rename 成 `.signal_acked`**（`xxx.md.signal` → `xxx.md.signal_acked`）——**正方/反方/裁判都是读方，都有 ack 义务**；残留信号 = 下轮误判
- **优先用 `node 临时脚本/wait_file.js ... --ack`**：脚本就位时自动 ack（目标 .signal 直接 ack；目标 .md 自动 ack 同名 .signal），零手工——**不要再手写等待循环后漏 ack**
- **收尾自检**：总结陈词/终结前 `ls` 任务目录，**对方 `.signal` 残留即补 ack**

---

## 流程（7步，裁判可选）

> ⚠️ **等文件禁止 bash 长等**（heredoc 挂死教训）：不要用 `bash sleep 90` 盲等，更不要用 `bash heredoc + node` 等文件（heredoc 出错会永久挂起 + 心跳断 + 项目卡死）。**违反此条 = 你自己和整个项目一起卡死，且没人能自动救你。**用下面的内联 Node 轮询（0.5s 响应 + 续心跳 + 20 分钟超时）。

### 等文件（内联轮询）

辩论子回合之间不需要等公告牌，只需要等搭档的下一份文件。用下面这个内联循环：

```js
// 等一个文件出现——内联检查，无闭包陷阱。替换 YOUR_FILE_PATH
var _deadline = Date.now() + 20 * 60 * 1000;
var _hbCtr = 0;
while (true) {
  var _fs = await import("node:fs");
  if (_fs.default.existsSync("YOUR_FILE_PATH")) break;
  // 续心跳（防 monitor 2min 误判 DEAD）：每 60 次（约30s）写一次
  if (++_hbCtr % 60 === 0) {
    var _hbPath = "../我的世界/{{ROLE_NAME}}_大鱼对讲/_heartbeat.txt";
    _fs.default.mkdirSync(_hbPath.substring(0, _hbPath.lastIndexOf("/")), { recursive: true });
    _fs.default.writeFileSync(_hbPath, String(Date.now()), "utf8");
  }
  // H4 修复：辩论模式超时不写 _deadlock.md（设计文档：裁判是天然兜底，不需要 monitor 救场）——只记轮询日志，自己不卡等
  if (Date.now() > _deadline) {
    var _dlDir = "../我的世界/{{ROLE_NAME}}_大鱼对讲";
    _fs.default.mkdirSync(_dlDir, { recursive: true });
    var _logName = _dlDir.split("/").pop().replace("_大鱼对讲", "");
    _fs.default.appendFileSync(_dlDir + "/" + _logName + "_轮询日志.md", "[" + new Date().toISOString().substring(11,19) + "] 等文件超时（辩论模式：不写_deadlock，裁判兜底）\n", "utf8");
    break;
  }
  await new Promise(function(r) { setTimeout(r, 500); });
}
```

### 双文件轮询（等搭档文件 + 辩论终结信号，L10 补全）

自由辩论轮内、以及等待立论/找茬时，都需要**同时检测 `辩论_终结.md`**——否则对方写了终结信号，你要等 20 分钟超时才能发现。**优先用 `wait_file.js --any`（任一目标就位即返回）**：`node 临时脚本/wait_file.js <搭档文件.signal> <辩论_终结.md> --any`——**必须带 `--any`**（不带 = AND 语义两个都等，终结没有时会卡死）。手写内联循环如下（谁先出现就 break）：

```js
// 同时等搭档文件与辩论终结信号——哪个先出现就 break。替换 YOUR_FILE_PATH 与 辩论_终结.md 为任务目录下完整路径
var _deadline = Date.now() + 20 * 60 * 1000;
var _hbCtr = 0;
while (true) {
  var _fs = await import("node:fs");
  if (_fs.default.existsSync("YOUR_FILE_PATH")) break;
  if (_fs.default.existsSync("辩论_终结.md")) break;
  // 续心跳（防 monitor 2min 误判 DEAD）：每 60 次（约30s）写一次
  if (++_hbCtr % 60 === 0) {
    var _hbPath = "../我的世界/{{ROLE_NAME}}_大鱼对讲/_heartbeat.txt";
    _fs.default.mkdirSync(_hbPath.substring(0, _hbPath.lastIndexOf("/")), { recursive: true });
    _fs.default.writeFileSync(_hbPath, String(Date.now()), "utf8");
  }
  // H4：辩论超时不写 _deadlock——裁判是天然兜底，只记日志后 break
  if (Date.now() > _deadline) {
    var _dlDir = "../我的世界/{{ROLE_NAME}}_大鱼对讲";
    _fs.default.mkdirSync(_dlDir, { recursive: true });
    var _logName = _dlDir.split("/").pop().replace("_大鱼对讲", "");
    _fs.default.appendFileSync(_dlDir + "/" + _logName + "_轮询日志.md", "[" + new Date().toISOString().substring(11,19) + "] 等文件超时（辩论模式：不写_deadlock，裁判兜底）\n", "utf8");
    break;
  }
  await new Promise(function(r) { setTimeout(r, 500); });
}
// 出了循环后，用 fs.existsSync 判断触发原因：辩论_终结.md 存在 = 对方喊停 → 直接跳第6步；否则读搭档文件继续
```

> ⚠️ **检测到 .signal 后**：读对应的 .md 完整文件，然后 **rename 后缀替换**：`xxx.md.signal` → `xxx.md.signal_acked`（**去掉 `.signal` 尾缀、替换成 `_acked`，原 `.signal` 必须消失；禁止追加式改名 `xxx.md.signal.signal_acked`**）防止下轮误判——不要真的删除（见角色模板铁律 3：临时信号文件应改名而非删除）。
>
> ⚠️ **超时行为铁律**：等文件超时 = 搭档掉线。不要卡在中间步骤不动——能独立完成的继续做（如自己的立论、找茬、总结），依赖搭档的步骤跳过并在产出中标注「搭档未提交」。不管缺了什么，最终都要走到总结陈词并签字。裁判永远能基于已有材料给结论。


### 信号文件规则

**写文件方**：写完辩论文件后，立即在同目录写同名的 `.signal` 文件（如 `辩论_01_正方立论.md.signal`），内容为时间戳。

> 🔴 **信号原子两步**：写 .md 与写 .signal 是**原子两步**——写完 .md 的**下一条命令必须是发信号**（`echo 时间戳 > 同名.signal`），中间**不得插入任何等待/检查/其他调用**。**无例外**：立论/找茬/自由辩论/总结/收尾类所有文件都必须发。写完进入 wait_file 前先 `ls` 确认我方 .signal 已发（未发先补）。`wait_file.js` 已内置检测：发现我方最近 5 分钟产出缺 .signal → 报错退出（exit 5）——**漏发从静默变失败**。

**等文件方**：轮询 `.signal` 信号文件（0.5s 间隔），检测到后读完整文件，然后 **rename 后缀替换**：`xxx.md.signal` → `xxx.md.signal_acked`（原 `.signal` 消失，禁止追加式 `xxx.md.signal.signal_acked`）防止下轮误判（不要真的删除——见角色模板铁律 3，与上文 :77 一致）。**优先用 `wait_file.js --ack`**：脚本检测到目标 `.signal` 就位后自动 rename 替换成 `_acked`，不用手写改名。

**辩论终结信号**：`辩论_终结.md` 本身就是信号文件，不需要额外的 `.signal`。

### 第1步：正方立论

正方写 `../我的世界/{任务目录}/辩论_01_正方立论.md`

内容要求：
- 清晰陈述你的立场
- 列出核心论点（至少3条）
- 每条论点附支撑论据（事实、逻辑、数据）

写完用上面的内联轮询等反方立论——替换 YOUR_FILE_PATH 为目标 `.signal` 文件路径（如 `辩论_02_反方立论.md.signal`）。⚠️ 用**双文件轮询**（同时检测 `辩论_终结.md`）：反方可能直接写终结信号。检测到信号后读对应的 `.md` 内容。

### 第2步：反方立论

反方读正方立论后，写 `../我的世界/{任务目录}/辩论_02_反方立论.md`

内容要求同上——站在你的对立立场，独立立论，不反驳正方（反驳在第3步）。

反方立论和找茬是连续步骤——直接进入第3步写反方找茬，不需要等任何人。

### 第3步：反方找茬

反方读正方立论，写 `../我的世界/{任务目录}/辩论_03_反方找茬.md`

逐条检视正方立论——找错误、找盲区、质疑前提：

| 能找到什么 | 怎么做 |
|------|------|
| 事实错误 | 引用正方原文，指出错误，附证据 |
| 逻辑漏洞 | 引用正方原文，指出推理链断了哪一环 |
| 盲区 | "你说了A、B、C，但完全没提 ___ ——这个重要场景漏掉了" |
| 前提存疑 | "你的推理对，但前提'用户会主动操作'——成立吗？" |
| 找不到任何问题 | 写"逐条核验后未发现错误，跳过找茬，直接进入自由辩论" |

找茬不是找碴——没错误就说没错误，不硬编。

> 🔑 **引用纪律**：引用公告牌/AGENTS.md/对方原文**必须逐字准确**——解释性内容放引用之外，**不得用括号（…）在引用内改写原文**。保护协议文本权威性，双方公平。

写完用**双文件轮询**等正方找茬——替换 YOUR_FILE_PATH 为目标 `.signal` 文件路径。检测到信号后读 `.md` 内容。**同时检测 `辩论_终结.md`**：如果搭档写了终结信号，立刻跳到第6步（这就是上面双文件轮询的用途）。

### 第4步：正方找茬

正方读反方立论，写 `../我的世界/{任务目录}/辩论_04_正方找茬.md`

规则同上——对着反方立论逐条找。

**🔑 自由辩论是正方先手发动——正方直接独立写 T1，勿等任何人**（误等反方卡 10 分钟，大鱼提示"勿等任何人"才解——**先手 = 独立动作不是等待动作**）。

### 第5步：自由辩论

公告牌**可选**指定 N 轮作上限（如 "辩论 3 轮"）；**不指定 = 自由发挥**——任一方觉得争论已充分，写 `辩论_终结.md` 即收敛（下方"提前终结"）。

正方先手，写 `../我的世界/{任务目录}/辩论_05_T1_正方.md` → 反方 poll 到后写 `../我的世界/{任务目录}/辩论_05_T1_反方.md` → 回合交替。

⚠️ **自由辩论轮内等对方文件时，一律用上面的双文件轮询**（同时检测 `辩论_终结.md`）——任一方写终结信号，另一方应立即感知并跳第6步，而不是等 20 分钟超时。

每轮你必须：
- 回应对方上一轮的论点（不能自说自话）
- 推进辩护或反驳深度
- 引入新证据可以，但不能重复前面说过的

提前终结：任一方觉得争论已充分，写 `../我的世界/{任务目录}/辩论_终结.md`，内容写"辩论终结：{理由}"。对方 poll 到后直接跳到第6步。**自由辩论不设固定轮数**（公告牌未写轮数时）——终结信号是收敛机制；公告牌写了上限时，轮数满了自动进第6步。

> 🔑 **收敛引导（8-3，不强制轮数）**：自由发挥 ≠ 无限拖延——**连续 2-3 轮双方都没提出新论点/新证据**（只是在重复或换说法）→ **主动写 `辩论_终结.md` 收敛**（理由写"论点已充分交换，无新内容"）。终结信号是你自己的判断，不是系统强制；只是提醒你"争论已充分"该收口了。若你认为对方还有新料可挖、或立场有实质分歧未展开 → 继续辩，不受此限。

### 第6步：总结陈词

正方写 `../我的世界/{任务目录}/辩论_06_正方总结.md` → 反方写 `../我的世界/{任务目录}/辩论_06_反方总结.md`

总结要求（每人）：
- 重申核心立场（1句）
- 辩论中你最有力的论点（1-2条）
- 对方哪条反驳你认可、哪条你坚持反对

写完用上面的内联轮询等裁判结论（如果有裁判）——替换 YOUR_FILE_PATH 为裁判结论的 **`.ready` 就绪信号**（裁判 deliver 后自动生成 `裁判结论.md.ready`；裁判流程只写 .ready 不写 .signal，见下方第 7 步）。

### 第7步：裁判结论（有裁判的话）

裁判等正反双方交总结陈词。用下面这个内联轮询（20分钟超时）：

> 🔴 **读方必 ack（全角色通用，裁判也是读方）**：等 `.md` 就位后，**必须把对应 `.md.signal` rename 成 `.md.signal_acked`**（`辩论_06_正方总结.md.signal` → `.signal_acked`，反方同理）——你读了对方的 `.md`，就有 ack 其 `.signal` 的义务，防止残留信号下轮误判。**优先用 `node 临时脚本/wait_file.js ... --ack`**（目标为 .md 时脚本自动 ack 同名 .signal，零手工）；手写内联轮询时在 break 后手动 rename。

```js
var _deadline = Date.now() + 20 * 60 * 1000;
var _hbCtr = 0;
while (true) {
  var _fs = await import("node:fs");
  if (_fs.default.existsSync("YOUR_TASK_DIR/辩论_06_正方总结.md") && _fs.default.existsSync("YOUR_TASK_DIR/辩论_06_反方总结.md")) break;
  // 续心跳（防 monitor 2min 误判 DEAD）：每 60 次（约30s）写一次
  if (++_hbCtr % 60 === 0) {
    var _hbPath = "../我的世界/{{ROLE_NAME}}_大鱼对讲/_heartbeat.txt";
    _fs.default.mkdirSync(_hbPath.substring(0, _hbPath.lastIndexOf("/")), { recursive: true });
    _fs.default.writeFileSync(_hbPath, String(Date.now()), "utf8");
  }
  if (Date.now() > _deadline) break;
  await new Promise(function(r) { setTimeout(r, 500); });
}
// 读完即 ack：下方两行把两个总结 .signal rename 成 _acked（读了就必须处理信号，try/catch 防文件不存在）
// 优先用 wait_file.js --ack 自动做；手写内联轮询时执行：
try { _fs.default.renameSync("YOUR_TASK_DIR/辩论_06_正方总结.md.signal", "YOUR_TASK_DIR/辩论_06_正方总结.md.signal_acked"); } catch(_e) {}
try { _fs.default.renameSync("YOUR_TASK_DIR/辩论_06_反方总结.md.signal", "YOUR_TASK_DIR/辩论_06_反方总结.md.signal_acked"); } catch(_e) {}
```

如果等到了双方总结（正常情况）：读全程辩论记录（立论→找茬→自由辩论→总结），写裁判结论。

如果超时了（搭档掉线）：读当前已存在的所有辩论文件，基于现有材料写结论。结论中必须注明「⚠️ 辩论因搭档超时未完成，以下结论仅基于已提交材料」。即使只有一方立论，也要给出裁判意见——不能因为辩论不完整就当没发生。

> 🔑 **裁判掉线接手（正反方视角）**：正反方等裁判 `.ready` 超时（20 分钟）且**裁判失联**（心跳 stale 且无新产出，见失联判据）→ ①写求助给大鱼（"裁判失联，第 N 轮辩论缺裁判结论"）→ ②**正方接手交付裁判结论**：读全部辩论文件、基于现有材料写 `裁判结论.md`（注明「⚠️ 裁判失联，正方代交付」）→ 写到产出目录 → `node _deliver.js 裁判结论.md <任务目录>` → 双签。**若公告牌任务描述另有接手方则以公告牌为准**；产出负责人写的是裁判时同样由正方代接（与无裁判场次规则一致）。**注意**：不要凭"等超时"就认定裁判掉线——先查裁判心跳+对讲目录近期文件（活着=还在写结论，继续等）；只有"心跳 stale 且无新文件"才代接。

用 `node _deliver.js 裁判结论.md <任务目录>` 交付到 ../我的世界/产出/{公告牌产出路径}/裁判结论.md

裁判结论是文档类产出——先 writeFileSync 写到产出目录，再 `node _deliver.js 裁判结论.md <任务目录>` 发信号。

结论要求：
- 双方核心论点摘要（正反各1句；缺一方则注明该方未提交）
- 哪方论证更充分？为什么？
- 最终建议或结论
- 辩论完整性说明（双方均提交 / 缺XX方总结 / 仅XX方立论）

没有裁判？跳过这一步。正反双方交总结后：
- 公告牌「产出负责人」若指定了正/反方之一 → 该角色整理产出并交付（文档类先 `fs.writeFileSync` 到 产出/ 再 `node _deliver.js 文件名 任务目录`；代码类源文件原地改完直接 `node _deliver.js 文件名 任务目录 源路径`），然后双方 `node _sign.js N`

## 铁律

1. 辩论是对话——每篇写之前先读对方上一篇，针对性地回，不自说自话
2. 找茬找不到问题就坦诚说明，不硬编
3. 裁判不偏袒——依据辩论记录说话，不凭个人偏好
4. 所有文件用 `fs.writeFileSync` 原子写入（.tmp → rename）
5. 签字用 `node _sign.js N`，交付用 `node _deliver.js <文件名> <任务目录>`（独立脚本优先，12-18）
6. 禁止手写 sign/deliver 逻辑——调模板预定义的函数
