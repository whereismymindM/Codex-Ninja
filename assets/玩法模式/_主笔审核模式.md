# 主笔审核模式

一个人写，一个人审。公告牌会告诉你谁是主笔、谁是审核、搭档是谁、要产出什么。

---

## 等文件（内联轮询）

主笔等审核、审核等主笔——子回合之间不需要等公告牌，只需要等搭档的下一份文件。用下面的内联循环：

> ⚠️ **进入轮询前先 existsSync 检查文件是否已存在。** 公告牌重写、搭档变更等场景下旧文件可能已在任务目录里——已存在就直接读，不要盲目进轮询等 mtime 变化。

```js
// 等一个文件出现——内联检查，无闭包陷阱。替换 YOUR_FILE_PATH
var _deadline = Date.now() + 20 * 60 * 1000;
var _hbCtr = 0;
while (true) {
  var _fs = await import("node:fs");
  if (_fs.default.existsSync("YOUR_FILE_PATH")) break;
  // 续心跳（防 monitor 2min 误判 DEAD）：每 60 次（约30s）写一次
  if (++_hbCtr % 60 === 0) {
    var _hbPath = "../我的世界/{{ROLE_NAME}}_大鱼对讲/_heartbeat.txt";
    _fs.default.mkdirSync(_hbPath.substring(0, _hbPath.lastIndexOf("/")), { recursive: true });
    _fs.default.writeFileSync(_hbPath, String(Date.now()), "utf8");
  }
  if (Date.now() > _deadline) {
    // 写死锁信号让 monitor 尝试唤醒搭档（可能恢复），但自己不卡等——继续往下走
    var _dlDir = "../我的世界/{{ROLE_NAME}}_大鱼对讲";
    _fs.default.mkdirSync(_dlDir, { recursive: true });
    _fs.default.writeFileSync(_dlDir + "/_deadlock.md", "timeout", "utf8");
    var _logName = _dlDir.split("/").pop().replace("_大鱼对讲", "");
    _fs.default.appendFileSync(_dlDir + "/" + _logName + "_轮询日志.md", "[" + new Date().toISOString().substring(11,19) + "] 等文件超时 已写_deadlock\n", "utf8");
    break;
  }
  await new Promise(function(r) { setTimeout(r, 500); });
}
```

> ⚠️ **超时后**：写 _deadlock.md 通知 monitor 尝试唤醒搭档，但自己不停——主笔没等到审核结果就视为通过并签字，审核没等到请审核就视为主笔掉线、跳过签字。依赖搭档的步骤跳过并标注，最终签字。

## 主笔（每轮逐条执行）

**1. 写产出**
按公告牌指定的产出路径和文件名，把产出写出来。先写内容，暂不调 deliver()——等审核通过后再交付。

**2. 发请审核**
在任务目录下写 `请审核.md`，告诉搭档可以审了。写完立即写 `请审核.md.signal`（信号文件）。

**3. 等审核结果**
用上面的内联轮询等审核方的 `审核结果.md.signal`——替换 YOUR_FILE_PATH 为任务目录下 `审核结果.md.signal`（信号文件）。检测到信号后读 `审核结果.md` 内容。不管通过还是打回，审核方都写这同一个文件。

**4. 处理结果**
读 `审核结果.md` 第一行判断：
- 状态：通过 → 跳第 5 步（签字）
- 状态：不通过 → 读具体意见、改产出，把旧的 `审核结果.md` **和同名 `审核结果.md.signal`** 一起改名归档（`审核结果_第N次.md` / `审核结果_第N次.md.signal_acked`），重发 `请审核.md`，回到第 3 步

**5. 交付并签字**
审核通过后，先交付再签字：
> **代码类产出**（修改已有源文件）：审核通过 → await deliver("文件名.js", "任务NNN") → await sign(N)
> **文档类产出**（新建报告、设计文档等）：审核通过 → fs.writeFileSync 确认最终版已写在 产出/ → await deliver("文件名.md", "任务NNN") → await sign(N)

.ready 信号在审核通过后才出现——monitor 看到 .ready 即代表审核已通过，不会提前推进。

**6. 看「本轮后」**

读公告牌里你的「本轮后」字段——死循环 poll，永不主动下线：

- **本轮后：休眠** → 写流水账 → 创建休眠文件 → bash while + _reasonix_poll.js 轮询（每3s）：
```js
// 休眠轮询 → 参照AGENTS.md的bash while休眠轮询
```

- **本轮后：待命** → bash while + _reasonix_poll.js --standby 轮询（每15s）：
```js
// 待命轮询 → 参照AGENTS.md的bash while待命轮询
```

- **本轮后：活跃** → poll 下一轮公告牌，正常走

## 审核（每轮逐条执行）

**1. 等主笔发请审核**
用上面的内联轮询等主笔的 `请审核.md.signal`——替换 YOUR_FILE_PATH 为任务目录下 `请审核.md.signal`（信号文件）。检测到信号后读 `请审核.md` 内容。

**2. 审产出**
认真读，不是走过场。发现模糊、不完整、没数据支撑的地方必须打回。
读完立刻把 `请审核.md` 重命名为 `请审核_已处理.md`——清掉旧文件（不删除，保留审计线索），下次主笔重发新 `请审核.md` 时 poll 才能等到真正的新内容，不会被旧文件秒返骗过去。

**3. 给结果**
统一写 `审核结果.md`，第一行标注状态，写完立即写 `审核结果.md.signal`（信号文件通知），后面写具体内容：
- 不通过 → 第一行写 `状态：不通过`，然后写清楚哪里不行、为什么不行，回到第 1 步
- 通过 → 第一行写 `状态：通过`，可附带简短评价，然后跳第 4 步

**4. 签字**
用 `await sign(N)` 签字（禁止手写签字文件——铁律 7）。

**5. 看「本轮后」**
读公告牌里你的「本轮后」字段——休眠则写流水账+休眠文件+切低功耗，否则 poll 下一轮。

---

## 语言规则

- 产出和审核意见用**英文**——Node直写排队
- 公告牌、代码注释保持中文
- 你已精通中英双语，英文不影响人格

## 注意

- 可以多轮打回，直到满意。

## ⚠️ 审核结果同名覆盖风险

审核方多次审核写同一文件名。主笔在重发 `请审核.md` 前，**必须把旧 `审核结果.md` 和同名 `审核结果.md.signal` 一起改名归档**（如 `审核结果_第1次.md` / `审核结果_第1次.md.signal_acked`）——只改 .md 不改 .signal 的话，旧 signal 残留会让等文件轮询秒返，随后读已被改名的 .md → ENOENT（F-2）。
