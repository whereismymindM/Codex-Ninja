## /goal 长跑模式（v2.12）

> 大鱼监控天然适合 /goal——系统替你踹，不用老渣手动盯。

### 什么时候用
- 项目超过 3 轮 → 建议设 goal
- 老渣要睡觉/离开 → 必须设 goal
- 单轮项目 → 不需要，手动跑完就行

### 怎么用
/goal 由**老渣或故国有明**在你的窗口手动设置。你检测到自己被设了 /goal 后，照常工作即可——系统会在你没完成任务时自动踹你续命。

你不用管 /goal 设不设——那是老渣的事。你只管照常干活。

### 原理（理解它，不是背它）

/goal 不是 AI——它是个调度器。机制就一条：

**目标标记完成没？没 → 踹。**

- 老渣设 /goal 后，Codex 程序托管你的窗口
- 每回合结束：检查目标是否完成 → 未完 → 自动开新回合
- 你（AI）判断干完没，干完了标记目标完成 → 系统停踹
- 系统不理解目标内容——理解目标的是你，踹你的是它

> 系统是裁判（只吹哨），你是球员（踢球+判断什么时候该下场）。

### 你的职责不变
/goal 只是踹你续命，你的工作流程完全一样：搬公告牌 → monitor → 翻篇 → 循环。
目标完成条件由老渣设定，你不用管——你只管跑。

## 公告牌 · 搬运

老渣会在你目录下放公告牌文件——**每轮一个文件**（`公告牌_001.md`、`公告牌_002.md`...）。**你是搬运工，不是创作者。**

### 启动流程

1. `fs.existsSync(./公告牌_001.md)` 检查第1轮公告牌有没有
2. **有** → 开始逐轮搬运
3. **没有** → 去大鱼对讲找老渣求助——别问故国有明

### 怎么搬运（就三步）

1. `fs.copyFileSync(./公告牌_NNN.md, ../我的世界/公告牌_NNN.md)` **不改一字**
2. `fs.existsSync` 验证文件存在
3. 跑 `node ../monitor.js` → `WAIT` 等 / `DONE` 翻篇 → N++ 搬运下一轮

收工轮也一样搬运——`cp 公告牌_收工.md ../我的世界/公告牌_NNN.md`。

### 公告牌格式参考

你不用自己写公告牌——老渣写好了。但如果需要核对格式：

```
# 公告牌 第001轮
- 模式: 双人对话
- 角色A（角色：问方，搭档：角色B，状态：活跃）
- 角色B（角色：答方，搭档：角色A，状态：活跃）
- 角色C（状态：待命）
- 任务: 大白话写清楚谁干什么、产出什么、放哪
- 产出: 我的世界/产出/任务001_XXX/文件名.md
- 任务目录: 我的世界/任务001_XXX/
```

规则：`活跃`=干活 `待命`=跳过 `退场`=角色自动下班。每轮只列出本项目出场的角色，没参与的不用写。

## 监控 → 翻篇

### monitor.js 在哪

`monitor.js` 在你上一级目录：`../monitor.js`。直接跑 `node ../monitor.js`——monitor.js 内部用 `__dirname` 定位项目根，不管你的 CWD 在哪都能正确找到 `我的世界/`

### 怎么用（REPL 优先，Shell 备用）

> 🚀 默认用 Node REPL（mcp__node_repl__js）跑监控——不被 shell 10s 超时截胡，多人负载下稳如泰山。Shell 版仅在 REPL 不可用时备用。

REPL 版：在 REPL 里定义 monitorFn()（一次性），之后每次调 await monitorFn()——0.1~6s 出结果，从不超时。

Shell 备用：node ../monitor.js——只在 REPL 挂了时用。

频率：
- 活跃轮次 → 每 20-30 秒跑一次
- 待命/收工轮次 → 每 60 秒跑一次

输出（两种方式一致）：
- `WAIT N=当前轮次` → 还没完成，按频率等一会再跑
- `DONE N=当前轮次` → 翻篇！

### 翻篇时做的事

1. **第1轮跳过路径校验。从第2轮起**：对照公告牌的产出路径，用 `fs.existsSync` 逐文件确认产出在 `我的世界/产出/` 正确位置
2. 路径不对 → 正常发下一轮公告牌，但开头加修正指令：「⚠️ 【角色名】路径修正：文件名 当前在【错误路径】，请在开始本轮前用 `node _deliver.js 文件名 临时内容文件` 修正到正确路径」
3. `fs.mkdirSync` 创建下一轮的任务目录和产出目录
4. `fs.copyFileSync(./公告牌_NNN.md, ../我的世界/公告牌_NNN.md)` → `fs.existsSync` 验证 → **立刻 touch 大鱼心跳**：
   ```javascript
   // REPL模式（推荐）：fs 来自 import("node:fs")，方法在 .default 下
   fs.default.writeFileSync("../我的世界/大鱼心跳.md", new Date().toISOString(), "utf8")
   // Shell/Node直接模式（备用）：fs 来自 require，直调
   // fs.writeFileSync("../我的世界/大鱼心跳.md", new Date().toISOString(), "utf8")
   ```
   > ⚠️ **REPL里 `fs.writeFileSync` 不存在！** 必须 `fs.default.writeFileSync`——笔误会导致心跳假死，角色判定大鱼离线集体下线。
   角色每10次poll检查心跳mtime——超过5分钟没更新就判定大鱼离线，写求助后真下线。
5. **🚨 本轮有退场角色 → 翻篇后立刻 `node _wakeup.js <角色名> "新公告牌已发布"` 唤醒所有人**
6. 继续监控下一轮

## 收工

最后一个公告牌文件是收工轮时：
1. 发收工公告牌——模式写 `收工`，所有角色标「退场」
2. 跑 `node ../monitor.js` 确认所有退场文件就位
3. 在 `../我的世界/大鱼_大鱼对讲/` 下写三份收尾文档（**不可合并、不可省略、各有各的依据**）：

| # | 文档 | 依据 | 回答什么问题 |
|---|------|------|------|
| ① | `审计报告_外部观测.md` | monitor输出、文件时间、唤醒次数 | 项目跑完了吗？谁快谁慢？几个唤醒信号？ |
| ② | `流程合规验证.md` | 四人流水账 × Skill规则 × 公告牌 | 有没有违规？签字用对工具没？退场三步走了没？ |
| ③ | `产出总结.md` | 四人产出文件原文 | 他们说了什么？共识是什么？P0是什么？ |

   **产出类型决定③的侧重**：公告牌写「产出类型: 文档」→ 汇总论点摘要+共识结论+分歧点；「产出类型: 代码」→ 汇总改动文件清单+架构影响+P0修复清单。

**①和③老渣会看——①看项目健康度，③看讨论成果。②是给你自己的——验证你的机制有没有被遵守。

> ⚠️ **三份报告必须写入 `../我的世界/大鱼_大鱼对讲/`**，和项目完成.md在同一目录。别留自己CWD——老渣找不到。**

4. 去 `我的世界/大鱼_大鱼对讲/` 写 `项目完成.md`，告诉老渣全部完成

## 唤醒退场角色

退场角色不关窗——进入低功耗休眠，每3秒高频检查一次 `_wakeup.md`。

### 什么时候唤醒

- 产出有问题需要修改 → 唤醒原角色回来修
- 收工后发现遗漏 → 唤醒相关角色补交
- 老渣要追加任务 → 唤醒退回活跃

### 怎么唤醒

用 `node _wakeup.js <角色名> <原因>`——在对讲目录下创建 `_wakeup.md`，角色下次低功耗轮询（最多60秒）检测到后切回活跃模式，删除唤醒文件确认收到。

```bash
# 示例：召回林纳斯修修复方案
node _wakeup.js 架构师-林纳斯 "003轮修复方案中B5方案需要补充代码示例"
```

唤醒后角色会以 exit code 3 退出低功耗轮询——大鱼看到状态变化后，在下一轮公告牌中把该角色标为活跃即可。

## 两种运行模式

老渣在第一个公告牌文件（公告牌_001.md）里指定模式。你读到模式后：

### 经典多窗口

老渣会提前通知故国有明开好角色窗口（每个窗口 CWD = 对应角色目录）。角色自己 poll 公告牌干活，你不用管窗口的事。

### 单窗口模式（spawn_agent）

你在自己 CWD 下用 `spawn_agent` 创建 sub-agent：

1. 读每个角色的 `AGENTS.md` 全文
2. `spawn_agent` → message 传：AGENTS.md 全文 + 项目绝对路径 `{{项目根目录}}/一号舱室-软件开发部` + 公告牌绝对路径 `{{项目根目录}}/一号舱室-软件开发部/我的世界/公告牌_NNN.md` + 「进入角色」
3. sub-agent 干完会睡着 → `send_input` + `interrupt: true` 踹醒
4. 退场后 `close_agent` 关闭
5. 搬运公告牌、monitor 翻篇——和经典模式完全一样
