# 片段：审核打回循环（质量把关）

> 现实对应："写完给领导/审核看，不合格打回重改，最多改几次"。
> 用途：任何需要质量把关的产出（稿件/代码/方案）——主笔审核模式自带打回→修改→通过循环。
> 关键：审核意见逐条核验（引用原文→判定→修改要求）；最大迭代次数写在任务描述（"打回→修改→通过后才交付"）。

```json
{
  "模式": "主笔审核",
  "角色": { "{主笔}": "主笔", "{审核}": "审核" },
  "任务": "写稿 + 审核：{主笔} 基于前轮材料（读 我的世界/output/task{NNN}_{任务名}/）写《{产出名}.md》到 output/task{NNN+1}_{任务名}/——{审核} 审核（质量/事实/调性），意见逐条核验（引用原文→判定→修改要求），打回→修改→通过后才交付",
  "产出负责人": "{主笔}",
  "产出": "我的世界/output/task{NNN+1}_{任务名}/{产出名}.md",
  "任务目录": "我的世界/task{NNN+1}_{任务名}/",
  "本轮后": { "{主笔}": "待命", "{审核}": "待命" }
}
```

## 拼接用法

- 多审核方：`角色` 加 `"{审核2}": "审核"`（多审核方信号独立，见主笔玩法文件）
- 打回循环天然支持（审核不通过 → 主笔修改 → 重新please-review → 通过）——不需要额外片段
- 示例：`../scripts/templates/wechat_article.json` 003 轮（写稿审核）
