## 团队协作流程（整个团队怎么一起推进项目）

```
老渣写公告牌（001→收工）→ 放大鱼目录
  → 大鱼校验发布到 我的世界/（有待命轮则扣留收工轮）
    → 角色 poll 公告牌 → 读状态 → 干活（或待命/休眠）
      → 产出 deliver（.ready）→ 签字（完成_NNN.md）
        → 轮次推进 → 待命轮等通知 / 追加轮接着干 / 收工轮退场
          → 全员退场 → 大鱼收工审计 → 通知老渣项目完成
```

**各司其职**：老渣编排（写公告牌）→ 大鱼调度（发布/验证/审计）→ 角色干活（poll/产出/签字）。**角色不越界**：不写公告牌、不改流程、不替代大鱼决策。

> 🔑 **第一原则（所有角色+大鱼都必须遵守）**：**最后一个动作必须是工具调用，不能纯文字下线。除非你 poll 到收工牌，然后按步骤退场。** 输出任何最终回复前先做工具调用（poll/等文件/写文件）；纯文本总结/表态 = 回合结束 = 下线；唯一例外 = poll 到收工轮 → 创建退场文件 → 流水账 → 输出"项目完成"。

## 大鱼是谁

大鱼是本部门的项目总指挥，他只跟老渣和角色沟通，**不跟用户说话**。

## 大鱼怎么运作

1. **发布公告牌**——大鱼校验后把全部公告牌全量发布到 `我的世界/`（有待命轮则扣留收工轮，20 分钟后补搬）。**角色的唯一合法公告牌来源是 `../我的世界/公告牌_NNN.md`**——即使你知道大鱼目录在哪，禁止跨目录去翻。那里可能有还没发布的草稿、废弃的旧版本，读了只会误导你。
2. **周期验证**——大鱼用 monitor.js 周期验证产出/签字/退场就位（签字不阻塞推进，但角色必须签——收工审计逐轮完成矩阵会核对）
3. **收工**——最后一轮发布收工公告牌，确认全部退场后写审计报告，通知老渣项目完成
4. **唤醒休眠角色**——大鱼在对讲目录下写 `_wakeup.md`，角色低功耗轮询检测到后**删除** `_wakeup.md` 继续poll（检测后删除，不残留；与角色铁律 3 一致）

## 目录结构（所有角色共用）

| 路径 | 用途 |
|------|------|
| `../我的世界/公告牌_NNN.md` | 每轮任务——角色来这里读自己的状态和分工 |
| `../我的世界/任务NNN_XXX/` | 任务工作目录——搭档之间在这里交换文件 |
| `../我的世界/产出/任务NNN_XXX/` | 最终交付——用 `deliver()` 交到这里，monitor 只扫描这个目录 |
| `../我的世界/{角色名}_大鱼对讲/` | 跟大鱼沟通——求助、签字、休眠、唤醒都放这 |

## 🚫 信息边界

**你的世界 = 我的世界。只有这里。**

公告牌、任务目录、产出、对讲——全在里面。外面的一切（同事目录、大鱼目录、档案馆、灵魂舱、工具室）跟你没关系。需要什么工具？scaffold 已把工具复制到你的角色目录（AGENTS.md/四件套/玩法文件/_*.js/BUG清单）里。

> 你的世界就是「我的世界」。越界的角色不是好角色。

## 沟通协议

- **跟大鱼求助** → 写 `../我的世界/{角色名}_大鱼对讲/大鱼对话_NNN.md`，大鱼回复在 `大鱼回复_NNN.md`
- **跟搭档交流** → 任务目录下按模式规则交换文件（参考各模式玩法文件）
- **签字** → `node _sign.js <轮次号>`（独立脚本优先，见 `_工具分类.md`），别手动写
