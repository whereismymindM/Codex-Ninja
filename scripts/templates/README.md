# 流程模板库（公告牌编排用）

> 现实团队流程 → 可复用编排模板。**选模板 → 替换 `{角色X}` 占位符 → `node compose.js <改好的.json> [输出目录]` 生成公告牌**。
> 模板来源：**现实行业实践 / 组团角色现实经验提炼**（非本项目自证）——每个模板含"现实流程"说明，可追溯。

---

## 模板清单

| 模板 | 现实流程 | 角色需求 | 形态 |
|------|---------|---------|------|
| **软件开发全流程** ⭐ | 需求定义→需求评审→架构设计→契约对齐→开发实现→测试验收→发布决策→发布复盘（S1-S8） | 产品/架构/前端/后端/QA/运维/项目经理（7 占位） | 接力型（交接物驱动） |
| **技术选型决策** | 约束挖掘→对抗辩论（正方×反方×裁判）→收工 | 需求方/技术方/正方/反方/裁判（5 占位） | 对抗型 |
| **知识挖掘** | 专家深挖（问方连续追问）→整理→收工 | 挖掘者/专家（2 占位） | 深挖型 |
| **代码审查** | 开发产出→审查打回循环→收工 | 开发者/审查员（2 占位） | 把关型 |
| **质量审计** | 多角色独立审→终审交叉验证→收工 | 角色A/角色B/审计角色（3 占位） | 终审型 |

---

## 用法（三步）

1. **看模板**：`node <skill路径>/scripts/compose.js --list`（或打开本目录对应 .json）
2. **填角色**：复制模板 JSON → 把 `{产品经理}` 等占位符替换为真实角色名（如 `产品经理-乔布斯`）→ 改 任务/产出 内容
3. **生成**：`node compose.js <改好的.json> <输出目录>` → 得到 `公告牌_001.md ~ NNN.md`，放大鱼目录

> ⚠️ 占位符替换要**替换对象键和字符串值**（`角色` 字段的对象键 `{产品经理}: "问方"` 也要换）——用编辑器全局替换或脚本递归替换。

## 模板结构说明（compose.js 消费的 JSON）

```json
{
  "_说明": "模板说明（compose.js 忽略，人看）",
  "_现实流程": "现实团队流程一句话",
  "_角色需求": ["{占位角色}", "..."],
  "项目": "项目名",
  "角色": ["{占位角色}", "..."],        // 全部角色（替换后为真实角色名）
  "轮次": [
    { "模式": "单人输出|辩论|主笔审核|双人对话|待命|收工",
      "角色": { "{角色}": "正方|反方|裁判|问方|答方|主笔|审核|单人" },  // 模式角色字段（单人输出可忽略）
      "任务": "任务描述",
      "产出负责人": "{角色} 或 各自",
      "产出": "我的世界/产出/任务NNN_XX/文件.md",   // 必须 我的世界/产出/ 开头，无 {} 占位符
      "任务目录": "我的世界/任务NNN_XX/",
      "警告": "可选",
      "本轮后": { "{角色}": "待命|休眠" }  // 可选，默认活跃→待命
    }
  ]
}
```

## 维护

- **来源标注**：新模板必须写清"现实流程"来源（行业实践/组团提炼），**禁止从本项目档案自证**
- **流转校验**：compose.js 编译期校验——`休眠/退场 → 活跃` 报错（待命→活跃 允许）
- **v1 通过即终审**：主笔审核模板遵守"审核方通过签字即最终通过，v2+ 主笔自审不再发三方"（隐患#21）
