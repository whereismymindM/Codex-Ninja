# doc-consistency.js 审核指南

> **给谁**：审核 doc-consistency.js 的人（人或 AI）。
> **核心思路**：**不全文读源码**——这是元审核（用工具审工具），正确姿势是"**行为验证优先 + 4 处关键源码抽查**"。审的不是"代码写得漂不漂亮"，是"**它抓得准不准：不漏 / 不误报 / 不自腐化**"。
> **前置**：已先读同目录 `doc-consistency-使用说明.md`（了解工具是什么、怎么跑），本指南只讲"怎么审"。

---

## 五步审核流程（推荐顺序，共约 30-60 分钟）

### ① 自证：脚本没自腐化（1 分钟）

```bash
cd <codex-ninja 仓库根>
node scripts/doc-consistency.js --self-test   # 反向用例：故意制造漂移，断言必被抓
node scripts/doc-consistency.js --smoke       # wait_file 命令实测
```

**期望**：self-test 4/4 PASS、smoke 7/7 PASS。

**局限（必须知道）**：这只能证明"它能抓脚本自己想到的漂移"，**不能证明"它都抓了"**——self-test 的用例是脚本作者写的，抓不到作者没想到的盲区。所以必须继续 ②③④。

### ② 灵敏度：已知真漂移必须被抓（2 分钟）

```bash
node scripts/doc-consistency.js   # 正向跑
```

**期望**：报出当前仓库的已知真漂移（写这份指南时是 `assets/玩法模式/_主笔审核模式.md:46` "第三只眼"轨迹残留，D1 校验器）——**脚本对已知问题的灵敏度**。

### ③ 独立抽查"脚本说干净的地方"（最重要，15-20 分钟）

脚本报"0 漂移" ≠ 真的干净。**审核人独立**挑 2-3 处人工核，与脚本输出对照——这是抓"脚本漏网"的唯一方法（self-test 测不到脚本没想到的用例）：

- **挑一个数字**：`grep -n "调查轮" SKILL.md assets/老渣文档/公告牌完全指南.md` → 数出文档写的数 vs `ls assets/通用公告牌/*调查*.md | wc -l` 实际数，对比
- **挑一个引用**：文档里随便找一处 `assets/xxx.md` 或 `scripts/xxx.js` 引用 → `ls` 确认文件真实存在
- **挑一条铁律引用**：`grep -n "铁律" 团队须知/团队须知.md assets/玩法模式/*.md` → 对照 `assets/模板/Reasonix版_角色_AGENTS模板.md` 铁律表编号（签字=6/产出路径=8/信号改名与删除例外=2/抢锁=3）

人工结果 vs 脚本输出：一致 = 脚本在该处可信；不一致 = **脚本漏网**，记入审核结论。

### ④ 反向核验"脚本报的漂移"是真漂移（5 分钟）

脚本报的每一项，人工复核确有其事——防止脚本误报制造噪音（误报多了会导致"狼来了"效应，反而让人不信任脚本）。

### ⑤ 关键源码抽查（只读 4 处，不全文读，15-20 分钟）

| 校验器 | 源码位置 | 为什么值得读 | 重点看 |
|---|---|---|---|
| **B1 铁律映射** | `kwMap` 数组 | 最复杂：语义关键词→编号手动映射，关键词匹配可能误判/漏判 | ①编号从模板主表解析（非硬编码）②关键词会不会一条铁律匹配多个/零个（导致跳过或错报）③关键词措辞与铁律表实际文本是否对得上 |
| **D3 代码块卫生** | `checkBash` / `checkJs` 函数 | bash -n/node --check 全量实测，占位符替换与包装逻辑 | ①占位符替换是否覆盖所有写法（`{{ROLE_NAME}}`/`<lastN>`/`<任务目录>`/`YOUR_FILE_PATH`）②JS 包 async IIFE 是否正确（不改变语法语义）③临时文件是否清理 |
| **A4 monitor 输出** | `prefixes` 提取 + 白名单 | "独立语义 vs 家族变体/日志前缀"的归类 | ①前缀正则是否覆盖 console.log/logMonitor 两种形式 ②OUTPUT-FORMAT/OUTPUT-WARN/WARN/MONLOG_WARN 归类是否合理（会不会把真实独立输出误归为日志） |
| **C5 裸行号** | `re1`/`re2` + 过滤条件 | 正则边界 | 会不会把时间（HH:MM）/版本号（v1.2）/表格编号/URL 误判为裸行号 |

> 其他 16 个校验器（A1/A2/A3/C1/C2/C3/C4/D1/D2/E1/E2/E3 等）都是直白枚举/正则——**跑行为验证（①②③④）就够，不必读源码**。

## 审核判据（结论模板）

| 判据 | 通过标准 |
|---|---|
| **灵敏度** | 已知真漂移必被抓（②） |
| **不漏网** | 人工抽查 2-3 处与脚本输出一致（③）——**这是最主要的失败点**：任何一处人工发现脚本没报 = 漏网 |
| **不误报** | 脚本报的每项经人工复核确有其事（④） |
| **不自腐化** | self-test 4/4 + smoke 7/7（①） |
| **关键逻辑** | B1/D3/A4/C5 四处抽查无缺陷（⑤） |

**结论三态**：
- ✅ 通过：五步全过
- ⚠️ 有条件通过：有 minor 问题（如某关键词映射可改进）但不影响当前仓库准确性
- ❌ 不通过：③发现漏网（脚本没报该报的）或 ⑤发现逻辑缺陷——列出问题，修后重审
