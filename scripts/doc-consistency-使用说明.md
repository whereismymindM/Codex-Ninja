# doc-consistency.js 使用说明

> **这是什么**：codex-ninja 的文档一致性校验工具——从代码/文件系统枚举"事实"（模式枚举、模板数、调查轮数、monitor 输出、退出码、铁律编号、文件引用、参数语义），再断言文档里写的数字/名称/描述与事实一致。跑一次就知道文档漂没漂。
>
> **为什么存在**：历轮审核反复抓出同一类错误——**计数漂移**（同一个数字在不同文档不同步，如模板 5 vs 实际 7、调查轮 4 vs 实际 6）。人工 grep 只能查"想到要查的数字"，查不到"没想到的数字"（开放集合问题）；脚本从代码枚举，新增功能事实自动变化、文档不跟着变就报警。
>
> **设计依据**：`阅览室/doc-consistency校验脚本-计划书.md`（双审通过）。

---

## 怎么跑

```bash
# 在 codex-ninja 仓库根目录下
node scripts/doc-consistency.js              # 跑一次查漂移（默认全量 20 个校验器）
node scripts/doc-consistency.js --verbose    # 每个校验器都显示（含通过项）
node scripts/doc-consistency.js --self-test  # 反向用例：故意制造漂移断言必被抓（防脚本自身腐化）
node scripts/doc-consistency.js --smoke      # wait_file 命令实测：抽取玩法文件命令验证路径解析
```

**退出码**：`0`=全部一致　`1`=有漂移（stdout 列出每处位置+原因）　`2`=脚本自身错误（防"脚本坏了当全过"）

## 什么时候跑

| 场景 | 谁跑 | 为什么 |
|---|---|---|
| **改完模板/文档后** | 老渣（迭代 Skill 待办 #6） | 改 A 处常漏 B 处，跑一次立刻暴露 |
| **审核前** | 审核者 | 审核标准第 5/6 步已改为"跑脚本，只复核输出" |
| **提交前** | 老渣/开发者 | 防把漂移带进仓库 |
| **接入新功能后** | 开发者 | 新增枚举（模式/模板/调查轮/输出）后文档数字自动漂移，脚本自动报警 |

## 校验器清单（20 个，五类）

| 类 | 校验器 | 查什么 |
|---|---|---|
| **A 枚举**（5） | A1 模式枚举 / A2 流程模板数 / A3 调查轮数 / A4 monitor 输出 / A5 轮次类型 | 文档数字 == 代码/文件系统实际枚举 |
| **B 数字**（4） | B1 铁律编号引用 / B2 阈值时间 / B3 退出码 / B4 参数语义 | 文档引用 == 权威表/实现常量 |
| **C 引用**（5） | C1 仓库内文件引用 / C2 仓库外标注 / C3 scaffold 分发 / C4 占位符残留 / C5 裸行号引用 | 文档引用的文件/路径真实存在 |
| **D 卫生**（3） | D1 开发轨迹关键词 / D2 全角冒号字段 / D3 排版判据 | 轨迹残留 + 排版 7 项判据（超长行/围栏/表格/标题/缩进/代码块卫生/空壳代码块，含 bash -n 与 node --check 实测） |
| **E 口径**（3） | E1 _deadlock 口径 / E2 信号后缀声明 / E3 wait_file 命令路径前缀 | 同一规则跨文档同口径 |

## 白名单与豁免

脚本对以下文件**不检查**（与审核标准「保留例外」一致）：
- `CHANGELOG.md`（版本历史本体）、`assets/_隐患清单.md`（修复记录本体）
- `assets/老渣文档/goal模式认知.md`、`assets/模板/_大鱼实测教训.md`（实测知识库类）
- `e2e/` 目录（维护者信息）

> 白名单条目都带理由注释，审核时可抽查——防"误报→全进白名单→全失效"。

## 维护点（改脚本时注意）

- **B1 铁律语义映射**（脚本内 `kwMap`）：编号从模板主表自动解析（铁律重编号脚本自动跟），但"语义关键词→编号"的映射是**手动维护点**——模板里某条铁律的措辞大变时需检查映射是否仍命中
- **A4 monitor 输出**：前缀自动提取，但"独立语义类别 vs 日志/家族变体"的归类是人工清单
- **新增校验器**：需评审（像审核标准追加易错点一样走流程），避免范围蔓延

## 验证方法（改完脚本必做）

```bash
node --check scripts/doc-consistency.js        # 语法
node scripts/doc-consistency.js                # 正向：当前仓库应只有已知漂移（如实报告）
node scripts/doc-consistency.js --self-test    # 反向：4 个代表性用例必被抓
node scripts/doc-consistency.js --smoke        # wait_file 命令实测
```

## 常见问题

| 现象 | 处理 |
|---|---|
| 跑出漂移但确认文档是对的 | 可能脚本判据过严 → 检查是否该进白名单（带理由）或修脚本判据 |
| 脚本报"脚本错误"（退出码 2） | 校验器内部异常，看 stdout 具体信息修复 |
| `--smoke` 报 FAIL | 玩法文件 wait_file 命令目标缺路径前缀（裸名会被锚定到角色目录等满超时）——补 `<任务目录>/` 或 `../` 前缀 |
| `--self-test` 报 FAIL | 脚本自身腐化（反向用例抓不到漂移）→ 修脚本后重跑 |
