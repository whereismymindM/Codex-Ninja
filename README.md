> 当前版本：**方案A + 方案E（turn 内循环）**（方案A 已交付、方案E 已实测通过）

## 这是什么

Codex Ninja 是一个 AI Agent 团队协作框架。通过文件系统通信、公告牌调度、休眠协议自治运行——你交代完任务就可以离开，项目自动推进到完成。

## 三方协作

| 角色 | 窗口 | 职责 |
|------|:--:|------|
| **老渣**（你） | 用户窗口 | 写公告牌、盯场救火、陪故国有明聊天 |
| **大鱼** | 独立窗口 | 搬运公告牌 → 监控翻篇 → 唤醒角色 → 收工审计 |
| **各角色** | N 个窗口 | 轮询公告牌 → 干活 → 签字交付 → 休眠/待命 |

## 四种玩法

| 模式 | 角色 | 适用场景 |
|------|------|----------|
| 单人输出 | 1人 | 写代码、写文档、独立任务 |
| 双人对话 | 问方+答方 | 需求访谈、方案讨论 |
| 主笔审核 | 主笔+审核 | 代码审查、文档校对 |
| 辩论 | 正方+反方+裁判(可选) | 技术选型、架构决策 |

## 容错能力

> 角色可能在任意时刻掉线。系统有三层容错确保项目不卡死：

| 层级 | 机制 | 怎么工作的 |
|:--:|------|------|
| 1 | **心跳自愈** | 角色每轮写心跳时间戳，monitor 2分钟无心跳自动唤醒 |
| 2 | **死锁并行** | 等搭档文件超时写死锁信号通知 monitor + 自己继续推进，两条恢复路径同时跑 |
| 3 | **产出兜底** | monitor 翻篇只看产出就位不看签字，签字失败不阻塞项目推进 |

## 核心机制

- **公告牌驱动**：任务写在 `公告牌_NNN.md`，大鱼逐轮搬运，角色轮询读取——不需要长连接
- **turn 内循环**（可选全自动）：项目 `reasonix.toml` 配 `[tools] bash_timeout_seconds = 0` 后，角色第一回合内循环 等牌→干活→等牌→收工，全程无人值守（详见角色模板「工作模式」节）
- **E 模式守护**：大鱼转型守护者——发布前校验公告牌（编号/收工格式/角色枚举/前置依赖/状态流转 5 项）、周期 monitor 验证（不干预推进）、求助具体回复、收工审计（产出总结含逐轮完成矩阵）
- **角色状态机**：待命 → 活跃 → 休眠 → 退场，公告牌指定每轮谁干活、干完去哪
- **bash while 轮询**：角色通过 bash while + node _reasonix_poll.js 持续轮询，不依赖 REPL
- **双向心跳**：角色写心跳保活 + monitor 反向检测，任一方离线都能被发现
- **原子操作**：`.tmp → rename` 写所有文件，搭档不会读到半截

## 快速开始

1. 安装 Skill 到 Reasonix skills 目录
2. 按 SKILL.md 5步流程：定角色、scaffold、部署团队须知、写公告牌、开窗口
3. 启动方式二选一：
   - **E 模式**（推荐，全自动）：角色 reasonix.toml 已含 `bash_timeout=0` → 按 启动指南.md「E 模式启动命令」全量发布 + `reasonix run` 启动，单回合跑完全部轮次，零人工干预
   - **A 模式**（手动窗口）：`reasonix code` + 逐轮搬运，按 启动指南.md「启动流程」
4. 读公告牌完全指南.md，在火影-大鱼下写公告牌（每轮一个独立文件）
5. 参考阅览室 `角色窗口启动方案全集.md`（仓库外文档）批量启动角色
6. 离开，让他们自己干活 ☕

## 设计哲学

> 文件系统是总线，公告牌是时钟，大鱼是调度器，休眠是安全网，容错是底线。

- 📋 公告牌驱动：不需要长连接，不需要消息队列
- 🐟 大鱼不干活：调度器和工人严格分离
- 🚪 休眠不是下班：窗口永远不关，while(true) 循环到底
- 💉 灵魂注入：不是通用 Agent，是专家
- 📁 文件系统通信：可审计、可回溯、可恢复
- 🛡️ 三层容错：单点故障不卡死整轮
